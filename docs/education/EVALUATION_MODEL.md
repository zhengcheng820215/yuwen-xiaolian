# 能力评估模型（Evaluation Model）

## 文档定位

本文档是 AI 语文能力诊断与成长系统的能力评估模型。

本模型负责定义：

- AI 如何评估学生能力
- AI 如何验证能力是否真正成长
- AI 如何更新能力画像
- AI 如何形成长期成长记录

本文档不是考试评分规则，不是成绩统计，不是排行榜，不是 Prompt，不是算法实现，也不是页面设计。

本文档是一份可被 AI 调用、可被程序实现、可长期扩展的能力评估模型。

未来以下模块必须引用本模型：

- Ability
- Diagnosis
- Training
- Question
- Student Profile
- Prompt Guide

本文档的核心目标是建立整个系统统一的 Evaluation Language（评估语言）。未来成长报告、能力画像、AI 点评和能力升级，都必须引用本模型。

本文档用于回答以下问题：

1. 什么是能力评估？
2. 为什么正确率不能代表能力？
3. AI 如何证明能力成长？
4. 能力什么时候升级？
5. 能力什么时候保持？
6. 能力什么时候退步？
7. 能力画像如何更新？

评估对象永远是能力，不是题目。

整个评估体系必须体现：

> 能力成长比考试成绩更重要。

## 一、评估模型定义（Evaluation Definition）

能力评估不是考试评分。

能力评估是持续验证学生能力状态变化的过程。

评估目标不是给学生打分，而是判断：

```text
能力是否真正成长？
```

在本系统中，评估关注的是学生在能力上的成熟度变化，包括是否更独立、是否更稳定、是否能迁移、是否能完成复杂任务、是否减少提示依赖。

能力评估应回答以下问题：

- 学生当前具备什么能力？
- 哪些能力正在成长？
- 哪些能力仍不稳定？
- 哪些能力已经能够迁移？
- 哪些能力需要重新训练？
- 哪些证据支持这些判断？

评估不是对一次结果的静态判断，而是对长期能力变化的动态确认。

## 二、评估原则（Evaluation Principles）

### 1. 持续评估

能力评估必须基于长期行为。

系统不能依据一次考试、一次作答或一次训练结果判断能力状态。

### 2. 证据优先

所有评估结论必须有能力证据支撑。

没有证据，不能输出能力等级、能力状态、成长趋势或升级判断。

### 3. 成长优先

评估的核心不是比较学生之间的高低，而是观察同一学生在能力上的变化。

系统关注的是学生是否比之前更稳定、更独立、更可迁移。

### 4. 能力优先

评估对象是能力，不是题目、知识点、考试分数或完成数量。

题目只是评估能力的观察载体。

### 5. 解释优先

评估结论必须可解释。

系统需要说明能力判断来自哪些表现、哪些证据、哪些变化，而不是只输出等级或结论。

### 6. 迁移优先

迁移表现是能力是否真正成长的重要依据。

学生只在原题或高度相似任务中表现良好，不足以证明能力成熟。

### 7. 长期观察

能力状态可能波动。

系统应通过连续作答、间隔复测和复杂任务表现观察能力是否真正保持。

### 8. 动态更新

能力画像不是固定档案。

每一次诊断、训练、复测和迁移任务都可能产生新证据，并推动能力状态更新。

## 三、能力成长判断（Growth Validation）

能力成长必须满足多个条件，不能只看正确率。

能力真正成长通常表现为：

| 成长标准 | 说明 |
| --- | --- |
| 能够独立完成 | 学生可以在少量提示或无提示情况下完成能力任务 |
| 能够迁移 | 学生可以在新文本、新题型或新任务中使用该能力 |
| 能够长期保持 | 学生在多次任务或间隔复测中保持稳定表现 |
| 能够完成复杂任务 | 学生可以在更长文本、更多信息或多步骤任务中完成能力活动 |
| 能够减少提示依赖 | 学生从依赖 AI 提示逐步转向独立思考 |
| 能够完成修正 | 学生能根据反馈识别问题并修正思考过程 |

能力成长判断应遵循以下逻辑：

```text
训练表现改善
↓
形成新能力证据
↓
通过复测验证
↓
完成迁移验证
↓
能力状态更新
```

如果学生只是记住原题答案，或只在强提示下完成任务，不能判断能力已经成长。

能力成长需要证明学生在新的情境中能够更稳定、更独立地完成相同能力活动。

## 四、评估维度（Evaluation Dimensions）

能力评估不能只评价结果，应从多个维度观察能力状态。

统一评估维度如下：

| 评估维度 | 说明 | 关注问题 |
| --- | --- | --- |
| 正确性 | 学生结果是否符合任务要求 | 答案是否准确、是否抓住关键 |
| 独立性 | 学生完成任务时对提示的依赖程度 | 是否需要大量提示或示范 |
| 稳定性 | 学生在多次同类任务中的表现是否稳定 | 是否反复波动或偶然正确 |
| 迁移性 | 学生能否在新文本、新题型或新任务中使用该能力 | 是否只会原题或固定形式 |
| 持续性 | 学生在间隔复测或长期任务中是否保持能力 | 能力是否能够长期保持 |
| 复杂任务完成度 | 学生能否在更复杂任务中完成能力活动 | 是否能处理多信息、多步骤任务 |
| 修正能力 | 学生是否能根据反馈修正错误 | 是否理解错因并补足思维缺口 |
| 学习效率 | 学生形成稳定能力所需训练和提示程度 | 是否能更快形成有效方法 |

每个维度代表能力成熟度的不同方面。

系统应避免只用正确率替代全部评估。

## 五、能力状态（Ability Status）

能力不只有等级，还有状态。

能力等级描述成熟度，能力状态描述当前发展阶段和稳定程度。

本系统采用以下能力状态模型：

```text
未建立
↓
成长中
↓
基本稳定
↓
稳定掌握
↓
可迁移
↓
持续保持
```

| 状态 | 说明 |
| --- | --- |
| 未建立 | 学生尚不能完成该能力任务，或只能在大量提示下完成 |
| 成长中 | 学生开始理解方法，但表现不稳定，需要持续训练 |
| 基本稳定 | 学生能在常规任务中较稳定完成，但迁移证据不足 |
| 稳定掌握 | 学生能独立完成多数同类任务，表现相对稳定 |
| 可迁移 | 学生能在新文本、新题型或新任务中应用该能力 |
| 持续保持 | 学生能在长期复测、复杂任务或间隔任务中保持稳定表现 |

能力状态可以与能力等级共同使用。

例如：

```text
概括能力：Lv3，基本稳定，待迁移验证
推理能力：Lv2，成长中，仍依赖提示
信息提取：Lv4，可迁移，表现稳定
```

## 六、能力升级机制（Ability Promotion）

能力升级必须基于能力证据，不是题目数量。

升级流程为：

```text
持续稳定
↓
形成能力证据
↓
迁移成功
↓
完成复测
↓
升级能力等级
```

能力升级应满足以下条件：

| 升级条件 | 说明 |
| --- | --- |
| 多次稳定表现 | 学生在多个任务中表现稳定 |
| 独立完成 | 学生减少或不再依赖提示 |
| 迁移成功 | 学生能在新文本、新题型或新任务中完成能力活动 |
| 复测通过 | 学生在复测中保持目标能力表现 |
| 证据一致 | 新证据与既有证据共同支持升级判断 |

升级不是对学生的奖励，而是能力成熟度变化的记录。

系统不应因为学生完成了固定数量的题目就自动升级，也不应仅凭一次高正确率判断能力升级。

## 七、能力退化机制（Ability Regression）

能力不是永久存在。

当能力表现长期不稳定或出现明显下降时，系统应识别能力退化或状态回落。

能力退化可能来自：

- 长期未使用
- 连续迁移失败
- 持续依赖提示
- 复杂任务失败
- 间隔复测表现下降
- 同类错因反复出现

能力状态可能从：

```text
可迁移 -> 基本稳定
稳定掌握 -> 成长中
基本稳定 -> 待训练
```

能力退化不是惩罚，而是重新训练的依据。

系统应将退化视为新的诊断信号，用于判断是否需要重新训练前置能力、降低任务难度或增加复测。

退化判断同样必须有证据支持，不能基于单次失败直接下结论。

## 八、能力证据体系（Evidence System）

能力证据是评估的基础。

AI 形成评估依据时，应综合多种证据来源：

- 连续作答
- 复测结果
- 迁移表现
- 修正能力
- 提示依赖
- 长期稳定性
- 复杂任务表现
- 错因变化
- 训练过程表现

能力证据可分为以下类型：

| 证据类型 | 说明 |
| --- | --- |
| 成长证据 | 支持能力正在提升或已经提升的表现 |
| 稳定证据 | 支持能力在多次任务中保持稳定的表现 |
| 迁移证据 | 支持能力能够应用到新情境的表现 |
| 衰退证据 | 支持能力状态下降或不稳定的表现 |
| 待验证证据 | 单次或少量表现形成的线索，需要后续确认 |

说明：

本节描述长期评估模型中的证据语义。当前工程最小 Ability Evidence 枚举暂以 `ABILITY_EVIDENCE_CONTRACT.md` 为准：

```text
positive / weakness / growth / insufficient
```

长期模型中的稳定证据、迁移证据、衰退证据暂不作为独立枚举落地，可先通过 `observation`、`source`、`rootCause` 和后续 Profile / Evaluation 聚合逻辑表达。

能力证据应满足：

- 可追溯：能够回到具体作答、训练、修正或复测表现
- 可解释：能够说明为什么支撑某项能力判断
- 可累计：能够与历史证据共同形成趋势判断
- 可比较：能够观察同一学生在不同时期的能力变化
- 可验证：能够通过后续任务继续确认

所有评估必须可解释。

没有能力证据，不能输出能力成长、能力升级、能力保持或能力退化结论。

## 九、能力画像更新（Profile Evolution）

每次评估以后，能力画像都应根据新证据进行更新。

能力画像应该持续成长，不是静态记录。

画像更新内容包括：

| 更新项 | 说明 |
| --- | --- |
| 能力等级 | 根据能力成熟度更新 Lv1-Lv5 |
| 能力状态 | 更新未建立、成长中、基本稳定、稳定掌握、可迁移、持续保持等状态 |
| 新增证据 | 记录本次评估形成的新证据 |
| 成长趋势 | 判断能力近期是提升、稳定、波动还是下降 |
| 训练历史 | 记录该能力经历过的训练阶段和训练结果 |
| 待提升能力 | 标记仍需训练或复测的能力 |
| 下一阶段目标 | 明确下一步应进入训练、复测、迁移验证或持续保持 |

能力画像更新应遵循以下原则：

- 新证据必须与既有证据共同判断
- 迁移表现优先级高于原题表现
- 独立完成优先级高于提示后完成
- 长期稳定优先级高于短期正确
- 复测表现优先级高于即时训练表现
- 能力画像应保留成长过程，而不是只保留最新结论

能力画像的核心价值是记录学生能力如何变化，而不是记录学生得了多少分。

## 十、成长报告（Growth Report）

成长报告不是成绩单。

成长报告是能力成长记录，用于说明学生在某一阶段的能力变化、证据基础和后续方向。

标准成长报告应包括：

| 模块 | 说明 |
| --- | --- |
| 本阶段成长能力 | 本阶段发生明显变化或达到新状态的能力 |
| 新增能力证据 | 支撑成长判断的关键证据 |
| 能力变化 | 能力等级、能力状态或成长趋势的变化 |
| 仍需提升能力 | 当前仍不稳定、待复测或待训练的能力 |
| 建议训练方向 | 下一阶段应重点训练或验证的能力方向 |
| 长期成长趋势 | 能力在一段时间内的持续变化情况 |

成长报告应避免：

- 只展示分数
- 只展示正确率
- 用排名比较学生
- 用一次测试定义能力
- 只给结论不提供证据

成长报告应体现：

- 学生在哪些能力上成长了
- 成长证据是什么
- 哪些能力仍需要支持
- 下一步如何继续成长

## 十一、本模型与其他模型关系

Evaluation 位于能力成长闭环的验证环节。

系统关系可以表示为：

```text
Ability
↓
Diagnosis
↓
Training
↓
Evaluation
↓
Question
↓
Student Profile
```

EVALUATION_MODEL 的职责是验证：

- Diagnosis 是否正确
- Training 是否有效
- 能力是否真正成长
- 能力画像是否需要更新
- 下一阶段目标是否需要调整

ABILITY_MODEL 定义评估对象和能力等级基础。

DIAGNOSIS_MODEL 生成能力短板和能力证据。

TRAINING_MODEL 组织能力改善过程。

QUESTION_MODEL 提供用于评估、复测和迁移验证的任务载体。

Student Profile 记录评估结果、能力状态、成长趋势和长期证据。

Prompt Guide 和 AI Coach 应使用本模型中的评估语言，避免将评估简化为分数、排名或题目正确率。

本模型不涉及：

- 页面设计
- Prompt 编写
- 算法实现
- 数据库设计
- 考试评分规则
- 成绩排名机制
- 具体题目内容

评估对象永远是能力。成长必须基于能力证据。

未来成长报告、能力画像、AI 点评和能力升级，都必须引用本模型。
