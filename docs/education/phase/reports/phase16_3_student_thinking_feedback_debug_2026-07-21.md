# Phase 16.3 学生思路点评优化验收记录

日期：2026-07-21
状态：PASS

## 目标

解决回答已形成正式 Positive / Growth Evidence，但学生端只显示“正式记录整理的受限反馈”或只复述学生原句、不能说明关键点覆盖的问题。

本次不调整 Diagnosis、Evidence、Profile、GrowthMemory 或普通 Live 的 `restricted` 准入边界，只优化正式学生反馈的事实适配与展示。

## 实现结果

- Positive / Growth Evidence 只用于确认本次表现方向，不再把 `detail`、`observation` 等内部说明改写成学生点评；
- “思路点评”中的完成项必须绑定学生原答案的精确片段，或由任务要求覆盖检查定位到学生答案中的完整语义；
- “答案包含核心结论”“答案隐含依据”“对应材料中”“结论与依据的关系成立”等内部分析句不得进入学生反馈；
- 禁止通过“你的回答”与 Evidence 文本机械拼接生成“你的回答答案”“还答案”等病句；
- 没有正向 Evidence、答案无效或信息不足时，不因存在学生原文而生成正向点评；
- 学生端标题由“做得好的地方”收敛为“思路点评”；
- `StudentLearningFeedback` 增加可选 `thinkingReview.requirementCoverage`，按结论、文本依据、推理关系等正式任务环节记录结构化覆盖；
- 每个环节使用 `covered / partially_covered / missing / insufficient_to_judge` 四态，避免把信息不足误判为错误；
- 完整覆盖检查保留在反馈内部，学生页面只消费 `coveredPoints`、`primaryGap` 和兼容字段 `missingPoints`；
- 页面将其展示为“回答到位”和“还需调整 / 还需补充”，最多呈现一至两个已完成点和一个主要缺口；
- `primaryGapRequirementId` 成为点评与建议的共同权威来源，覆盖检查先行，建议不得从另一条 Diagnosis 文案独立生成；
- “思路点评”只描述本次完成情况，不包含方法步骤；“思路建议”只描述下一步动作，不重复评价本次答案；
- 完整回答只显示点评，不强造建议；全部关键要求均为 `insufficient_to_judge` 时只给下一步动作，不强造完成度点评；
- 关键点只从正式任务要求、评价依据、材料事实、学生答案和正式 Diagnosis / Evidence 派生；
- 合理异表述可由正式 Diagnosis 与 Positive / Growth Evidence 接纳，不要求命中参考答案关键词；
- 学生依据必须通过有意义事实片段校验，“自己、当时”等孤立词不会进入“回答到位”；
- 文本依据匹配已从关键词/子串命中升级为完整学生句段、动作谓词与上下文对象关系校验；
- “自己、当时、这样、那里”等孤立代词、时间词和指示词即使与材料重合也不能形成有效依据；
- 学生对原文动作作合理改写时可以通过；只写结论时不能伪装为已有依据；
- 引用事实但未解释关系时，文本依据记录为已覆盖或部分覆盖，推理关系继续记录为缺失；
- 题干已经公开且学生实际使用的完整动作仍可正常形成具体点评；
- 材料细节即使在内部用于核验，也不会因学生尚未写出而直接作为答案线索展示；
- Rubric、Diagnosis 或 Evidence 单独声称“关系成立”，不能代替学生答案中的实际表达；学生端只有在答案中同时定位到具体依据和关系说明时，才显示推理关系已完成；
- 当正式结果判定完整、但学生端无法独立定位依据时，该项保留为 `insufficient_to_judge`，不向学生伪造完成项，也不反向制造未经正式结论支持的不足；
- 无法确认覆盖或遗漏时不强造点评，且结构化点评不会被 LLM 增强文案改写；
- 已有结构化点评时，“需要留意”不重复展示同一问题，只保留“思路建议”作为修改动作；
- “正式记录”“受限反馈”“人工标注”等准入信息不再进入学生摘要；
- 旧持久化反馈按当前规则只读兼容展示，不重跑 Provider，也不改写正式记录。

## 页面实测

正式入口：`#/learning`

入口恢复结果：

```text
上次学习已经完成
下面是根据本次回答整理的反馈。
```

反馈页目标结果：

```text
思路点评

回答到位
1. 你写出了“不舍”这一人物心理。

还需补充
1. 题目还要求结合人物的具体动作或语句说明理由，你的答案里还缺少这一部分。
```

完整反馈对象仍保留“文本依据”和“依据与心理关系”两个未完成环节，但学生端当前只显示优先级最高的一个缺口，避免一次性暴露完整评分结构。“思路建议”另行说明怎样补充，不重复点评结论。

学生页面未出现：

- 正式记录；
- 受限反馈；
- 能力码；
- Evidence / Diagnosis 等内部字段。

## 状态映射修正

反馈形成后，若下一学习策略或下一资源匹配进入 `review_required`，本轮 Diagnosis、Evidence、反馈和正式保存并未失效。学生端必须显示：

```text
下一任务待检查
本轮学习已经完成
本轮结果已经保存。下一任务暂时无法确定，需要先检查任务安排。
```

只有正式结果尚未保存、Diagnosis 无法安全采用时，才显示“本次结果暂不采用”。统一入口顶部标签、主标题和学习进度必须使用同一阶段语义，不得在同一页面同时出现“本轮已经完成”和“结果未采用”。

## 边界结论

“思路点评”不是表扬模块。它说明学生本次答案完成了哪些正式任务环节、哪个关键环节还需要调整或补充。覆盖结论必须可由正式任务、材料、学生答案和已确认 Runtime 结果追溯；无法核验时保持 `insufficient_to_judge`。内部保留完整覆盖信息，学生端进行克制投影，不通过模板补造优点、不机械匹配参考答案，也不直接给出学生尚未写出的答案线索。点评与建议必须由同一个主要缺口驱动：点评负责说明现状，建议负责说明动作。

本次针对页面实测中出现的内部复合 Evidence 泄露与覆盖冲突，新增：

- Case 57：内部复合 Evidence 不进入学生点评，不产生机械拼接病句；
- Case 58：学生答案中没有可核验依据时，正式结果不能让文本依据与推理关系在学生端显示为已完成。
