## 五、问题修复与复验

### P1：单题完整质量检查无可见结果（已修复）

稳定复现步骤：

1. 在已确认训练计划中选择状态为“待检查”的训练任务；
2. 点击“检查题目”；
3. 按钮进入 `正在检查`；
4. 等待约 20 秒；
5. 按钮恢复为“检查题目”，任务仍为待检查；
6. 页面没有成功 Toast、失败说明或重试原因。

修复结果：

- Command 已拆分为保存、结构检查和完整 Assessment 三个可观察阶段；
- 任务卡摘要区即时显示“正在检查题目结构”或“正在生成完整质量检查记录”；
- 远端完整质量评估未形成时，页面明确显示“题目结构检查已完成，但完整质量检查记录未形成。请重试检查。”；
- 已完成阶段被保留，重试不要求重复保存；
- 浏览器复验无控制台错误，静默失败闭环已消除。

当前边界：本次真实环境中的远端完整质量评估仍未返回成功结果，因此只确认了失败恢复闭环；成功写入 Assessment 的确定性行为由自动化测试覆盖。

### P2：素材标题存在重复书名号风险（已修复）

当前素材标题数据包含 `谭嗣同《潼关》`，部分展示区域再次包裹书名号后可能显示为 `《谭嗣同《潼关》》`。

已统一为幂等标题格式化规则：纯标题补书名号，已有外层或内嵌规范书名号的标题保持原样。浏览器中的 `谭嗣同《潼关》` 未出现重复包裹，专项回归 `7 / 7 PASS`。

### P2：学习入口空结果语义（已补强）

学习入口现在保留 `no_formal_resource`、`no_eligible_match` 与 `already_used` 的结构化状态，页面可分别解释“没有正式任务”“没有符合本轮条件的新任务”和“本轮任务已使用完”。这些状态属于成功读取结果，不再与读取失败混用。

当前真实页面显示“本次学习已经结束”，无读取错误且控制台无异常。另有 `23 / 23 PASS` 自动化覆盖正式资源为空、筛选无匹配和已使用完三类边界。

### P2：长操作耗时需要继续监控

训练计划确认和正式发布约需 7 秒。当前 Loading 状态清楚，交互可理解，但建议记录耗时并在超过阈值时显示阶段提示，避免用户误判为卡死。

## 七、2026-08-04 P0 单入口真实发布复验

本轮使用新建素材《P0验收短文·山路灯火·20260804》执行隔离验收，共生成并采用 3 个训练任务。首次复验仅对任务 1 修改题目并完成发布，任务 2、任务 3 保持未处理状态；后续人工 Demo 补充验收见第十节。

复验中发现“发布任务”在确认训练计划阶段报错。根因是编排命令错误地把两个不同的服务返回值都当作 `{ plan }`：计划提交实际直接返回 `MaterialObservationPlan`，计划批准实际返回 `MaterialObservationReviewDecision`。批准决定已持久化后，页面继续读取不存在的 `approved.plan.status`，因而出现前台报错和状态错觉。

修复后，命令按服务契约分别处理：提交阶段读取 Plan 的 `status`，批准阶段成功后显式进入 `reviewed`，已处于 `pending_review` 的计划不再重复提交。专项自动化覆盖草稿提交批准和待审核直接批准两条路径。

真实浏览器复验结果：

- 任务 1 显示“题目已经发布成功”；
- 批次状态为 `待处理 2 / 待最终确认 0 / 已确认待发布 0 / 已发布 1`，总数守恒为 3；
- 任务 2、任务 3 未被连带确认或发布；
- 持久层存在当前 Plan 的 `reviewed` 状态，以及任务 1 唯一的 Reviewed Draft、Frozen Formal Version 和 Active Registry Entry；
- 学习入口读取正常，因当前学习筛选与去重条件无可消费新任务而显示正常业务空状态。

该问题的防回归规则为：跨服务编排只能消费各服务公开返回契约，不得根据相邻接口形状推测包装字段；阶段成功后必须保存阶段结果，并从失败点继续。
