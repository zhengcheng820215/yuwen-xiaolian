# Learning 正式题组连续消费验收（2026-08-19）

## 1. 问题与目标

旧实现完成一道题后重新执行自适应下一任务匹配；只要能力、难度或任务角色暂时不匹配，反馈页就直接只显示“返回学习入口”。这使录入端已经发布的 4—5 道同材料训练任务无法作为一个稳定题组连续消费。

本次收口冻结以下目标：

- 普通 Training 会话首次进入时冻结同材料、当前可执行的正式版本队列，最多 5 道；
- 学生端显示“第 k / n 题”，完成前一题后直接进入下一题；
- 完成最后一题后才显示“完成本轮学习”；
- Retest / Transfer 不插入当前 Training 题组；
- 刷新和恢复沿用冻结版本身份，不重跑上一题 Diagnosis；
- 下一版本失效或推进失败时显示准确原因，并且不把活动题号留在不可恢复的位置。
- 旧题组引用的 Frozen Resource 已失效时，不得显示通用“学习状态读取失败”；入口必须说明旧题组需要结束，并保留“结束本次学习”操作，已有完成结果不受影响。

## 2. 工程结果

- 新增 `LearningSessionTaskQueue`，持久化 `materialId`、有序 `resourceVersionIds`、题数、版本与创建时间；
- 题组顺序继续复用正式资源顺序规划，基础理解单选可以作为阅读进入层；
- 当前队列明确锁定的正式版本优先于到期 Retest 与新的自适应 Strategy；
- 锁定版本的运行时难度范围与正式版本对齐，避免已发布的进阶题被默认难度再次拒绝；
- 题间推进改为“保存下一题位置 → 预加载下一题 → 失败回滚”，不会出现题号已前进但页面打不开；
- 旧会话若已经保存本题结果但下一题处于旧复核态，入口允许回到反馈页并懒迁移题组；
- 队列与当前/上一正式版本身份不一致时，按 Frozen Version 重建同材料队列，不允许跨材料静默续题；
- 无法重建的失效旧队列投射为可操作的题组失效状态，不再让入口落入无操作的通用错误页；
- Learning 头部与反馈主操作统一使用题号语义，不再显示“第 n 轮 / 进入下一轮任务”。

- Reading Single Choice Stage 4 E2E：`13 / 13 PASS`
- Learning Feedback Revision Stage 4：`19 / 19 PASS`
- Learning Feedback Presentation：`10 / 10 PASS`
- Production Build：`PASS`

真实浏览器验证：

- 旧“下一任务待检查”状态已恢复为“查看反馈并继续”；
- 反馈页显示明确题组进度与下一题按钮；
- 锁定进阶题不再因默认难度范围产生 `difficulty_not_allowed`；
- 新建题组固定同一材料与正式版本顺序；刷新后优先恢复活动题组当前题，不让复测或重新匹配抢占题组；
- 浏览器验收同时发现一条由旧实现遗留、且缺少完整来源身份的跨材料队列。新实现已加入题组身份自检；这类无法安全追溯的既有脏会话不做静默改写，应结束旧会话后重新开始题组。

## 4. 结论

本次问题不是单个按钮文案错误，而是录入端“正式题组”没有进入 Learning 会话契约。现在已收口为稳定题组连续消费：学生完成一道题后优先继续本组下一题，最后一题结束后才回到学习入口；诊断、自适应和复测仍保留，但不再打断当前正式题组。
