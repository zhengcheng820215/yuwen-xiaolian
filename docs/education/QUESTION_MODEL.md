# 题目模型（Question Model）

## 文档定位

本文档是 AI 语文能力诊断与成长系统的题目模型（Question Model）。

本模型负责定义：

- 一道题应该如何被系统理解
- 一道题如何映射能力
- 一道题如何支持诊断
- 一道题如何支持训练
- 一道题如何支持评估

本文档不是题库设计，不是阅读理解模板，不是 Prompt，不是算法实现，也不是页面设计。

本文档是一份可被 AI 调用、可被程序实现、可长期扩展的 Question Model。

未来以下模块必须引用本模型：

- Ability
- Diagnosis
- Training
- Evaluation
- Student Ability Profile
- AI Coach

本文档的核心目标是建立整个系统统一的 Question Language（题目语言）。未来所有题目、AI 诊断、能力训练和能力评估，都必须引用本模型。

本文档用于回答以下问题：

1. 什么是一道题？
2. 为什么题目不是学习目标？
3. 一道题如何映射能力？
4. 一道题如何支持能力诊断？
5. 一道题如何支持能力训练？
6. 一道题如何支持能力评估？
7. AI 如何理解一道题？

题目不是目的。题目只是能力成长的载体。

整个 Question Model 必须体现：

> 题目不是学习目标，而是能力成长载体。

## 一、题目模型定义（Question Definition）

一道题不是一个题干。

在本系统中，一道题是承载能力诊断、能力训练和能力评估的结构化任务。

一道题应该包含：

| 信息类型 | 说明 |
| --- | --- |
| 能力信息 | 该题主要涉及哪些能力、能力路径和前置能力 |
| 诊断信息 | 该题能够观察学生哪些能力表现和错误类型 |
| 训练信息 | 该题适合用于哪些训练阶段和训练策略 |
| 评估信息 | 该题是否适合用于复测、迁移验证或能力升级判断 |

题目的价值不在于学生是否完成这一题，而在于系统能否通过这道题观察、诊断、训练和验证学生能力。

因此，题目是能力载体，不是学习目标。

## 二、题目设计原则（Question Principles）

### 1. 能力优先

所有题目必须服务能力成长。

题目设计、题目标注和题目调用都应首先回答：这道题承载什么能力？

### 2. 诊断优先

题目必须能够支持能力诊断。

一道题应帮助 AI 观察学生在审题、定位、理解、概括、分析、推理和表达中的具体表现。

### 3. 训练优先

题目应能够作为训练载体，被用于能力短板的针对性改善。

题目的训练价值取决于它是否能帮助学生练习某项能力，而不是题目本身是否典型。

### 4. 评估优先

题目应支持能力评估、复测和迁移验证。

不是所有题都适合作为评估题。评估题必须能够产生可靠的能力证据。

### 5. 迁移优先

题目应支持能力迁移。

系统需要通过不同文本、不同题型和不同任务验证学生是否真正掌握能力，而不是只记住原题。

### 6. 可解释

题目与能力之间的关系必须可解释。

系统应能够说明为什么这道题诊断某项能力，为什么适合某类训练，为什么能作为某项评估依据。

### 7. 可追踪

题目使用过程必须能够形成可追踪记录。

同一道题在诊断、训练、修正、复测中的作用应能够被记录并转化为能力证据。

### 8. 可复测

题目模型应支持复测设计。

题目可以直接用于复测，也可以与同能力、不同文本或不同题型的任务共同构成复测资源。

约束：

> 诊断题、训练题和复测题可以来自同一能力任务族，但复测原则上应优先使用新文本或新任务，避免将原题记忆误判为能力提升。

## 三、题目生命周期（Question Lifecycle）

题目不会因为做过一次就结束。

题目的完整生命周期为：

```text
题目录入
↓
能力标注
↓
学生作答
↓
能力诊断
↓
训练
↓
复测
↓
能力评估
↓
继续作为训练资源
```

### 1. 题目录入

系统获得题目文本、题干、任务要求和必要的参考信息。

录入不是题目的终点，而是题目结构化理解的起点。

### 2. 能力标注

系统为题目标注主要能力、辅助能力、能力路径、前置能力和适用训练阶段。

能力标注决定题目如何被诊断、训练和评估模块调用。

### 3. 学生作答

学生基于题目完成作答。

作答结果不仅用于判断答案，也用于观察学生能力表现。

### 4. 能力诊断

系统根据题目能力映射和学生作答，识别能力表现、错误类型和真实能力短板。

### 5. 训练

题目可以进入训练流程，用于针对性训练、重复强化、变式训练、迁移训练或综合训练。

### 6. 复测

题目或同能力任务可用于验证学生是否真正掌握相关能力。

复测关注的是能力是否迁移和保持，而不是是否记住原题答案。

复测题与训练题可以属于同一能力任务族，但不应默认复用完全相同的原题。复测越接近新文本、新任务和独立完成，其形成的能力证据越可靠。

### 7. 能力评估

系统根据题目中的表现生成评估证据，用于能力状态、能力等级和成长趋势判断。

### 8. 继续作为训练资源

题目可以在不同阶段承担不同角色。

同一道题可以先用于诊断，再用于训练，也可以作为后续同能力任务的对照资源。

## 四、题目能力映射（Ability Mapping）

每一道题必须映射能力。

一道题不是对应一个知识点，而是对应多个能力。

但一道题不应无限扩张能力标签。

每道题可以涉及多个能力，但必须有且只有一个主要观察目标，其他能力只作为辅助观察或前置排查依据。

题目能力映射应包含：

| 映射项 | 说明 |
| --- | --- |
| mainAbility | 本题最核心观察、诊断或训练的能力 |
| supportingAbilities | 完成本题时同时涉及，但不是主要结论对象的能力 |
| prerequisiteAbilities | 完成主要能力前需要具备、失败时应优先排查的前置能力 |
| incidentalAbilities | 可能被顺带观察到，但不得因为单题表现直接形成能力结论的能力 |
| abilityPath | 完成本题所依赖的主要能力节点和依赖关系 |
| 训练目标 | 本题可用于训练的能力目标 |

示例能力路径：

```text
审题 -> 信息提取 -> 理解 -> 概括 -> 表达
```

或：

```text
审题 -> 信息提取 -> 理解 -> 分析 -> 推理 -> 表达
```

能力路径用于表达完成任务所需的关键依赖关系，不表示学生真实思考必须严格按单一路径顺序发生。

真实作答过程中，学生可能在多个能力节点之间并行、回退或相互影响。

因此：

```text
Ability Path
= 任务完成所依赖的主要能力节点和依赖关系
≠ 固定线性作答流程
```

未来如果 Runtime 需要更精细的根因追溯，能力路径可以演进为轻量能力依赖图，但当前阶段不需要引入复杂图结构。

能力映射必须支持 DIAGNOSIS_MODEL 的根因追溯。

当学生在某题中表现失败时，系统应根据能力路径检查失败发生在哪一步，而不是直接根据题目类型下结论。

## 五、题目诊断价值（Diagnosis Value）

题目本质上是能力观察器。

一道题能够帮助 AI 观察学生在能力路径中的具体表现。

题目的诊断价值包括：

| 观察点 | 说明 | 关联能力 |
| --- | --- | --- |
| 是否理解题意 | 学生是否明确题目要求、对象、范围和作答方式 | 理解、表达 |
| 是否找到依据 | 学生是否定位到正确文本区域、关键句和关键词 | 信息提取 |
| 是否理解文本 | 学生是否准确理解词句、段落、人物、事件和观点 | 理解 |
| 是否遗漏限定条件 | 学生是否忽略范围、数量、角度或对象限制 | 信息提取、理解 |
| 是否完成概括 | 学生是否能够提炼核心内容、删除无关细节 | 概括 |
| 是否完成分析 | 学生是否能够拆解结构、人物、手法、情感或观点 | 分析 |
| 是否完成推理 | 学生是否能够基于文本依据形成合理判断 | 推理 |
| 是否表达完整 | 学生是否能够准确、完整、有逻辑地呈现答案 | 表达 |

题目的诊断价值不在于它能否区分对错，而在于它能否暴露学生的思维过程。

如果一道题无法支持能力观察、错因识别或证据生成，它在本系统中的诊断价值较低。

## 六、题目训练价值（Training Value）

一道题可以在不同训练阶段承担不同作用。

题目训练价值包括：

| 训练用途 | 说明 |
| --- | --- |
| 首次训练 | 用于帮助学生初步理解某项能力任务 |
| 重复训练 | 用于围绕同一能力点进行稳定性强化 |
| 迁移训练 | 用于验证学生是否能在新文本、新题型或新任务中使用能力 |
| 强化训练 | 用于针对反复出现的能力短板进行集中训练 |
| 综合训练 | 用于多个能力已经具备一定基础后进行综合应用 |

同一道题在不同阶段可能承担不同作用。

例如，同一道题首次使用时可能用于诊断信息提取能力，订正后可用于表达修正，后续还可以作为同类能力训练的对照资源。

题目的训练价值来自它与训练目标的匹配程度。

训练目标永远是能力成长，而不是题目完成。

## 七、题目评估价值（Evaluation Value）

题目可以用于能力评估，但不是所有题都适合作为评估题。

题目的评估价值包括：

| 评估用途 | 说明 |
| --- | --- |
| 能力升级验证 | 判断学生是否达到更高能力等级或更稳定状态 |
| 迁移验证 | 判断学生是否能在新文本、新题型或新任务中使用能力 |
| 复测 | 判断训练后的能力表现是否得到改善 |
| 长期保持验证 | 判断学生经过一段时间后是否仍能稳定完成能力任务 |

适合作为评估题的题目应具备：

- 能够明确映射能力
- 能够产生可解释的能力证据
- 能够观察独立完成情况
- 能够支持迁移或复测
- 能够区分原题记忆与能力掌握

题目评估价值不等于题目难度。

一题是否适合评估，取决于它是否能可靠观察能力状态，而不是它是否更难。

## 八、题目角色（Question Role）

同一道题在不同运行阶段可能承担不同角色，但每次使用必须明确当前角色。

题目角色决定 Runtime 是否允许提示、是否能形成成长证据、是否可用于改善判断。

建议角色类型：

```ts
type QuestionRole =
  | 'diagnostic'
  | 'training'
  | 'guided_practice'
  | 'independent_practice'
  | 'retest'
  | 'transfer'
  | 'maintenance';
```

| 题目角色 | 说明 | 是否允许提示 | 证据用途 |
| --- | --- | --- | --- |
| diagnostic | 用于建立初始能力表现或薄弱点基线 | 尽量不提示 | 可作为 baseline evidence |
| training | 用于围绕目标能力进行训练 | 可以提示 | 形成 training evidence |
| guided_practice | 用于教练式引导练习 | 允许递进提示 | 形成带提示依赖标记的 evidence |
| independent_practice | 用于观察较少提示下的独立表现 | 少量或无提示 | 形成表现证据 |
| retest | 用于训练后复测 | 不应提供方法提示 | 可形成改善迹象 |
| transfer | 用于新文本、新情境或新任务迁移 | 不应提供方法提示 | 形成迁移判断的重要 evidence |
| maintenance | 用于较长时间后的保持检查 | 不应提供方法提示 | 形成长期保持 evidence |

约束：

- 同一道题可以在不同阶段承担不同角色，但每次使用都必须记录当前 `QuestionRole`。
- guided practice 中的好表现不能直接等同于独立能力提升。
- retest / transfer 更适合用于判断改善迹象，但仍不能凭单次表现宣布长期能力提升。
- AI Coach 的介入方式必须服从当前题目角色。

## 九、题目证据质量（Evidence Quality）

题目可以产生能力证据，但不同题目使用方式产生的证据强度不同。

系统不应只判断“有没有 evidence”，还应判断“这条 evidence 有多可靠”。

建议证据质量分层：

| evidenceQuality | 说明 |
| --- | --- |
| low | 高提示完成、原题重复、答案空间过窄或 rubric 不清晰 |
| medium | 较少提示下完成，同能力近迁移，难度基本可比 |
| high | 新文本、新情境、独立完成、难度可比且 rubric 明确 |

影响证据质量的因素包括：

- 是否独立完成；
- 是否使用提示；
- 是否与训练题高度相似；
- 难度是否可比较；
- 是否为延迟复测；
- 是否为迁移任务；
- 题目 rubric 是否足够明确；
- 学生答案是否提供足够可分析内容。

证据质量约束：

- 原题重复产生的 positive evidence 不应直接证明能力提升。
- 高提示完成的 training evidence 应标记提示依赖。
- 新文本、新情境、独立完成的 transfer / retest evidence 更适合支持改善判断。
- 能力提升仍必须由多次 evidence、独立复测和 Student Ability Profile 综合判断。

## 十、题目元数据关系（Question Metadata）

题目元数据用于统一系统对题目的结构化理解。

本模型不维护具体字段清单。

`QUESTION_MODEL.md` 定义题目需要具备哪些运行语义：

- 能力映射语义
- 诊断语义
- 训练语义
- 评估语义
- 难度与适用范围
- 题目身份与版本
- 候选任务关系

具体字段、类型、Schema、Rubric、Assessment Mode、Answer Acceptance、Common Error Candidates 和版本追溯规则，由 `QUESTION_METADATA_MODEL.md` 统一定义。

职责边界：

```text
QUESTION_MODEL
= 题目的产品与教育语义

QUESTION_METADATA_MODEL
= 具体题目的运行契约
```

题目可以提供候选任务关系，例如同能力候选、难度进阶候选、迁移候选、复测候选和前置依赖关系。

但题目不应静态决定“推荐下一题”。

真正的下一题应由 Personalized Next Task Agent 根据 Student Ability Profile、当前 Evidence、提示依赖、最近任务、训练阶段和复测时机综合决定。

## 十一、AI 如何理解一道题（AI Understanding）

AI 不应该把一道题理解成：

```text
题干 + 答案
```

AI 应该把一道题理解为：

```text
能力任务
能力观察点
能力诊断点
能力训练点
能力评估点
```

AI 理解一道题时，应回答以下问题：

- 这道题主要承载什么能力？
- 完成这道题需要哪些前置能力？
- 这道题能观察学生哪些行为？
- 学生可能在哪些能力步骤失败？
- 本题当前以什么 QuestionRole 被使用？
- 本题适合用于诊断、训练、复测、迁移还是保持验证？
- 本题形成的 evidenceQuality 可能处于什么层级？
- 本题形成的证据如何进入能力画像？

AI 永远围绕能力工作，不是围绕答案工作。

因此，AI 对题目的理解必须服务于：

- 能力映射
- 诊断归因
- 训练组织
- 评估验证
- 能力画像更新

## 十二、本模型与其他模型关系

Question 是能力模型的具体载体。

系统关系不应理解为 Question 位于 Evaluation 之后。

Question 贯穿诊断、训练、复测、评估和下一任务生成过程。

更准确的关系可以表示为：

```text
Ability Model
↓
Question Model
↓
Question Metadata
↓
Student Answer
↓
Diagnosis
↓
Ability Evidence
↓
Training / Retest
↓
Evaluation
↓
Student Ability Profile
↓
Personalized Next Task
```

ABILITY_MODEL 定义题目需要承载的能力。

QUESTION_METADATA_MODEL 定义具体题目的运行契约，包括 assessmentMode、rubric、answerAcceptance、commonErrors、candidateTrainingDirections 和版本追溯。

DIAGNOSIS_MODEL 定义题目如何支持能力观察、错因识别和根因追溯。

TRAINING_MODEL 定义题目如何进入训练闭环，并在不同训练阶段承担不同作用。

EVALUATION_MODEL 定义题目如何用于复测、迁移验证、长期保持验证和能力升级判断。

Student Ability Profile 记录题目产生的能力证据、能力状态变化和长期成长趋势。

Personalized Next Task Agent 根据学生画像、证据状态和候选任务关系决定下一道任务。

AI Coach 贯穿作答、反馈、训练、修正和复测过程。它应使用本模型中的题目语言，避免将题目简化为题干、答案和解析。

本模型不涉及：

- 页面设计
- Prompt 编写
- 算法实现
- 数据库设计
- 题库设计
- 具体题目内容
- 知识点体系设计

所有能力最终都需要通过题目进行观察和验证。

题目不是学习目标，而是能力成长载体。未来所有题目、AI 诊断、能力训练和能力评估，都必须引用本模型。
