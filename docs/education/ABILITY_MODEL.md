# 语文能力模型（Ability Model）

## 文档定位

本文档是 AI 语文能力诊断与成长系统的基础能力模型。

本文档不是教学文档，不是教育理论说明，也不是具体训练方案，而是一份可被 AI 调用、可被程序实现、可长期扩展的「语文能力模型」。

未来所有核心模块都必须引用本模型，包括：

- Diagnosis（能力诊断）
- Training（能力训练）
- Evaluation（能力评估）
- Question（题目模型）
- AI Prompt（AI 教练）
- Student Profile（能力画像）

本产品不是围绕“题目”建立，而是围绕“能力”建立。题目只是能力训练和能力诊断的载体。

本文档用于统一回答以下问题：

1. 什么是能力？
2. 为什么要拆分这些能力？
3. 能力之间是什么关系？
4. AI 如何识别能力？
5. 能力成熟需要体现哪些维度？
6. 为什么能力比题目更重要？

### Ability Model 职责边界

Ability Model 定义能力，不直接判断能力。

它负责：

- 定义统一能力 ID 和名称；
- 定义能力边界；
- 定义可观察行为；
- 定义能力之间的依赖关系；
- 定义能力成熟所需要体现的维度。

它不负责：

- 根据单次答案判断能力状态；
- 生成 Ability Evidence；
- 决定能力是否提升；
- 更新 Student Profile；
- 决定下一步训练任务。

## 一、什么是能力（Ability Definition）

在本系统中，能力不是一道题做对，不是一次考试成绩，也不是一个知识点。

能力定义为：

> 在陌生情境中，能够持续、稳定、独立完成某项思维活动的能力。

该定义强调三个核心条件：

- 陌生情境：学生面对的不是已经记住答案的原题，而是新的文本、新的问题或新的表达任务
- 持续稳定：学生不是偶然完成，而是在多次任务中表现出相对稳定的能力状态
- 独立完成：学生能够在较少提示或无提示的情况下完成关键思维活动

能力必须满足以下特点：

| 特点 | 说明 |
| --- | --- |
| 可观察（Observable） | 能够从学生作答、修正、表达和复测表现中观察到 |
| 可诊断（Diagnosable） | 能够被拆解为具体能力表现，并识别薄弱环节 |
| 可训练（Trainable） | 能够通过针对性任务和反馈逐步提升 |
| 可迁移（Transferable） | 能够从一个文本、题型或任务迁移到新的情境 |
| 可复测（Retestable） | 能够通过后续任务验证是否真正掌握 |
| 可成长（Growable） | 能够在持续训练、反馈和复测中形成长期提升 |

正确率只是能力表现之一，不代表能力本身。

一次正确作答可能来自稳定能力，也可能来自猜测、记忆或题目熟悉度。一次错误作答也不必然说明能力不足，可能来自审题偏差、表达不完整或局部信息遗漏。因此，系统不能仅基于单次对错判断能力状态。

### Ability 与 Ability Dimension

能力对象和能力表现维度必须分开。

```text
Ability
= 学生能够完成什么思维活动

Ability Dimension
= 学生以何种成熟程度完成该活动
```

例如：

```text
能力：概括
独立性：mostly_independent
稳定性：basically_stable
迁移性：near_transfer
保持性：not_tested
```

`概括 / 推理 / 表达` 是能力对象。

`独立性 / 稳定性 / 迁移性 / 保持性 / 复杂度适应` 是评估这项能力成熟程度的维度。

具体维度状态、成长层级和证据门槛由 `EVALUATION_MODEL.md` 定义。

## 二、能力设计原则（Ability Principles）

能力模型必须遵循以下原则。

### 1. 能力必须可拆解

每项能力都应能够被进一步拆分为可观察的思维活动。

例如，“理解”不能只作为抽象标签存在，而应能够关联到词句理解、段落理解、语境理解、观点理解等具体表现。

### 2. 能力必须可解释

系统输出能力判断时，必须能够解释判断依据。

能力判断不能只给出等级、分数或结论，而应说明该判断来自哪些作答表现、修正记录或复测证据。

### 3. 能力必须可量化

能力不等于分数，但能力状态需要能够被结构化描述。

系统应能够用等级、状态、证据数量、稳定性、迁移表现等方式描述能力成熟度。

### 4. 能力必须能够形成证据

所有能力判断都必须有证据支撑。

证据可以来自多次作答、文本依据使用、修正过程、独立完成情况、迁移任务表现和长期稳定性。

### 5. 能力必须支持持续成长

能力模型不只用于判断当前水平，也必须支持长期成长追踪。

系统应能够记录能力从不稳定到稳定、从依赖提示到独立完成、从单一任务到迁移应用的变化过程。

### 6. 能力必须支持 AI 自动诊断

能力定义必须足够清晰，使 AI 能够基于学生作答识别能力表现、分析能力短板、生成诊断结论，并提出下一步训练方向。

能力模型应避免模糊、无法判断或无法归因的概念。

## 三、一级能力树（Primary Ability Tree）

本系统采用统一的一级能力树。

```text
语文能力
├── 信息提取
├── 理解
├── 概括
├── 分析
├── 推理
└── 表达
```

一级能力用于统一系统中的能力命名、诊断归因、训练目标、评估维度和能力画像结构。

本文档只定义一级能力及其关系，不展开三级能力。

### 稳定能力 ID

Runtime、Question Metadata、Ability Evidence、Student Profile 和 Evaluation 必须使用稳定能力 ID。

中文名称只作为展示标签。

```ts
type PrimaryAbilityId =
  | 'extraction'
  | 'comprehension'
  | 'summarization'
  | 'analysis'
  | 'inference'
  | 'expression';

type AbilityDefinition = {
  id: PrimaryAbilityId;
  name: string;
  definition: string;
  observableBehaviors: string[];
  commonFailureSignals: string[];
};
```

规则：

```text
系统引用 = abilityId
用户展示 = 中文名称
```

禁止在长期聚合中自由使用：

```text
推理
推理能力
深层推理
文本推断
```

这些表达应映射到稳定 `abilityId`，例如 `inference`。

## 四、一级能力说明

### 1. 信息提取（Extraction）

**能力定义：**  
信息提取是指学生能够从文本中准确找到与问题相关的显性信息、关键词、关键句和限定条件。

**能力价值：**  
信息提取是所有阅读理解和文本分析的基础。学生只有先找到正确的信息来源，后续理解、概括、分析和推理才有可靠依据。

**为什么重要：**  
大量错误并不是学生不会思考，而是没有找到正确文本位置，或遗漏了关键限制条件。信息提取能力不足会导致后续答案偏离文本。

**解决的问题：**  
该能力主要解决学生找不到依据、找错依据、遗漏关键词、忽略题干范围和无法跨句跨段定位信息的问题。

### 2. 理解（Comprehension）

**能力定义：**  
理解是指学生能够准确把握词语、句子、段落和全文在具体语境中的真实含义。

**能力价值：**  
理解能力决定学生是否能够正确进入文本。没有理解，后续概括、分析和推理都会建立在错误基础上。

**为什么重要：**  
语文任务中的许多错误来自对词句含义、人物行为、事件关系、情感态度或观点意图的误解。

**解决的问题：**  
该能力主要解决学生表层阅读、断章取义、脱离语境、误解人物情感和误判作者观点的问题。

### 3. 概括（Summarization）

**能力定义：**  
概括是指学生能够从文本中提炼核心内容，删除无关细节，并用简洁准确的语言表达主要意思。

**能力价值：**  
概括能力帮助学生从信息堆叠走向结构化理解，是连接文本理解与高阶分析的重要能力。

**为什么重要：**  
学生如果只能摘抄原文，不能提炼核心，就难以形成稳定的主旨理解，也难以完成分析和表达任务。

**解决的问题：**  
该能力主要解决学生抓不住重点、回答冗长、照搬细节、无法提炼段意和无法概括主旨的问题。

**边界说明：**  
概括主要负责信息筛选、要点合并、内容压缩和核心结构表达。

主旨、情感、观点的深层提炼，根据题目要求可能同时涉及理解、分析或推理。

因此，不应把所有“概括主旨”题都直接归入 `summarization`，需要结合 Question Metadata 和 rubric 判断主要观察目标。

### 4. 分析（Analysis）

**能力定义：**  
分析是指学生能够拆解文本中的人物、事件、结构、情感、观点和表达方式，并说明其作用或意义。

**能力价值：**  
分析能力使学生从“读懂内容”进入“理解文本如何表达和为什么这样表达”的层面。

**为什么重要：**  
语文学习不仅要求知道文本写了什么，还要求理解文本如何组织、如何表达、如何塑造人物和传达情感。

**解决的问题：**  
该能力主要解决学生只能复述内容、不能分析作用、不能解释手法、不能拆解结构和不能把文本现象与表达效果连接起来的问题。

### 5. 推理（Inference）

**能力定义：**  
推理是指学生能够基于文本中的显性信息和上下文线索，得出合理的隐含判断。

**能力价值：**  
推理能力帮助学生从文本表层走向深层意义，是理解人物动机、情感变化、观点态度和隐含信息的关键能力。

**为什么重要：**  
许多语文题并不会直接给出答案，而要求学生根据文本依据形成合理判断。没有文本依据的推理会变成主观猜测。

**解决的问题：**  
该能力主要解决学生结论缺少依据、因果判断错误、人物动机误判、情感推断偏差和隐含信息识别不足的问题。

### 6. 表达（Expression）

**能力定义：**  
表达是指学生能够用清晰、准确、完整、有逻辑的语言呈现自己的理解、分析和判断。

**能力价值：**  
表达能力是语文能力的外显结果。学生即使已经理解文本，如果无法组织语言，也无法形成有效答案。

**为什么重要：**  
语文评价最终需要通过语言表达呈现。表达不完整、缺少依据、逻辑混乱会掩盖真实理解水平，也会影响系统诊断。

**解决的问题：**  
该能力主要解决学生答案不完整、表述含混、逻辑不清、缺少文本依据、要点遗漏和不能按照任务要求组织语言的问题。

**边界说明：**  
表达不是系统无法定位根因时的兜底标签。

只有当学生已经表现出相应理解、分析或推理结果，但未能完整、准确地外显时，才优先形成 `expression` 相关 evidence。

例如“缺少文本依据”可能代表：

- 没有找到依据 -> `extraction`
- 没理解依据 -> `comprehension`
- 不会连接依据和结论 -> `analysis` / `inference`
- 已经想到但没有写完整 -> `expression`

因此，表达问题必须在排除明显的信息提取、理解、分析或推理缺口后谨慎判断。

## 五、能力依赖关系（Ability Dependency）

能力不是完全并列关系，而是存在任务相关的依赖关系。

常见阅读任务中的依赖示意可以表示为：

```text
信息提取
↓
理解
↓
概括
↓
分析
↓
推理
↓
表达
```

该链条表示：后续能力往往依赖前置能力的稳定性。

但这不是固定流水线。

能力依赖关系是任务相关的依赖图，不是所有题目都必须严格经过同一顺序。

更真实的关系通常是：

```text
信息提取 -> 理解
理解 -> 概括
理解 -> 分析
信息提取 + 理解 + 分析 -> 推理
理解 + 概括 + 分析 + 推理 -> 表达
```

约束：

- 表达不是所有能力最后才发生，它贯穿整个作答过程；
- 推理不一定依赖概括；
- 分析和推理有时是并行关系；
- 概括有时是高阶任务，有时只是信息组织能力；
- 审题本身可能同时涉及理解和信息提取；
- 后一能力失败不一定由前一能力导致。

例如：

- 不会提取信息，就很难进行准确理解
- 不会理解词句和语境，就无法进行有效概括
- 不会概括核心内容，就难以展开结构或人物分析
- 不会分析文本线索，就容易产生无依据推理
- 不会组织语言，就无法呈现真实思考结果

AI 在诊断时需要优先寻找真正缺失的前置能力，而不是直接判断最终能力。

例如，学生在推理题中答错，表面上是推理错误，但真实原因可能是：

- 没有找到关键句，属于信息提取问题
- 误解了人物行为，属于理解问题
- 没有整合多段内容，属于概括或分析问题
- 结论表达不完整，属于表达问题

因此，能力诊断应遵循前置追溯原则，但不能机械套用固定链条：

```text
最终错误 -> 表层能力表现 -> 任务相关依赖检查 -> 候选能力问题
```

Diagnosis Agent 应结合 Question Metadata、rubric、学生答案和 evidenceLinks 判断当前任务中的真实依赖关系。

## 六、能力成长机制（Ability Growth）

能力成长不是刷更多题。

Ability Model 只定义能力成长的语义目标。

能力成长意味着学生逐步表现出：

- 从依赖提示到独立完成；
- 从偶然表现到稳定表现；
- 从熟悉任务到陌生情境迁移；
- 从即时表现到长期保持；
- 从单一任务到复杂任务应用。

完整成长闭环通常是：

```text
能力诊断
↓
针对训练
↓
复测验证
↓
形成新的能力证据
↓
能力升级
```

能力成长不是一次性结论，而是长期变化过程。系统应持续观察学生是否从依赖提示走向独立完成，是否从熟悉题型走向陌生情境迁移，是否从偶尔正确走向稳定完成。

题目完成不等于能力成长。只有当系统能够确认某项能力在新的任务中表现更稳定、更独立或更可迁移时，才能判断能力发生提升。

具体成长层级、证据门槛、证据充足性、冲突处理和状态转换规则，由 `EVALUATION_MODEL.md` 统一定义。

### 能力提升判断约束

“能力提升”不是 AI 输出的描述字段，而是一个需要经过时间、多次表现和独立复测才能成立的状态。

单次作答、单次训练或单次复测只能形成能力证据，不能直接证明长期能力提升。

系统在证据尚不足时，应使用谨慎状态：

- 出现改善迹象
- 初步改善
- 本次复测表现优于训练前
- 尚未稳定
- 需要继续观察

系统不应在证据不足时输出：

- 能力已经提升
- 能力已经掌握
- 薄弱点已经解决
- 训练后能力明显提高

能力提升的具体判定不由 Ability Model 执行。

Ability Model 只规定：

> 所谓能力成长，必须体现独立性、稳定性、迁移性和持续性，而不能由单次表现直接宣布。

## 七、能力等级（Ability Level）

能力等级用于描述能力成熟度，不是分数，也不是正确率。

本系统采用五级能力等级：

| 等级 | 名称 | 定义 |
| --- | --- | --- |
| Lv1 | 需要大量引导 | 学生无法独立完成该能力任务，需要明确提示、步骤拆解或直接示范 |
| Lv2 | 能够模仿完成 | 学生能够在示范或固定结构下完成任务，但独立性和稳定性不足 |
| Lv3 | 能够独立完成 | 学生能够在常规任务中独立完成该能力活动，表现相对稳定 |
| Lv4 | 能够迁移应用 | 学生能够在不同文本、题型或任务场景中迁移使用该能力 |
| Lv5 | 能够稳定完成复杂任务 | 学生能够在复杂文本、多步骤任务或综合表达任务中稳定完成该能力活动 |

能力等级代表能力成熟度，而不是考试成绩。

Lv1-Lv5 是多个评估维度综合后的摘要，不应替代内部维度状态。

系统判断等级时，应综合考虑：

- 是否需要提示
- 是否能够独立完成
- 是否能够在不同文本中保持稳定
- 是否能够迁移到不同题型
- 是否能够处理复杂任务
- 是否能够长期保持

内部仍应保留：

- independence；
- stability；
- transferStatus；
- retentionStatus；
- complexityAdaptation。

例如，一个学生可以独立完成复杂常规题，但尚无迁移证据；此时不能只靠 Lv 说明全部状态。

## 八、能力证据（Ability Evidence）

能力判断必须基于证据。

AI 判断某项能力达到某一等级时，必须能够说明该判断依据。没有证据，不能输出能力判断。

Ability Model 只声明证据原则，不维护完整 Evidence Schema。

能力结论必须基于可追溯、多源、独立、可迁移的 evidence。

证据原则：

| 原则 | 说明 |
| --- | --- |
| 多源性 | 证据不应只来自一次作答，而应来自多个任务和多个过程 |
| 可追溯性 | 每个能力结论都应能回到具体作答、修正或复测记录 |
| 稳定性 | 能力判断应基于连续表现，而不是单次结果 |
| 迁移性 | 能力提升需要在新情境中被验证 |
| 独立性 | 能力成熟度需要区分有提示完成和独立完成 |

具体 Evidence 类型、字段、来源、提示依赖、聚合资格和 comparison baseline，由 `ABILITY_EVIDENCE_CONTRACT.md` 定义。

多条 evidence 允许形成什么成长结论，由 `EVALUATION_MODEL.md` 定义。

## 九、能力可观察行为（Observable Behaviors）

Ability Model 必须定义什么表现可以观察，什么表现不足以形成能力结论。

每项能力后续都应逐步补充：

```ts
type AbilityObservationRule = {
  abilityId: PrimaryAbilityId;
  positiveSignals: string[];
  riskSignals: string[];
  insufficientConditions: string[];
};
```

当前先定义关键边界。

### 推理（Inference）

可观察正向表现：

- 能指出文本线索；
- 能说明线索与结论之间的关系；
- 结论不超出文本边界；
- 能在新材料中使用同类推理方法。

可观察风险表现：

- 只有结论，没有依据；
- 依据与结论没有关系；
- 用生活经验替代文本；
- 推断范围超出文本。

不足以形成推理薄弱结论的情况：

- 空答案；
- 纯数字；
- 表达过短但无法判断是否理解；
- 题目元数据不完整；
- 学生未完成最低作答要求。

### 概括（Summarization）

可观察正向表现：

- 能筛选主要信息；
- 能合并同类要点；
- 能删除无关细节；
- 能用简洁语言表达核心结构。

可观察风险表现：

- 只摘抄原文；
- 保留大量无关细节；
- 遗漏核心对象、事件或结果；
- 把深层主旨问题简单当作内容压缩。

不足以形成概括薄弱结论的情况：

- 题目实际主要考察理解、分析或推理；
- 学生答案太短且无法判断是否完成信息筛选；
- 参考答案或 rubric 没有明确核心信息结构。

### 表达（Expression）

可观察正向表现：

- 能完整呈现已经形成的理解、分析或判断；
- 能按题目要求组织答案；
- 语言清晰，逻辑顺序合理；
- 能把依据、解释和结论表达出来。

可观察风险表现：

- 表述含混；
- 结构混乱；
- 要点顺序不清；
- 已有理解但没有完整外显。

不足以形成表达薄弱结论的情况：

- 学生没有找到文本依据；
- 学生明显误解文本；
- 学生没有形成分析或推理关系；
- 作答无效或证据不足。

这些情况应先进入 extraction、comprehension、analysis 或 inference 的候选原因排查，而不是直接归为 expression。

## 十、能力画像（Ability Profile）

能力画像用于记录学生在各项能力上的当前状态和成长变化。

能力画像记录的是成长，不是考试成绩。

Ability Model 只说明每项能力都必须能够被长期画像记录。

能力画像至少需要能够表达：

- 当前成熟度；
- 独立性、稳定性、迁移性与保持性；
- 支撑 Evidence；
- 当前限制；
- 待验证事项。

具体字段、状态转换、更新策略和长期记录结构由 `STUDENT_PROFILE_MODEL.md` 定义。

能力画像应具备以下特征：

- 以能力为主线，而不是以题目为主线
- 记录长期变化，而不是只记录单次结果
- 能够解释当前判断，而不是只呈现等级
- 能够支持下一步训练，而不是只做静态展示
- 能够被后续诊断、训练、评估和 AI 教练模块调用

能力画像的核心价值是帮助系统理解学生在语文能力上的真实状态，并持续追踪其成长路径。

## 十一、本模型与其他模型关系

ABILITY_MODEL 是整个 AI 语文能力诊断与成长系统的基础模型。

后续文档和模块必须引用本模型，包括：

- DIAGNOSIS_MODEL
- TRAINING_MODEL
- QUESTION_MODEL
- EVALUATION_MODEL
- PROMPT_GUIDE
- Student Profile

本模型负责定义系统对于“能力”的统一理解，包括：

- 能力定义
- 能力设计原则
- 一级能力树
- 一级能力说明
- 能力依赖关系
- 能力成长语义目标
- 能力等级摘要边界
- 能力证据上位原则
- 能力画像上位原则
- 可观察行为边界

本模型不涉及：

- 页面设计
- Prompt 编写
- 算法实现
- 数据库设计
- 具体题库内容
- 具体训练任务设计

所有后续 AI 行为都必须以本模型作为唯一能力标准。

当其他模块需要判断“学生具备什么能力”“学生缺失什么能力”“下一步训练什么能力”“能力是否发生成长”时，必须回到本模型进行定义和归因。

模块边界：

```text
ABILITY_MODEL
定义能力是什么、能力边界是什么、什么表现可以观察

QUESTION_MODEL / QUESTION_METADATA_MODEL
定义某道题能够观察哪些能力

DIAGNOSIS_MODEL
从一次作答中识别可观察表现和候选能力问题

ABILITY_EVIDENCE_CONTRACT
把一次表现保存成最小证据单元

EVALUATION_MODEL
聚合多次 evidence，判断成长层级和状态变化

STUDENT_PROFILE_MODEL
保存长期能力状态和成长历史
```

Ability Model 是基础语言，但不负责完成诊断、评估、证据契约或画像更新。
