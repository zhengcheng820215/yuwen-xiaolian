# AI 语文能力诊断与成长系统（AI Language Ability Diagnosis & Growth System）

## 一、产品定位

本产品不是刷题工具，也不是单纯的提分工具。

本产品是面向初中生的「AI 语文能力诊断与成长系统」。它通过 AI 对学生作答过程进行持续诊断，帮助学生发现能力短板、理解错误原因、完成针对性训练，并通过复测验证能力是否真正提升。

产品目标不是让学生做更多题，而是帮助学生建立可迁移的语文能力，包括：

- 准确理解文本
- 快速提取关键信息
- 清晰概括核心内容
- 有依据地分析与推理
- 用完整、准确、有逻辑的语言表达思考

题目只是能力诊断和能力训练的载体。系统真正关注的是：学生为什么这样答、暴露了什么能力问题、下一步应该如何训练。

核心学习路径为：

```text
能力诊断 -> 错因分析 -> 针对训练 -> 复测验证 -> 能力成长
```

## 什么是能力（What is Ability）

在本产品中，能力不是一次考试成绩，也不是一道题做对。

能力是学生在陌生情境下，能够持续、稳定、独立完成某项思维活动的表现。它体现的是学生面对新文本、新问题和新表达任务时，是否能够调动已有方法，完成理解、提取、概括、分析、推理和表达。

因此，能力必须具备以下特征：

- 可诊断（Diagnosable）：能够从学生作答和思考过程中识别具体能力状态
- 可训练（Trainable）：能够通过有针对性的任务和反馈逐步提升
- 可迁移（Transferable）：能够从当前题目迁移到新的文本、题型和表达场景
- 可复测（Retestable）：能够通过后续任务验证是否真正掌握
- 可成长（Growable）：能够在持续训练和反馈中形成长期提升

正确率只是能力表现之一，不等于能力本身。一个学生做对一道题，可能是能力稳定，也可能是偶然猜对；一个学生做错一道题，也不必然说明能力不足，可能是审题、表达或文本依据使用中的局部问题。

系统需要关注的不是单次结果，而是学生在多次任务中的稳定表现和成长变化。

## 二、核心原则

### 1. 能力优先，而非题目优先

所有学习内容必须映射到具体能力，而不是停留在题目、篇目或知识点本身。

例如：

- 一篇阅读理解不是几道题的集合
- 而是一次「信息提取 + 理解 + 概括 + 推理 + 表达」的综合诊断

系统不以“做完多少题”为核心指标，而以“哪些能力被诊断、哪些短板被修正、哪些能力完成提升”为核心指标。

### 2. 题目只是载体，不是目的

题目的作用不是制造练习量，而是暴露学生的思考过程。

每一道题都应该回答三个问题：

- 这道题考查了什么能力？
- 学生的回答暴露了什么能力短板？
- 接下来应该如何训练这个短板？

因此，学习过程不应是：

```text
做题 -> 对答案 -> 结束
```

而应是：

```text
作答 -> 诊断 -> 分析错因 -> 训练能力 -> 修正表达 -> 再次验证
```

### 3. AI 不是答案机器

AI 不应该只告诉学生“正确答案是什么”。

AI 的核心职责是识别学生的思维缺口，并帮助学生修正思考路径。

AI 应该：

- 引导学生回到文本寻找依据
- 追问学生为什么这样判断
- 判断学生在哪个能力环节出现问题
- 给出可执行的训练建议
- 陪伴学生完成修正和复测

AI 不应该：

- 直接替学生完成思考
- 只给标准答案
- 只解释题目本身
- 只用分数或星级评价学生

### 4. 每一道题都是一次能力诊断

题目不是学习目标，题目只是诊断能力的载体。

每一次作答都应该帮助系统理解：

- 学生为什么这样回答？
- 学生在哪一步思考出现问题？
- 下一步应该训练什么能力？

产品真正积累的不是做题数量，而是能力成长数据，包括能力表现、错因类型、修正过程、复测结果和长期变化。

## 三、产品开发原则：最小闭环模块驱动

本项目采用“最小闭环模块 -> 阶段功能 -> 产品能力”的递进开发方式。

产品开发不是以页面数量为目标，而是以产品能力逐步形成作为目标。

每个最小功能模块都必须具备明确输入、明确处理逻辑、明确输出结果，并且可以独立运行、独立验收。

若干个最小闭环模块组合形成一个阶段功能；若干个阶段功能持续累积，最终形成完整产品能力。

本项目避免一次性搭建复杂系统，而是通过可运行、可验证、可协同的小模块，让产品逐步从工程 Demo 进化为可用的 AI 学习 Runtime。

## 四、能力模型

语文能力由多个可诊断、可训练、可复测的能力维度构成。

### 1. 信息提取能力（Extraction）

从文本中准确获取显性信息。

能力表现包括：

- 找到题干对应的文本区域
- 提取关键词和关键句
- 区分主要信息与次要信息
- 识别限定条件
- 跨句或跨段整合相关信息

能力层级：

- Lv1：能找到明显信息
- Lv2：能定位关键信息
- Lv3：能跨句整合信息
- Lv4：能识别隐含或变形表达的信息
- Lv5：能在复杂文本结构中准确提取多重信息

### 2. 理解能力（Comprehension）

理解词句、段落和全文的真实含义。

能力表现包括：

- 理解词语在语境中的含义
- 理解句子表层和深层意思
- 理解段落之间的关系
- 把握人物、事件、情感和观点
- 避免脱离文本的主观臆断

### 3. 概括能力（Summarization）

从文本中提炼核心内容，并用简洁准确的语言表达。

能力表现包括：

- 提取主要对象、事件和结果
- 删除无关细节
- 合并同类信息
- 提炼段落大意
- 概括全文主旨

### 4. 分析能力（Analysis）

拆解文本内容、结构、人物、情感和表达方式。

能力表现包括：

- 分析人物形象
- 分析事件发展逻辑
- 分析段落结构和行文思路
- 分析写作手法及其作用
- 分析情感变化和表达效果

### 5. 推理能力（Inference）

基于文本依据推导隐含信息。

能力表现包括：

- 因果推理
- 动机推理
- 观点推理
- 情感推理
- 隐含信息推断
- 从多个文本线索中形成合理判断

### 6. 表达能力（Expression）

用清晰、完整、准确、有逻辑的语言表达思考结果。

能力表现包括：

- 回答完整，不遗漏关键要点
- 表述准确，不含混、不跑题
- 逻辑清楚，有先后和层次
- 能结合文本依据组织答案
- 能根据题目要求进行改写、仿写、扩写、缩写和议论表达

## 五、能力诊断模型

每一道题都应被视为一次能力诊断，而不是一次简单判分。

系统需要从学生作答中分析：

- 学生是否理解了题目要求
- 学生是否找到了正确的文本依据
- 学生是否提取了关键内容
- 学生是否完成了必要的概括、分析或推理
- 学生是否能用清晰完整的语言表达答案

同一道题可能同时诊断多个能力维度。例如，一道阅读理解题可能同时涉及：

| 题目环节 | 诊断能力 |
| --- | --- |
| 审题 | 理解能力、信息提取能力 |
| 找依据 | 信息提取能力 |
| 整合内容 | 概括能力、分析能力 |
| 得出结论 | 推理能力 |
| 写出答案 | 表达能力 |

诊断结果不应只输出“对/错”，而应输出能力画像：

- 哪些能力已经稳定掌握
- 哪些能力处于不稳定状态
- 哪些能力明显薄弱
- 哪些错误是偶发失误
- 哪些错误反映了系统性能力缺口

能力诊断不能因为一道题就判断学生能力不足。单次结果只能作为诊断线索，不能直接等同于能力结论。

系统需要持续收集多个证据，包括：

- 多次作答
- 不同文本
- 不同题型
- 修正过程
- 独立完成情况
- 复测结果

最终，系统应基于持续证据形成学生的能力画像。能力判断应来自长期、稳定、可验证的表现，而不是单次结果。

## 六、错因分析模型

学生做错题后，系统必须判断具体错因，而不是只展示正确答案。

常见错因包括：

| 错因类型 | 说明 |
| --- | --- |
| 信息没找到 | 没有定位到题目对应的文本区域或关键句 |
| 信息找错 | 找到了文本内容，但依据与题目要求不匹配 |
| 理解偏差 | 对词句、人物、事件、情感或观点理解错误 |
| 忽略限定条件 | 漏看题干中的范围、对象、角度或数量要求 |
| 不会概括 | 只摘抄细节，不能提炼核心意思 |
| 整合不足 | 只能处理单句信息，无法跨句或跨段整合 |
| 推理错误 | 结论缺少文本依据，或推理链条不成立 |
| 分析角度偏离 | 回答没有围绕人物、结构、手法、情感等指定角度展开 |
| 表达不完整 | 答案要点缺失，语义不完整 |
| 缺少文本依据 | 只给结论，没有结合文本说明原因 |
| 表述不清 | 语言含混、逻辑混乱、层次不明 |

错因分析要服务于后续训练。系统需要把“错在哪里”转化为“练什么”和“怎么练”。

例如：

```text
错因：缺少文本依据
能力短板：信息提取 + 表达能力
训练方向：先回到原文标出依据，再用“依据 + 分析 + 结论”的结构重写答案
```

## 七、能力证据（Ability Evidence）

能力评估不能只给分数、星级或等级，还必须展示支撑结论的证据。

能力证据是系统判断学生能力状态的依据，来自学生的作答内容、修改过程、提示响应和复测表现。

能力证据可以包括：

- 能快速定位题目对应的文本区域
- 能准确提取关键词和关键句
- 能用自己的话概括段落核心意思
- 能找到文本依据支持判断
- 能在提示后修正答案
- 能独立完成同类题迁移
- 能处理单句信息，但无法跨段整合
- 能找到答案区域，但容易遗漏限定条件
- 能得出大致结论，但表达不完整
- 能说出人物特点，但缺少文本依据
- 能理解表层意思，但无法推断隐含情感

系统输出能力结论时，应同时呈现：

| 输出项 | 示例 |
| --- | --- |
| 能力判断 | 信息提取能力较稳定，跨段整合能力偏弱 |
| 支撑证据 | 能定位关键段落，但遗漏了第二段中的限定条件 |
| 错因解释 | 作答只依据单一信息点，未整合前后文 |
| 训练建议 | 进行“多段信息合并”和“限定条件标注”训练 |

能力证据的意义在于让学生、家长和教师知道：系统为什么这样判断，以及下一步为什么这样训练。

### 能力证据原则

系统所有能力判断都必须有证据支撑。

能力证据不仅来自：

- 对错
- 正确率

还来自：

- 思考过程
- 是否引用文本依据
- 是否遗漏限定条件
- 是否能够独立完成
- 是否能够完成迁移
- 是否能够完成修正
- 是否能够稳定保持

没有证据，不输出能力结论。任何能力判断都应能回到学生的具体作答、修正记录、训练表现和复测结果中找到依据。

## 八、能力训练机制

能力不是通过看答案增长的，而是在“思考、表达、反馈、修正”的过程中增长。

每一次训练必须包含以下步骤。

### Step 1：输入（Input）

学生阅读文本、题干或任务，系统识别本次任务对应的能力维度。

### Step 2：作答（Answer）

学生必须先用自己的语言回答。系统应保留学生的原始答案，用于能力诊断和错因分析。

### Step 3：诊断（Diagnosis）

系统根据题目要求、文本依据和学生答案，判断学生在哪些能力环节表现稳定，在哪些环节出现短板。

### Step 4：反馈（Feedback）

AI 给出面向能力的反馈，而不是只解释答案。

反馈应包括：

- 哪些地方答对了
- 哪些关键点遗漏了
- 错因属于哪一类
- 应该回到文本哪里重新思考
- 下一次作答应使用什么表达结构

### Step 5：修正（Revision）

学生基于反馈修改答案。系统比较原答案和修正答案，判断学生是否真正理解了错误原因。

### Step 6：针对训练（Targeted Practice）

系统根据错因生成或推荐小步训练，例如：

- 关键词定位训练
- 限定条件标注训练
- 段意概括训练
- 跨段信息整合训练
- 文本依据补充训练
- “依据 + 分析 + 结论”表达训练

### Step 7：复测验证（Retest）

系统通过同能力、不同文本或不同题型进行复测，判断学生是否能迁移应用，而不是只记住原题答案。

## 九、能力成长闭环

能力成长必须形成闭环，而不是停留在一次讲解或一次订正。

完整闭环为：

```text
作答记录 -> 能力诊断 -> 错因分析 -> 能力证据 -> 针对训练 -> 修正表达 -> 复测验证 -> 能力画像更新
```

每一轮闭环都应完成：

- 诊断一个具体能力点
- 确认一个主要错因
- 提供一条可执行的修正路径
- 完成一次针对性训练
- 通过复测验证是否迁移
- 更新学生的能力画像

系统应持续追踪能力状态，例如：

| 能力点 | 当前状态 | 证据 | 下一步 |
| --- | --- | --- | --- |
| 信息定位 | 稳定 | 能快速找到关键段落和关键词 | 增加复杂文本训练 |
| 限定条件识别 | 不稳定 | 多次遗漏“结合全文”“两个方面”等要求 | 加强审题标注训练 |
| 跨段整合 | 薄弱 | 回答常只引用单段信息 | 进行多段信息合并训练 |
| 文本依据表达 | 薄弱 | 有结论但缺少依据 | 训练“依据 + 分析 + 结论”结构 |

题目不是终点。题目完成后，系统真正要沉淀的是能力数据、错因数据、证据数据和下一步训练路径。

一次训练结束的标志不是学生知道答案，而是系统确认某项能力获得提升。系统关注的是能力变化，而不是题目完成。

## 十、AI 教练角色

AI 在本产品中的角色不是讲题老师，也不是答案机器，而是学生语文能力成长过程中的诊断者、教练、陪练和评估者。

### 1. AI 作为诊断者

AI 需要从学生答案中识别能力表现和能力短板。

诊断者关注：

- 学生是否找到了正确依据
- 学生是否理解题意和文本
- 学生是否能概括和整合信息
- 学生是否能完成合理推理
- 学生是否能清楚表达

### 2. AI 作为教练

AI 需要提供可执行的改进路径。

教练不只是说“你错了”，而是告诉学生：

- 错因是什么
- 应该回到哪里重新看
- 应该补上哪个思考步骤
- 应该使用什么答题结构
- 下一次如何避免同类错误

### 3. AI 作为陪练

AI 需要陪学生完成小步训练和多轮修正。

陪练应做到：

- 先提示，不直接代答
- 根据学生反应逐步降低或提高提示强度
- 鼓励学生自己补充依据、修正表达
- 用变式题验证是否真正掌握

### 4. AI 作为评估者

AI 需要基于能力标准和能力证据更新学生画像。

评估者不只输出分数，而要输出：

- 能力状态
- 支撑证据
- 主要错因
- 成长变化
- 下一步训练建议

## 十一、产品核心定义

本产品通过“AI 能力诊断 + 错因分析 + 针对训练 + 复测验证”的闭环，帮助学生从做题走向理解，从答案走向思维，从单次订正走向长期能力成长。

一句话定义：

> 本产品不是刷题工具，而是一个以题目为诊断载体、以 AI 为成长教练、以能力证据为评估基础的语文能力诊断与成长系统。

## 设计理念（Design Philosophy）

本产品的设计建立在以下理念之上：

- 题目不是目的，能力才是目的。
- 每一道题都是一次能力诊断。
- 每一次错误都是一次能力分析机会。
- 每一次反馈都应该形成下一步训练。
- AI 不负责告诉学生答案，而负责帮助学生形成正确的思考过程。
- 系统真正积累的不是题库数据，而是能力成长数据。

本产品不是让学生做更多题，而是让学生通过每一道题，更了解自己的思维方式，并持续提升语文能力。
