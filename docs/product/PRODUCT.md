# AI 语文能力诊断与成长系统（AI Language Ability Diagnosis & Growth System）

## 一、产品定位

本产品不是刷题工具，也不是单纯的提分工具。

本产品是面向初中生的 AI 语文能力诊断与成长系统。它通过有效任务、学生作答、能力证据、针对训练和复测评估，帮助学生发现能力薄弱点，并围绕薄弱点完成可验证的提升过程。

产品目标不是让学生做更多题，而是帮助学生建立可迁移的语文能力，包括：

- 准确理解文本
- 快速提取关键信息
- 清晰概括核心内容
- 有依据地分析与推理
- 用完整、准确、有逻辑的语言表达思考

题目只是能力观察、证据生成和训练验证的载体。

系统真正关注的是：

- 学生这次作答是否有效；
- 学生完成了哪些能力动作；
- 学生在哪些地方暴露出可观察问题；
- 这些问题能否沉淀为 Ability Evidence；
- 下一步更适合训练、复测、迁移验证还是继续诊断。

核心学习路径为：

```text
有效任务
→ 学生独立作答
→ 作答有效性判断
→ 本次能力诊断
→ Ability Evidence
→ 针对反馈与训练
→ 独立复测或迁移验证
→ 多次 Evidence 评估
→ Student Ability Profile 更新
→ 下一步个性化任务
```

## 二、产品核心价值

### 1. 能力优先，而非题目优先

所有学习内容必须映射到具体能力，而不是停留在题目、篇目或知识点本身。

系统不以“做完多少题”为核心指标，而以“哪些能力被观察、哪些问题被验证、哪些能力状态获得证据支持”为核心指标。

### 2. 题目是能力观察机会

每一道经过能力标注的有效任务，都是一次能力观察与证据生成机会。

单题不能直接形成长期能力结论。

无效答案不能形成具体能力诊断。

题目的作用不是制造练习量，而是帮助系统观察学生如何理解、提取、概括、分析、推理和表达。

### 3. 证据驱动，而非主观判断

单次作答产生观察。

单次诊断产生证据。

多次证据形成评估。

评估结果推动画像更新。

画像状态驱动下一步任务。

没有证据，不输出长期能力结论。

### 4. 能力提升必须被验证

“能力提升”不是 AI 输出的描述字段，而是一个需要经过时间、多次表现和独立复测才能成立的状态。

系统可以在单次作答、训练或复测后记录：

- 改善迹象
- 本次表现优于训练前
- 仍需继续观察
- 建议进入复测或提高难度

但系统不应仅凭一次作答、一次训练或一次 AI 评价直接宣布：

- 某项能力已经提升
- 某项能力已经掌握
- 某个薄弱点已经解决

能力提升判断必须至少依赖多条可追溯证据，并优先包含新题、新文本或新情境下的独立复测证据。

## 三、产品非目标

本产品当前不追求：

- 提高刷题数量
- 追求题库规模
- 做成自动批改工具
- 用分数或等级替代能力成长
- 用单次 AI 判断定义学生长期能力
- 通过排行榜、经验值或奖励系统驱动学习

旧的刷题、错题、等级经验模块可以作为辅助功能暂时保留或弱化，但不应成为当前产品主线。

当前产品主线是：

```text
发现问题
→ 形成证据
→ 制定训练
→ 执行训练
→ 复测验证
→ 更新画像
→ 推荐下一步任务
```

## 四、能力模型定位

本产品围绕六项一级能力运行：

- 信息提取
- 理解
- 概括
- 分析
- 推理
- 表达

能力不是一次考试成绩，也不是一道题做对。

能力是学生在陌生情境下，能够持续、稳定、独立完成某项思维活动的表现。它体现的是学生面对新文本、新问题和新表达任务时，是否能够调动已有方法完成任务。

能力必须体现：

- 独立性
- 稳定性
- 可迁移性
- 可复测性
- 可成长性

各能力的正式定义、边界、可观察行为、依赖关系和成熟度，以 `ABILITY_MODEL.md` 为唯一标准。

PRODUCT.md 不重复维护完整能力模型，避免与能力模型文档产生冲突。

## 五、诊断与证据原则

单次诊断不应输出长期能力画像。

单次诊断应输出：

- 本次作答有效性
- 本次答案状态
- 可观察表现
- 表面错误
- 根因假设或支持性判断
- 可供 Evidence Extractor 消费的结构化结果

长期能力画像必须由多次 Evidence 经 Evaluation 聚合后形成。

核心链路为：

```text
Diagnosis Result
→ Ability Evidence
→ Evaluation Result
→ Profile Update Decision
→ Student Ability Profile
```

这意味着：

- Diagnosis 负责本次作答诊断；
- Ability Evidence 负责保存一次表现证据；
- Evaluation 负责判断多条证据能支持什么结论；
- Student Profile 负责保存长期状态。

具体诊断规则以 `DIAGNOSIS_MODEL.md`、`OPEN_RESPONSE_DIAGNOSIS_RULES.md` 和 `AGENT_PROTOCOL.md` 为准。

一次表现如何转化为证据，以 `ABILITY_EVIDENCE_CONTRACT.md` 为准。

## 六、错因与根因原则

系统需要识别学生作答中的主要问题，但不应为了完成闭环强行确认根因。

一轮学习可能只能得到：

- 表面错误
- 候选根因
- 待验证假设
- 证据不足

系统必须允许：

```text
rootCause = unresolved
```

更稳妥的产品表达是：

```text
识别一个主要问题，
并在证据允许时形成根因假设或支持性判断。
```

示例：

```text
观察表现：
答案给出了结论，但未呈现文本依据。

候选原因：
信息提取、推理连接或表达组织仍需验证。

下一步：
通过追问或诊断性任务确认主要缺口。
```

不推荐直接写成：

```text
错因：缺少文本依据
能力短板：信息提取 + 表达能力
```

因为“缺少文本依据”只是可观察现象，背后的真实原因需要更多证据支持。

## 七、训练与复测原则

能力不是通过看答案增长的，而是在“思考、表达、反馈、修正、复测”的过程中逐步建立。

一次训练结束的标志不是学生记住答案，而是当前训练目标已经完成，或学生已经具备进入独立复测、迁移验证或重新诊断的条件。

训练可以结束于：

- 当前训练小目标已达到
- 提示依赖有所下降
- 已具备进入独立复测的条件
- 需要进入迁移验证
- 需要暂停并重新诊断

Training completed 不等于 Ability growth confirmed。

能力是否真正提升，由后续 Evaluation 基于多次 Evidence 判断。

具体训练模型以 `TRAINING_MODEL.md` 为准。

具体评估模型以 `EVALUATION_MODEL.md` 为准。

## 八、AI 角色边界

AI 在本产品中的角色不是讲题老师，也不是答案机器。

AI 可以承担：

- 当前作答诊断
- 学习表现反馈
- 教练式追问
- 小步训练陪伴
- 已确认评估结果的解释
- 下一步任务建议

AI Coach 负责把已经确认的诊断、证据和评估结果转化为学生可理解的反馈。

AI Coach 不能独立宣布：

- 能力提升
- 状态升级
- 薄弱点解决
- 长期能力稳定

Evaluation Runtime 基于能力证据形成评估结果与画像更新决策。

Student Profile Runtime 根据合法的 Profile Update Decision 更新长期画像。

AI 教练行为以 `AI_COACH_MODEL.md` 为准。

学生画像规则以 `STUDENT_PROFILE_MODEL.md` 为准。

## 九、产品开发原则：最小闭环模块驱动

本项目采用“最小闭环模块 -> 阶段功能 -> 产品能力”的递进开发方式。

产品开发不是以页面数量为目标，而是以产品能力逐步形成作为目标。

每个最小功能模块都必须具备：

- 明确输入
- 明确处理逻辑
- 明确输出结果
- 可独立运行
- 可独立验收
- 可被下游模块消费

若干个最小闭环模块组合形成一个阶段功能；若干个阶段功能持续累积，最终形成完整产品能力。

本项目避免一次性搭建复杂系统，而是通过可运行、可验证、可协同的小模块，让产品逐步从工程 Demo 进化为可用的 AI 学习 Runtime。

开发原则：

- 文档先行
- Debug 先行
- 最小闭环先行
- 验收后冻结
- 代码不提前承载长期复杂度
- 数据必须能被下游消费

## 十一、产品一句话定义

本产品通过“有效任务 -> 能力观察 -> 能力证据 -> 针对训练 -> 独立复测 -> 证据评估 -> 画像更新 -> 个性化下一步任务”的闭环，帮助学生从做题走向理解，从答案走向思维，从单次订正走向长期能力成长。

一句话定义：

> 本产品不是刷题工具，而是一个以有效任务为观察载体、以 AI 为成长教练、以能力证据为评估基础的语文能力诊断与成长系统。

## 十二、设计哲学（Design Philosophy）

### 产品定位

本系统不是面向低龄儿童的娱乐化学习产品，而是一套面向初中阶段学生的 AI 能力提升系统。

系统坚持：

- Ability First（能力优先）
- Evidence Driven（证据驱动）
- Long-term Growth（长期成长）
- Professional Learning（专业学习）

不以游戏化和即时激励作为核心设计手段，而以真实能力提升作为唯一目标。

### 核心原则

本产品的设计建立在以下理念之上：

- 题目不是目的，能力才是目的。
- 有效任务提供能力观察机会。
- 单次作答产生观察，不能定义长期能力。
- 每一次错误都是一次理解学生思维方式的机会。
- 每一次反馈都应该服务于下一步行动。
- AI 不负责替学生思考，而负责帮助学生形成正确的思考过程。
- 系统真正积累的不是题库数据，而是能力证据和成长记忆。

本产品不是让学生做更多题，而是让学生通过每一次有效任务，更了解自己的思维方式，并持续建立可迁移的语文能力。
