# 资源生产工作台 UX 规范

文档版本：`v1.5`

生效日期：`2026-08-13`

适用状态：`Accepted`

## 一、适用范围

本文是素材录入、训练任务生产、题目检查、自动发布和资源追溯页面的专属 UX 规范。它吸收既有[素材资源录入平台 UX 校准记录](./MATERIAL_WORKBENCH_UX_CALIBRATION_2026-07-30.md)中的有效结论，并将其提升为后续页面设计和验收的稳定规则。

共享基础遵循[跨平台 UX 基础规范](./CROSS_PLATFORM_UX_FOUNDATION.md)，颜色语义遵循[产品颜色语义规范](./PRODUCT_COLOR_SEMANTICS.md)，字段职责遵循[Authoring Field Contract](./AUTHORING_FIELD_CONTRACT.md)，题目完整生成与定向替换遵循[AI 题目生成质量与定向优化契约](./AI_QUESTION_GENERATION_QUALITY_AND_TARGETED_OPTIMIZATION_CONTRACT.md)。本文不改变 Material、Plan、Draft、Assessment、Review、Freeze 或 Registry 的正式状态。

## 二、体验目标

工作台首先帮助生产者回答四个问题：

1. 我正在处理哪篇材料、哪个任务和哪个版本；
2. 当前处于什么状态，是否有系统阻断或质量提醒；
3. 现在最应该执行什么操作；
4. 执行后会修改什么、保留什么、下一步是什么。

效率不能以隐藏关键证据为代价；追溯不能以把所有技术字段同时铺开为代价。

## 三、信息架构

正式单人生产主线按用户意图组织为：

```text
选择或录入材料
→ 形成训练任务组
→ 生成并判断候选
→ 不满意时由 AI 重新生成
→ 采用并发布
→ 查看正式资源与追溯
```

系统在主线背后自动完成并留痕 Candidate 采用、Revision 创建、Validation / Assessment、Human Review Decision、Freeze、Formal Version 与 Registry 写入。以上领域动作是可追溯的内部编排，不得重新展开为单人模式的连续按钮、页面或重复确认。检查出现阻断或新增人工取舍时，流程才停在当前工作对象上等待用户决定。

内部编排必须保留 `adoption_completed`、Validation、Assessment 和 Publication 的成功或失败结果，以支持断点恢复、幂等重试和错误审计。保留阶段结果不等于新增页面状态：前台仍只投影“正在发布 / 重新生成题目 / 继续发布 / 已发布”等与用户决定直接相关的状态。

页面采用 Material-scoped Workspace：未选材料时只显示材料入口；选定材料后，下游模块只展示该材料的计划、任务、草稿、质量和发布状态。跨材料统计进入资源总览，不混入单素材生产页。

## 四、页面结构模板

```text
宽顶栏：返回 / 页面标题 / 刷新或批次工具
收敛主体：
  材料模式与当前材料
  材料摘要和正文预览
  当前状态与下一步
  训练任务或候选工作区
  质量问题和发布结果
  按需展开的版本与追溯信息
```

- 顶栏最大宽度 `1360px`，主体最大宽度 `1200px`。
- 页面以纵向工作流为主，不为每个区块建立独立卡片外壳。
- 首屏优先显示对象、状态和当前动作；历史与追溯信息折叠到后层。
- 刷新不作为主操作，不与保存、采用或发布竞争。

## 五、信息层级

### 第一层：快速判断

当前材料、任务标题、状态、阻断原因、唯一主要操作。

### 第二层：完成当前工作

能力目标、题目、学生任务、观察目标、候选差异和质量问题说明。标准主线不提供字段级人工编辑。

### 第三层：做出正式决定

材料依据、结构检查、语义 Assessment、同一次采用决定的审计记录与发布影响。

### 第四层：追溯

Revision、版本、哈希、来源关系、Frozen Trace、Registry 和历史记录。默认折叠，但在争议和恢复场景中必须可达。

## 六、操作规范

- 本工作台遵循[跨平台 UX 基础规范的意图驱动流程原则](./CROSS_PLATFORM_UX_FOUNDATION.md#二意图驱动的流程原则)；领域对象数量不得决定页面步骤数量。
- 每个任务卡或工作单元只保留一个当前主操作。
- 用户选择“采用并发布”后，没有新增人工判断的保存、检查、审核记录和发布写入由系统连续完成，不追加“确认采用”“提交审核”或“最终发布”等重复步骤。
- 自动保存、创建 Revision、检查和 Registry 写入可以反馈进度，但不得伪装成需要用户完成的业务里程碑。
- 正常路径只展示一个当前可编辑或待决定对象；Candidate、草稿、Revision 和正式版本不得同时以“当前对象”争夺操作焦点。
- AI 生成、重新生成、优化和直接处理 AI 候选使用紫色 AI 语义。
- 返回和只读追溯使用常规动作语义，不伪装为 AI 操作。
- 绿色只表示检查通过、审核通过、发布成功或服务可用等结果，不用于普通保存或提交。
- 红色用于阻断、失败、删除和停用；黄色用于可继续但需要人工关注的事项。
- 候选采用后由系统自动持久化并检查，不进入人工编辑缓冲。
- 禁用按钮附近必须能理解前置条件；不能只显示灰色不可点。

## 七、任务卡与编辑区

任务卡采用“摘要判断层 + 任务依据层”两级结构：

1. 摘要判断层固定显示任务名称、当前状态、关键标签、完整题目和当前主操作；
2. “查看任务依据”内依次展示能力目标、学生任务、观察目标、评分规则、答案示例和设计依据；
3. Revision、规则版本、生成命令和技术追溯进入只读审计区域，不与业务判断信息并列常驻。

摘要判断层不得因展开详情而隐藏题目；展开只增加依据，不替换卡片原有摘要。标准主线没有题目或任务字段的未保存编辑态；素材录入内容切换前仍必须保护未保存输入。

### 连续批次生产

单篇材料继续以不超过领域上限的少量训练任务为当前工作对象；多篇材料合计形成的 20—30 道题属于跨材料批次，不得把全部题目合并为一个超长单页。

- 工作台使用一句自然语言概括活动材料总数、题目总数、已发布数和剩余待处理数，并使用进度条辅助理解；不得把当前材料序号与全局题目统计并列，避免误解为单篇材料进度。
- 全部完成时直接显示“n 篇材料，共 m 道题，已全部发布”，不再陈列“待处理 0”“需要关注 0”等低信息量指标。具体问题原因继续由对应任务卡说明，不在批次层使用含义模糊的“需要关注”。
- 批次完成进度条固定使用 `6px` 高度，右下方显示“已发布 x/y”；进度条只辅助表达比例，不承载额外状态分类。
- 材料选择列表始终展示全部活动材料，不提供“只显示有待处理的材料”筛选，也不因进度状态自动切换当前材料。材料选项可附加“已完成 / 待处理”只读状态，帮助用户自主选择下一篇。
- 批次统计只读取当前 Shared Store 快照中的规范当前 Plan 与 Active Formal Resource，不得使用当前页面选中的材料、历史记忆 Plan、浏览器内编辑态或候选态覆盖全局数字。任务经过 Plan 修订时，统计必须按 `observationTaskPlanId / taskRevisionRootId / parentObservationTaskPlanId` 血缘匹配既有正式资源，与任务卡“已发布”使用完全相同的口径。切换材料、展开详情和刷新选择状态都不得改变批次统计；只有正式发布关系发生变化时统计才可变化。
- 每篇材料的生产页面只打开该材料的规范当前 Plan。历史 Plan 不通过材料切换自动恢复，只能在独立的历史或审计入口查看，避免任务卡状态与批次统计采用不同版本口径。
- 单题发布成功后，当前卡片原位变为已发布，并自动定位到同一材料的下一道待处理任务；定位只改变滚动与键盘焦点，不自动展开卡片、不触发生成或发布命令。
- 当前活动题目 Revision 已与 Active Formal Resource 对齐时，正式发布事实优先于内存中的旧失败反馈；页面不得在“已发布”标签下继续显示同一次发布链的红色冲突。若红色错误属于尚未发布的新 Revision，则必须把该新 Revision 显示为待处理分支，不得伪装成当前版本已发布。
- 同篇材料已经全部发布时，明确显示“本篇任务已全部发布”；是否切换到下一篇材料继续由用户决定。
- 页面名称应覆盖真实职责，统一使用“素材与题目生产工作台”；标题已经表达完整职责时，不再追加重复辅助说明。

质量问题必须：

- 指明具体对象和字段；
- 区分阻断与提醒；
- 给出“重新生成”或“系统重试”中的唯一下一步动作；
- 内容问题必须转化为下一轮 AI 生成约束，不提供字段级人工修改入口；
- 新候选生成后明确说明旧检查或 Assessment 不得沿用。

### 材料版本升级

- 正文、分段、标点或来源信息需要写回时，页面使用“创建新版材料”，不得用普通保存覆盖当前 Material Version。
- 创建新版前说明影响范围：旧正式题目继续服务到新版本完整发布；新版本会重新建立 Plan、任务和题目关系；历史版本保留可追溯。
- 换版进行中显示一个连续进度，不把 Structure、Anchor、Plan、Assessment、Freeze 或 Link 拆成用户步骤。
- 新链路未完整可用时，工作台和 Learning 继续读取旧活动版本；不得提前把旧版本标记为待处理或让 Learning 进入空状态。
- 切换完成后，材料选择器只把新版本作为当前生产对象；旧版本进入只读历史，不与当前版本同时出现在普通材料列表。
- “已发布”必须同时满足当前活动 Material Version、当前 Plan、当前任务和 Active Formal Resource 的身份一致。旧 Plan 的题目即使仍有历史活动记录，也不得让新版本任务显示已发布。

## 八、AI 候选体验

- 生成前说明作用范围：整组、补充还是单题。
- 生成中保留当前已保存内容，显示可恢复状态。
- 候选与现有内容使用稳定对照结构，不依赖颜色表达差异。
- 单题候选提供选择、采用和重新生成入口；用户不选择候选即表示保留当前正式内容，不额外设置同义的“放弃”按钮。再次生成时，旧的未采用单题候选自动被新结果替代。
- 单题优化必须展示完整候选方案；题干、格式、能力、难度、作答要求、Rubric 和答案接受范围不得拆成需要用户分别保存的编辑步骤。
- 定向优化默认逐题执行；生成候选不改变正式题，只有“采用并发布”成功后才原子切换当前版本。
- 训练任务组候选只提供“采用当前任务方案”和“重新生成任务方案”；再次生成自动替换未采用候选，不增加独立“放弃候选”。
- 整组动作在触发前必须说明影响范围：“生成整组替代方案”只生成候选并保护已发布任务；“生成补充候选”生成一个完整补充组。两者均不得在生成完成时直接修改当前任务组，采用后由系统自动保存 Observation Plan。
- 采用是人工决定；页面不得用“AI 已完成”暗示已经审核或发布。
- Provider 失败不清空已通过候选，不伪造成功，也不静默回退到 mock。

## 九、状态、错误与恢复

| 状态 | 页面责任 |
| --- | --- |
| 未开始 | 说明前置条件和开始入口 |
| 编辑中 | 显示当前对象和未保存状态 |
| 检查中 | 防止重复触发，保留工作内容 |
| 需要关注 | 说明问题、影响和建议动作 |
| 被阻断 | 说明无法继续的原因和解除方式 |
| 已通过 | 说明通过主体和适用版本 |
| 发布失败 | 区分未写入、部分完成和可重试阶段 |
| 已发布 | 提供正式身份、版本和来源追溯 |

恢复后必须回到同一材料、同一任务、同一当前工作对象和可解释状态；不得只恢复文本却丢失对象身份或检查时效。系统必须记录已经成功的内部阶段并从断点继续，前台只提供与用户原意图一致的恢复动作，例如“继续发布”；不得要求用户选择 Revision、重做采用决定或手动管理 Assessment、Freeze、Registry 等事务状态。

## 十、原则落地与反例

| 场景 | 正确交互 | 禁止做法 |
| --- | --- | --- |
| 采用可发布候选 | 一个“采用并发布”主操作，后台完成后续正式化 | 依次要求“保存草稿—提交审核—审核通过—确认发布” |
| 自动质量检查通过 | 更新任务状态并继续确定性编排 | 要求用户点击“确认检查通过” |
| 出现非阻断提醒 | 在采用前展示证据，由采用决定一并留痕 | 用户采用后再要求填写相同决定或第二次确认 |
| 出现阻断问题 | 保留当前对象；内容问题重新生成，技术中断由系统重试 | 要求用户定位字段、手工改题或切换身份处理 |
| 发布中途失败 | 保留 adoption、validation、assessment、publication 的内部阶段结果，并显示唯一“继续发布”动作 | 丢弃已完成阶段，或暴露阶段列表让用户选择重跑 Revision、Assessment 或 Freeze |
| 查看历史 | 从当前对象按需展开只读版本与来源 | 在正常编辑区常驻多个“当前草稿”或版本选择器 |
| 单人生产 | 同一任务卡完成编辑、判断和发布 | 模拟录入员提交给同一个人的审核员账号 |

只有满足以下至少一项，才可以新增独立用户步骤：

1. 出现无法由系统确定的新人工取舍；
2. 高风险或不可逆操作需要用户理解新的影响；
3. 真实多人职责、权限或责任边界要求不同人员分别决定；
4. 法规或审计规则明确要求独立确认。

即使满足条件，也必须说明新增步骤对应的决定、责任人、输入和产出，不能只以“底层有这个状态”为理由。

## 十一、响应式规则

- 桌面端保持主体 `1200px` 内的高密度纵向工作区。
- 笔记本和平板按可用宽度收缩，不产生横向滚动。
- 双列编辑或对照表在空间不足时转为有明确先后顺序的单列。
- 批次侧栏不得压缩核心字段到不可读；空间不足时移到主内容之后。
- 移动端允许完成查看、轻量修改和状态处理，不强求承载长材料与复杂批次生产。
- 驻顶工具栏只能保留当前对象和高频动作，不能把全部按钮固定在屏幕上。

## 十二、推荐与禁止

### 推荐

- “题目依据不足，无法发布。请补充与第 3 段相关的证据要求。”
- 在任务卡内显示当前问题和“定位修改”。
- 已发布任务展开只读正式版本和来源。
- 切换对象前提示未保存内容并允许留在当前页。

### 禁止

- 只显示“检查失败”而不解释原因。
- 同一操作区出现多个同级实心主按钮。
- 用绿色表示“保存草稿”或“提交审核”。
- 把 AI 候选直接标记为“审核通过”。
- 在未选材料时提前铺开空的计划、题目和审核模块。
- 为追求整洁而隐藏发布依据、版本身份或阻断详情。
- 把 Candidate、Revision、Assessment、Review、Freeze 和 Registry 逐个变成用户步骤。
- 用多个“草稿”概念表达技术缓存、候选、当前修订和未发布版本。
- 在单人模式中让用户切换录入者、审核者和发布者身份。

## 十三、验收清单

- [ ] 未选材料时下游生产区保持隐藏；
- [ ] 切换材料后统计、正文、任务和状态同步切换；
- [ ] 首屏能判断当前对象、状态、问题和下一步；
- [ ] 每个工作单元只有一个当前主操作；
- [ ] AI、常规动作、成功、提醒和阻断颜色语义正确；
- [ ] 修改后存在未保存保护，Assessment 失效可见；
- [ ] 质量问题可定位到具体字段；
- [ ] 发布失败可解释、可恢复且不会产生重复正式版本；
- [ ] 已发布资源能够查看版本、来源和冻结追溯；
- [ ] 桌面、笔记本和平板无横向溢出；
- [ ] 页面去除颜色后仍能理解状态和操作；
- [ ] 正式流程没有恢复已废弃的独立审核跳转或平行入口。
- [ ] 正常路径的步骤均能对应明确用户意图或新增人工判断；
- [ ] 自动保存、检查和正式化写入没有被包装为用户里程碑；
- [ ] 前台仅有一个当前工作对象，多版本只在追溯层出现；
- [ ] 发布失败从已完成阶段恢复，用户无需管理内部事务状态；
- [ ] 单人模式没有虚构多人提交、审核或批准流程。
