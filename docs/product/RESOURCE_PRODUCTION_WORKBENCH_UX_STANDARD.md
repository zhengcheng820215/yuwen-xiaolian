# 资源生产工作台 UX 规范

文档版本：`v1.0`

生效日期：`2026-08-12`

适用状态：`Accepted`

## 一、适用范围

本文是素材录入、训练任务生产、题目检查、人工审核、正式发布和资源追溯页面的专属 UX 规范。它吸收既有[素材资源录入平台 UX 校准记录](./MATERIAL_WORKBENCH_UX_CALIBRATION_2026-07-30.md)中的有效结论，并将其提升为后续页面设计和验收的稳定规则。

共享基础遵循[跨平台 UX 基础规范](./CROSS_PLATFORM_UX_FOUNDATION.md)，颜色语义遵循[产品颜色语义规范](./PRODUCT_COLOR_SEMANTICS.md)，字段职责遵循[Authoring Field Contract](./AUTHORING_FIELD_CONTRACT.md)。本文不改变 Material、Plan、Draft、Assessment、Review、Freeze 或 Registry 的正式状态。

## 二、体验目标

工作台首先帮助生产者回答四个问题：

1. 我正在处理哪篇材料、哪个任务和哪个版本；
2. 当前处于什么状态，是否有阻断或提醒；
3. 现在最应该执行什么操作；
4. 执行后会修改什么、保留什么、下一步是什么。

效率不能以隐藏关键证据为代价；追溯不能以把所有技术字段同时铺开为代价。

## 三、信息架构

正式单人生产主线为：

```text
选择或录入材料
→ 形成训练任务组
→ 生成并判断候选
→ 保存当前修订
→ 质量检查与人工决定
→ 正式发布
→ 查看正式资源与追溯
```

页面采用 Material-scoped Workspace：未选材料时只显示材料入口；选定材料后，下游模块只展示该材料的计划、任务、草稿、质量和发布状态。跨材料统计进入资源总览，不混入单素材生产页。

## 四、页面结构模板

```text
宽顶栏：返回 / 页面标题 / 刷新或批次工具
收敛主体：
  材料模式与当前材料
  材料摘要和正文预览
  当前状态与下一步
  训练任务或候选工作区
  质量问题和发布结果
  按需展开的版本与追溯信息
```

- 顶栏最大宽度 `1360px`，主体最大宽度 `1200px`。
- 页面以纵向工作流为主，不为每个区块建立独立卡片外壳。
- 首屏优先显示对象、状态和当前动作；历史与追溯信息折叠到后层。
- 刷新不作为主操作，不与保存、采用或发布竞争。

## 五、信息层级

### 第一层：快速判断

当前材料、任务标题、状态、阻断原因、唯一主要操作。

### 第二层：完成当前工作

能力目标、题目、学生任务、观察目标、候选差异、可编辑字段和质量问题定位。

### 第三层：做出正式决定

材料依据、结构检查、语义 Assessment、人工审核结论、发布影响。

### 第四层：追溯

Revision、版本、哈希、来源关系、Frozen Trace、Registry 和历史记录。默认折叠，但在争议和恢复场景中必须可达。

## 六、操作规范

- 每个任务卡或工作单元只保留一个当前主操作。
- AI 生成、重新生成、优化和直接处理 AI 候选使用紫色 AI 语义。
- 普通保存、提交、定位修改和返回使用常规动作语义，不伪装为 AI 操作。
- 绿色只表示检查通过、审核通过、发布成功或服务可用等结果，不用于普通保存或提交。
- 红色用于阻断、失败、删除和停用；黄色用于可继续但需要人工关注的事项。
- 候选采用后进入普通编辑缓冲，后续保存和检查不再保持紫色。
- 禁用按钮附近必须能理解前置条件；不能只显示灰色不可点。

## 七、任务卡与编辑区

任务卡固定按以下顺序呈现：

1. 能力目标；
2. 题目；
3. 学生任务；
4. 观察目标。

评分规则、答案示例、设计依据和技术追溯默认按需展开。字段修改后应在本任务内显示未保存状态；切换材料、任务或页面前必须保护未保存内容。

质量问题必须：

- 指明具体对象和字段；
- 区分阻断与提醒；
- 给出下一步动作；
- “定位修改”必须落到真实存在且可编辑的字段；
- 修订后明确说明旧检查或 Assessment 是否失效。

## 八、AI 候选体验

- 生成前说明作用范围：整组、补充还是单题。
- 生成中保留当前已保存内容，显示可恢复状态。
- 候选与现有内容使用稳定对照结构，不依赖颜色表达差异。
- 每个候选提供采用、舍弃或重新生成的明确决策。
- 采用是人工决定；页面不得用“AI 已完成”暗示已经审核或发布。
- Provider 失败不清空已通过候选，不伪造成功，也不静默回退到 mock。

## 九、状态、错误与恢复

| 状态 | 页面责任 |
| --- | --- |
| 未开始 | 说明前置条件和开始入口 |
| 编辑中 | 显示当前对象和未保存状态 |
| 检查中 | 防止重复触发，保留工作内容 |
| 需要关注 | 说明问题、影响和建议动作 |
| 被阻断 | 说明无法继续的原因和解除方式 |
| 已通过 | 说明通过主体和适用版本 |
| 发布失败 | 区分未写入、部分完成和可重试阶段 |
| 已发布 | 提供正式身份、版本和来源追溯 |

恢复后必须回到同一材料、同一任务和可解释状态；不得只恢复文本却丢失对象身份或检查时效。

## 十、响应式规则

- 桌面端保持主体 `1200px` 内的高密度纵向工作区。
- 笔记本和平板按可用宽度收缩，不产生横向滚动。
- 双列编辑或对照表在空间不足时转为有明确先后顺序的单列。
- 批次侧栏不得压缩核心字段到不可读；空间不足时移到主内容之后。
- 移动端允许完成查看、轻量修改和状态处理，不强求承载长材料与复杂批次生产。
- 驻顶工具栏只能保留当前对象和高频动作，不能把全部按钮固定在屏幕上。

## 十一、推荐与禁止

### 推荐

- “题目依据不足，无法发布。请补充与第 3 段相关的证据要求。”
- 在任务卡内显示当前问题和“定位修改”。
- 已发布任务展开只读正式版本和来源。
- 切换对象前提示未保存内容并允许留在当前页。

### 禁止

- 只显示“检查失败”而不解释原因。
- 同一操作区出现多个同级实心主按钮。
- 用绿色表示“保存草稿”或“提交审核”。
- 把 AI 候选直接标记为“审核通过”。
- 在未选材料时提前铺开空的计划、题目和审核模块。
- 为追求整洁而隐藏发布依据、版本身份或阻断详情。

## 十二、验收清单

- [ ] 未选材料时下游生产区保持隐藏；
- [ ] 切换材料后统计、正文、任务和状态同步切换；
- [ ] 首屏能判断当前对象、状态、问题和下一步；
- [ ] 每个工作单元只有一个当前主操作；
- [ ] AI、常规动作、成功、提醒和阻断颜色语义正确；
- [ ] 修改后存在未保存保护，Assessment 失效可见；
- [ ] 质量问题可定位到具体字段；
- [ ] 发布失败可解释、可恢复且不会产生重复正式版本；
- [ ] 已发布资源能够查看版本、来源和冻结追溯；
- [ ] 桌面、笔记本和平板无横向溢出；
- [ ] 页面去除颜色后仍能理解状态和操作；
- [ ] 正式流程没有恢复已废弃的独立审核跳转或平行入口。
