# 素材资源录入平台 UX 校准记录

> 2026-08-12 规范说明：本文继续作为历史校准与落地记录。后续资源录入、审核和发布页面的规范性设计与验收，以[资源生产工作台 UX 规范](./RESOURCE_PRODUCTION_WORKBENCH_UX_STANDARD.md)为主；共享基础遵循[跨平台 UX 基础规范](./CROSS_PLATFORM_UX_FOUNDATION.md)。本文中的既有页面证据和校准结论继续有效，但不得覆盖新的平台边界。

## 状态

`IMPLEMENTED / BUILD VERIFIED`

## 目标

本轮校准收敛素材资源录入平台与题目修改平台的信息层级、操作颜色、按钮尺寸、刷新交互和局部间距。调整只影响页面呈现与操作表达，不改变 Material、Observation Plan、Question Draft、Validation、Quality Assessment、Human Review、Freeze 或 Formal Resource 的正式契约。

## 信息层级

1. 顶栏只保留平台名称，删除不能帮助当前操作的副标题。
2. 删除训练任务“发布进度”步骤条。正式状态统一由任务卡子状态与“待发布 / 已发布”互斥统计表达，不再重复展示模拟流程。
3. 当前素材区只展示素材名称、自然段数量与素材级操作。
4. 训练任务标题区域只保留“待发布 / 已发布”两项互斥统计；题目待采用、质量提醒、处理中和发布未完成等原因留在对应任务卡内部。
5. 删除“素材内容”标题，正文直接承接当前素材信息。
6. 删除独立“训练任务检查”和“提交最终确认”模块；质量检查结果、提醒原因和恢复动作就近归入对应任务卡。

## 间距与对齐

1. 主要纵向板块间距收敛为 `24px`。
2. “修改训练任务”标题、资源统计和版本提示之间分别使用 `16px` 间距。
3. 素材选择框到“当前素材”与素材级操作按钮的顶部距离均为 `24px`。
4. 素材名称信息结束到正文首段的距离为 `24px`。
5. 当前素材标题与操作按钮使用同一网格顶部基线；训练任务标题与三个资源统计保持水平居中。
6. 同组操作按钮间距统一为 `8px`，按钮宽度默认由文字和水平内边距决定，不无理由铺满容器。

## 文案与辅助信息

1. 删除适用学段、生成数量、训练方向和训练能力下方重复的辅助说明。
2. 可选规则合并到字段名称：`可选 2 项，默认由 AI 判断`，并使用辅助灰色。
3. 去重提示不再显示容易与当前计划任务数混淆的历史库存计数。
4. 已存在训练任务时统一说明：`再次生成时，系统会参考当前素材已有的训练任务，优先生成不同的训练内容。`
5. 标准生产主链不提供字段级人工编辑；用户只需判断当前方案，选择放弃本轮方案或采用并发布。

## 颜色与按钮

本节只记录素材资源录入平台对全局规范的应用结果。颜色含义、组件状态和跨平台边界的唯一来源为 [产品颜色语义规范](./PRODUCT_COLOR_SEMANTICS.md)；本记录不得另行定义或覆盖颜色语义。

1. AI 生成、重新生成整组任务和补充生成训练任务使用品牌紫语义；采用操作不沿用 AI 紫色，并通过文案明确其人工决策属性。
2. 单任务候选的加载状态和内容对照表使用蓝色信息语义。
3. 候选区最多展示“方案1 / 方案2 / 方案3”三个切换入口，并只允许采用当前查看方案；不提供多选、并排比较或字段级人工编辑入口。
4. “保留原内容”等普通次要操作统一使用白底、浅灰边框和深灰文字，不与生成或采用动作争夺主次；AI 次操作、危险操作和状态按钮继续遵循各自颜色语义。
5. 所有独立刷新入口统一使用 `RefreshIconButton`：`40px × 40px`、浅灰边框、白底、蓝色 Focus Ring，并统一采用 Lucide `RefreshCcw` 图标。
6. 紫色只用于 AI 生成、重新生成和补充生成；“采用并发布”是人工决策，使用常规蓝色主操作；“放弃本轮方案”使用白底浅灰边框的中性次操作。
7. 正常路径不得常驻“提交题目人工审核”“提交最终确认”“发布任务”或“发布已确认题目”等按钮。绿色只保留给检查通过、发布成功和已发布等结果状态。

### 刷新反馈规范

1. 用户点击刷新入口后，`RefreshCcw` 图标立即执行一次快速逆时针整圈旋转；标准时长为 `280ms`，使用 `ease-out`。
2. 单圈动画只表达“点击已被接收”，不得与请求持续时间绑定；请求期间仍通过按钮禁用状态和可访问名称表达处理中，避免重复提交。
3. 每次有效点击只触发一圈动画。页面初次渲染不得自动旋转，刷新完成后也不得追加第二圈。
4. 普通数据刷新成功不显示成功 Toast，刷新后的数据变化即为反馈；刷新失败继续使用现有错误提示，避免静默失败。
5. 保存、删除、停用、重新启用等会改变持久业务状态的操作，仍可按各自契约显示成功或失败反馈，不与普通刷新规则混用。
6. 系统启用“减少动态效果”时，旋转动画必须压缩到近似即时完成，不得影响刷新命令本身。

## 验收边界

- 页面刷新不会改变当前正式资源语义。
- 素材资源录入、题目修改与审核平台的独立刷新入口必须使用同一个 `RefreshIconButton` 和 `RefreshCcw` 图标。
- 点击刷新后应立即完成一次快速逆时针整圈动画；动画结束不得等待网络请求，网络请求结束也不得重复播放。
- 普通刷新成功后不得出现成功 Toast；刷新失败必须保留明确错误反馈。
- 展开或收起素材正文不会修改 Material。
- 移动统计位置不会改变 Repository 计数口径。
- 删除辅助文案不会放宽生成、保存、审核或发布门禁。
- 重新生成候选仍需人工采用，采用前不创建新版本。
- 已有素材被选中后直接显示对应训练任务编辑区，不再要求用户额外执行展开操作；从审核平台返回时仍应定位到对应素材和编辑区。
- AI 生成、优化、重新生成、候选采用和 AI 预览校准入口保持紫色；普通保存、检查、提交、返回和删除入口不得使用 AI 紫色样式。
- 普通保存、提交和返回入口不得使用绿色操作样式，绿色只表达已完成的正向结果。
- Production Build 必须通过；现有 Bundle Size Warning 属于非阻断项。

## 跨平台页面身份加载

从素材资源录入平台打开题目修改、审核恢复或已发布题目时，目标平台必须先解析 Draft、Review、Freeze 与 Formal Resource 状态，再呈现对应页面身份。

1. 状态尚未解析时只显示中性的“正在载入题目”状态。
2. 加载期间不得先渲染“题目修改与提交平台”等默认业务身份。
3. 加载期间不得暴露编辑、审核、冻结或发布操作。
4. 已发布题目应在解析完成后直接进入“已发布题目”，不得产生看似重新审核或重新发布的视觉跳转。
5. 该加载门禁只影响页面呈现，不推进或回退任何正式生命周期状态。

## 本轮工程同步与验收

1. 训练任务生成操作统一命名为“重新生成整组任务”和“生成更多任务”，区分替换整组与增量补充两种动作。
2. 题目平台新增工作区加载门禁；Draft、Review、Freeze 与 Formal Resource 状态解析完成前，不渲染业务页面身份和正式操作。
3. 页面状态加载失败时显示中性失败页，不默认回退到题目修改状态。
4. 展示状态专项 Debug 共 `21/21` 项通过。
5. Production Build 通过；现有动态导入与 Bundle Size Warning 仍为非阻断项。

## 题目检查 Loading 校准

### 问题记录

题目修改与提交页面执行`继续完成检查`时，按钮只进入静态禁用态，没有进行中图标和文案。该表现
无法区分“请求已经开始”与“按钮因其他门禁不可用”，容易诱发重复点击或误判页面卡死。

### 修复结果

1. 题目检查增加独立的`validationBusy`状态，不与页面其他异步操作共用模糊的全局禁用表现。
2. 检查期间按钮保持蓝色执行样式，显示旋转图标。
3. 首次检查显示`正在检查题目`；补齐完整质量记录时显示`正在完成检查`。
4. 检查期间继续禁用按钮以阻止重复命令，但通过`aria-busy`和等待光标明确表达正在处理。
5. 检查成功或失败后统一结束 Loading；失败时保留原错误提示并恢复重试能力。
6. 按钮尺寸保持稳定，Loading 切换不造成布局跳动。

### 回归结论

- Production Build 通过。
- 题目工作台 Command E2E `7/7` 通过。
- 题目工作流投影专项通过。
- 后续所有保存、检查、提交和发布类异步主操作均应复用“显式 Loading + 防重复触发 +
  完成后恢复”的规则，不得退化为只有静态禁用态。

## 异步主命令反馈统一

### 问题记录

保存、提交最终确认、审核、退回和发布等按钮此前只共享页面级 `busy` 状态。请求发出后按钮虽然
不可再次点击，但没有当前动作的 Loading 图标和进行中文案；同时状态切换还要等待领域命令与
页面刷新完成，用户容易误判点击无效或页面卡顿。

### 规范与修复结果

1. 页面使用独立命令身份记录当前执行动作，不再仅依赖模糊的全局 `busy` 推导按钮表现。
2. 保存、提交最终确认、撤回、退回、审核通过、发布和发布重试均显示各自的旋转图标与进行中
   文案。
3. 只有当前按钮显示 Loading；同组其他互斥按钮仅暂时禁用，不显示错误的并行执行状态。
4. 命令触发前设置同步执行锁，避免 React 禁用态尚未渲染时的快速双击产生重复请求。
5. 命令成功、失败、异常和后续刷新失败都会释放执行锁并结束 Loading。
6. 命令成功但刷新失败时明确提示刷新恢复，不把成功命令误报为失败。
7. 该规则已经写入
   `QUESTION_REVIEW_AND_PUBLICATION_WORKFLOW_CONTRACT.md` 的“全局异步主命令反馈规范”，后续
   新增异步主操作必须直接复用，不得另建只有静态禁用态的交互。

### 回归结论

- Production Build 通过。
- 题目工作台 Command E2E `7/7` 通过。
- 保存、检查、提交、审核与发布的重复触发继续保持幂等。

## 完整检查原地循环修复

### 问题记录

题目已经形成完整质量检查记录后，点击`继续完成检查`仍返回“结构检查通过，完整检查未完成”，
按钮结束 Loading 后再次显示原文案。该问题不是题目内容污染，而是同一 Revision 下存在多条
确定性检查记录时，恢复逻辑选中了较新的孤立记录，遮蔽了已经完成的语义检查与 Bundle。

### 修复结果

1. 当前检查上下文改为遍历同一 Revision、Validation 和规则版本下的全部持久化链。
2. 已完成语义检查且 Bundle 可用的完整链优先于较新的孤立或失败记录。
3. 页面和批次摘要恢复到完整链时，不再无条件生成新的确定性检查记录。
4. `semantic_unavailable` 只作为失败记录展示，不再被当作成功幂等结果；再次点击会重试。
5. 已审核或已发布题目在正式字段未变化时，不会因同批其他题变化退回检查阶段。
6. 增加专项回归，覆盖“完整链优先”和“失败链允许重试”。
7. API 增加唯一的 `qualityCheckState` 投影；页面不再从确定性检查、语义检查和 Bundle 三组字段
   分别拼装完成态。
8. 完整检查命令必须在确认完整链已经持久化后才返回成功；部分结果会有限重试，仍未完成时返回
   明确的可重试错误，避免 Loading 结束后原地循环。

## 最终确认无响应与语义检查记录错选修复

### 问题记录

页面已经显示“全部质量检查通过”和“当前题目已完成检查，等待最终确认”，点击`提交最终确认`
后却停留在原页面，并返回：

```text
Current semantic assessment result is required.
```

该问题不是按钮未绑定，也不是题目内容污染。根因是页面恢复和提交 Command 使用了两套检查记录
选择规则：

1. 页面会在同一 Revision 的全部记录中选择完整的确定性检查、语义检查与 Bundle；
2. 提交 Command 只读取时间最新的确定性检查，再查找它对应的语义结果；
3. 当一次重试只写入新的确定性检查时，该孤立记录遮蔽了较早但完整的检查链；
4. 因此页面判断“可提交”，Command 却判断“缺少语义检查”。

### 修复结果

1. 页面与提交 Command 统一复用完整检查上下文选择器；
2. 选择器遍历当前 Revision 的全部匹配记录，优先采用
   `Deterministic + completed Semantic + usable Bundle`；
3. 较新的孤立或失败重试记录不再遮蔽完整链；
4. `pending_review`、`reviewed` 状态的重复提交先走幂等恢复，不再被旧前置检查误拦截；
5. 主操作增加同步执行锁，避免快速双击并发提交；
6. 领域命令成功后的刷新失败与命令失败分开反馈，不再把“提交成功、刷新失败”显示成提交失败；
7. 内部英文错误保留在折叠技术信息中，首层继续展示可执行的中文恢复提示。

### 防回归规则

1. 页面状态、主按钮、批次统计和提交门禁必须消费同一检查上下文；
2. 新增检查重试记录时，必须覆盖“新孤立记录 + 旧完整链”的恢复场景；
3. 重复提交最终确认不得新增审核记录；
4. 提交成功但刷新失败后，刷新页面必须恢复到已提交状态；
5. 不得仅以最新 `createdAt` 决定当前完整检查事实。

### 自动化证据

- 质量持久化专项：`25 / 25 PASS`；
- 题目工作台 Command E2E：`7 / 7 PASS`；
- Production Build：PASS。

## 正式资源默认信息层级（2026-08-04）

“正式资源”只展示用户完成判断与后续使用时必须知道的信息：发布状态、可读版本、使用状态、来源素材和真实发布时间。原始资源 ID、版本 ID、来源草稿 ID、素材版本 ID 等工程追溯字段不进入生产界面，只保留在数据层、日志与管理员诊断链路。

1. 用户界面使用“第 N 版”“可用于学习”“来源素材”“发布时间”等业务语言，不直接用原始 ID 代替可读版本；
2. 默认层不展示 `Draft`、`Material Version` 等中英混排的 Schema 名称；
3. 工程标识继续保留完整可追溯能力，但不得在普通用户界面提供查看或复制入口；
4. 排障、工单或跨系统查询统一通过开发日志、管理员诊断页或错误详情获取工程标识；
5. 本调整只改变信息层级，不修改 Formal Version、Registry、材料关联或学习入口的读取语义。

## 任务卡折叠区顺序与人工校准展开规则（2026-08-04）

训练任务卡的二级信息固定按操作优先级排列：

1. 调整任务属性；
2. 评分标准与答案示例；
3. 设计依据；
4. 正式资源（仅在已经形成正式资源时展示）。

预览状态下四项默认全部收起，避免低频信息挤占题目、学生任务和观察目标。点击“人工编辑校准”后，仅自动展开“调整任务属性”和“评分标准与答案示例”，使最常用的校准字段直接可见；“设计依据”和“正式资源”继续保持收起。

展开状态必须按任务独立保存。用户进入人工校准后手动收起任一项时，页面不得再次强制展开；切换其他任务不得串用当前任务的展开状态。退出人工校准后，该任务四项恢复为默认收起。以上规则只控制任务卡展示，不得创建 Revision、改变检查结论或推进审核与发布状态。

## 单任务卡工作进度保存交互（2026-08-04）

单任务卡增加保存能力是合理的，但其职责只限于防止人工校准内容丢失，不承担版本提交。人工编辑校准状态下，操作区固定提供：

- 主按钮：保存当前任务；
- 次按钮：退出人工校准；
- 无修改时：当前任务已保存；
- 保存中：正在保存当前任务…；
- 保存成功：工作进度已保存，尚未提交检查；
- 保存失败：保存失败，可重新保存。

按钮位置、宽度和高度在进入与退出校准时保持稳定，状态切换不得造成任务卡抖动。只有当前保存按钮显示 Loading，同组其他互斥操作只进入禁用态。

单卡保存后，任务卡可以折叠，卡片首层仍需保留“当前修改尚未检查”或“工作进度已保存”的状态反馈。用户切换任务、素材或页面时，如果当前任务仍有未保存内容，必须提供“保存后切换”“放弃修改”“取消”三项明确选择。

单卡保存不得：

1. 创建 Question Revision；
2. 执行质量检查；
3. 创建或改变 Human Review；
4. 覆盖 Formal Version；
5. 写入 Registry；
6. 清空其他任务的检查或确认记录。

正式提交提供两种同级语义：任务卡内使用“提交当前任务并检查”，页面底部使用“提交全部已保存修改”。两者比较工作内容与基础 Revision，并复用同一提交编排；前者不得被其他未完成任务阻塞，后者仅是批量便利入口。提交只为发生真实变化的任务分别创建一个 Question Revision，多任务提交形成一次包含完整任务 Revision 引用的 Task Group Submission，未修改任务不得升版。

Revision 创建失败时，失败任务保留工作进度并允许重试；已经创建 Revision 但 Assessment 失败时，工作进度已完成提交，页面应进入“检查未完成”而不是“尚未提交修改”。重试检查不得重复创建 Revision。多任务提交只要仍有 Revision 创建失败，就不得提前执行任务组覆盖检查。

本功能的验收重点是：刷新恢复、单卡隔离、保存失败不丢内容、重复保存不堆积 Revision、整组提交不产生空 Revision，以及已发布任务修改时旧正式资源继续可用。
