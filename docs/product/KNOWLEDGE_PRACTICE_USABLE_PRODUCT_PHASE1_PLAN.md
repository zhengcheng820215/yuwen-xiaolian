## 二、现状基线

### 2.1 当前内容规模

截至本文建立时，学生侧轻量练习数据具有以下基线：

- `src/data/questions.json` 共 27 道知识题；
- 8 个知识分类中，7 个分类各 3 道题，1 个分类 6 道题；
- 题型分布为 15 道单选题、8 道判断题、4 道填空题；
- `src/data/readings.json` 仅有 2 篇阅读材料；
- 知识练习题目直接由页面导入静态 JSON，没有正式 Repository 边界。

本阶段只处理知识练习链路。阅读、文言阅读开放作答和作文反馈不在本阶段范围内。

### 2.2 当前运行链路

现有知识练习链路为：

```text
选择分类或综合练习
→ 页面加载该范围内全部题目
→ 按 JSON 固定顺序逐题作答
→ 展示对错、正确答案、知识点和统一解析
→ 完成后展示正确题数、正确率、估算用时和错题数
→ 再练一次 / 查看错题 / 返回首页
```

### 2.3 已确认问题

1. **练习容量不足**：专项通常只有 3 题，用户一轮即可刷完；综合练习直接暴露全部 27 题。
2. **题目顺序固定**：再次进入仍按原顺序练习，没有会话级抽题、轮换或近期去重。
3. **反馈没有对应错误选择**：错误反馈只给正确答案和通用解析，不能说明学生当前选择为什么不成立。
4. **结果只有汇总数字**：不能按知识点或错误类型解释本轮表现。
5. **推荐缺少依据**：结果页只根据是否存在错题输出通用建议。
6. **状态只在内存中**：刷新页面或关闭后，当前练习、作答记录和结果可能丢失。
7. **计分口径错误**：当前 `score = correct * 10`，题目数量不是 10 时不构成百分制。
8. **用时不是实测**：当前用时由题目数量估算，不能反映真实练习时长。
9. **页面承担过多职责**：抽题、判题、记录、统计和展示集中在 `Quiz.jsx`，难以稳定扩展。
10. **缺少内容质量门禁**：静态题目没有统一结构校验，不能保证答案、选项解析、错因和变式关系完整。

## 三、阶段定位

### 3.1 产品定位

知识练习是正式能力成长主链的辅助入口，承担以下职责：

- 提供低负担的基础知识练习；
- 对本轮客观作答给出可解释反馈；
- 帮助学生立即纠正具体知识性错误；
- 记录可供后续练习轮换使用的本地历史；
- 给出基于本轮表现的短期巩固建议。

知识练习不替代正式 `/learning` 链路，不直接生成正式 Diagnosis、Ability Evidence、Student Ability Profile 或长期成长结论。

### 3.2 阶段目标

第一阶段完成以下最小可用闭环：

```text
选择练习目标
→ 创建稳定的 5 / 10 题练习会话
→ 逐题作答并获得选项级反馈
→ 错题在条件满足时触发一次变式巩固
→ 刷新或退出后恢复当前进度
→ 完成后查看本轮知识点与错因摘要
→ 开始有依据的下一组专项练习
```

### 3.3 产品结果

阶段完成后，学生应能感受到：

- 每次练习长度清晰，不需要一次做完某分类全部题目；
- 再次练习时题目和顺序会合理轮换；
- 答错后能知道当前选择为什么错，以及下次该如何判断；
- 一道错题可以连接到一题真正相关的巩固题；
- 中断后可以继续，不必从头开始；
- 结果页能说明本轮具体哪里需要巩固，而不仅是给出分数。

## 四、范围与非目标

### 4.1 本阶段范围

1. 现有知识题数据结构升级与自动校验；
2. 专项 5 题、综合 10 题的会话级选题；
3. 近期降权、会话内去重、变式组排重和难度基本配比；
4. 单选、判断、填空题的稳定判题；
5. 选项级反馈、错因提示和解题步骤；
6. 每道原题最多触发一次变式巩固；
7. 当前会话、题目历史、错题和结果的浏览器本地持久化；
8. 真实计时和统一统计；
9. 结果页知识点摘要、错因摘要与下一步专项入口；
10. 数据层、领域层、组件层拆分；
11. 自动化测试与浏览器主链验收。

### 4.2 本阶段非目标

本阶段明确不做：

- 不扩展现代文阅读、文言文开放作答或作文训练；
- 不调用大模型自由生成反馈；
- 不建立正式能力诊断、Evidence 或长期能力画像；
- 不把一次答对称为“已经掌握”；
- 不接入账户、云同步或多端同步；
- 不新建第二套正式资源审核与发布系统；
- 不把静态知识题直接升级为正式 `/learning` Frozen Resource；
- 不一次性生产 300—500 道正式题目；
- 不增加排行榜、经验值、连续签到等激励系统；
- 不在第一阶段处理学校、班级或教师管理。

### 4.3 内容扩充边界

为支持变式巩固和基础轮换，本阶段允许继续扩充轻量知识题，但 `60—100` 只保留为内容建设估算，不构成固定产品门禁。最终题量由知识点覆盖、独立基础题、已审核变式关系及连续 5 / 10 次练习的重复率和枯竭率倒推。

新增题目必须通过本文定义的数据校验和人工内容核对。不得为了达到数量目标复制题目、机械替换名词或生成无真实干扰性的选项。

## 五、核心术语与结论边界

| 术语 | 定义 | 可否在本阶段输出 |
| --- | --- | --- |
| 本轮答对 | 当前题首次作答正确 | 可以 |
| 本轮需巩固 | 本轮同知识点出现错误或巩固题仍答错 | 可以 |
| 本轮表现较稳 | 同一知识点有至少 2 道独立原题且全部首次答对 | 可以，必须带“本轮” |
| 证据不足 | 某知识点只有 0—1 道有效原题 | 可以 |
| 初步掌握 | 跨会话、间隔复练后仍稳定正确 | 第一阶段结果页不输出 |
| 已掌握 | 经过正式、多次、可迁移证据支持的长期判断 | 禁止 |
| 能力提升 | 正式成长链基于多次 Evidence 的结论 | 禁止 |
| 错因 | 由题目错误选项预先标注的知识性偏差 | 可以，不等同根因诊断 |

页面文案必须区分“预设错因提示”和“系统已经识别学生长期根因”。第一阶段只能表达：

> 这个选项通常反映出……；本题建议重点检查……

不得表达：

> 系统已诊断你缺乏某项能力；你已经形成某种长期思维问题。

## 六、目标用户流程

### 6.1 新建专项练习

```text
进入知识练习
→ 查看分类、每组题数和预计时长
→ 选择一个分类
→ 系统创建 5 题会话
→ 进入第 1 题
```

如果分类内可用题少于 5 道，系统使用全部可用题并明确展示实际题数，不得重复题目凑满 5 道。

### 6.2 新建综合练习

```text
进入知识练习
→ 选择综合练习
→ 系统创建最多 10 题会话
→ 尽可能覆盖至少 3 个分类
→ 进入第 1 题
```

### 6.3 作答与反馈

```text
展示题目
→ 学生提交答案
→ 系统原子记录作答
→ 展示本题结果与针对性反馈
→ 学生主动进入下一题
```

提交后不得自动跳题。反馈出现后，原答案不可在当前 attempt 中修改。

### 6.4 错题巩固

```text
原题首次答错
→ 查找同一 variantGroupId 的未使用变式题
→ 满足条件时将 1 道巩固题加入会话队列
→ 学生完成巩固题
→ 记录巩固结果但不改写原题首次正确率
```

### 6.5 中断恢复

```text
练习进行中
→ 每次有效状态变化立即保存
→ 页面刷新 / 关闭 / 重新进入
→ 发现未完成会话
→ 提供“继续上次练习”或“放弃并新建”
```

不得在用户未确认时用新会话覆盖未完成会话。

### 6.6 完成与下一步

```text
完成最后一题
→ 关闭会话并生成不可变结果摘要
→ 展示本轮表现、知识点摘要和错因摘要
→ 提供重做错题 / 专项巩固 / 返回入口
```

## 七、数据契约

### 7.1 Question

建议将 JSON 数据映射为以下领域类型。字段名可在工程实施时保持与现有数据兼容，但语义不得改变。

```ts
type QuestionType = 'single_choice' | 'true_false' | 'fill_blank';
type DifficultyLevel = 1 | 2 | 3;

type Question = {
  id: string;
  category: string;
  subCategory?: string;
  type: QuestionType;
  stem: string;
  options?: Array<{
    id: string;
    text: string;
  }>;
  correctAnswer: string;
  acceptedAnswers?: string[];
  knowledgePoint: string;
  examPoint?: string;
  grade: string;
  semester?: string;
  difficulty: DifficultyLevel;
  sourceText?: string;
  explanation: string;
  answerAnalysis?: Record<string, string>;
  misconceptionByAnswer?: Record<string, {
    code: string;
    studentMessage: string;
  }>;
  solutionSteps: string[];
  variantGroupId?: string;
  contentStatus: 'draft' | 'approved' | 'retired';
  contentVersion: number;
};
```

规则：

- 页面只消费 `approved` 题目；
- `id` 在整个轻量题库中唯一且发布后不复用；
- 单选和判断题必须有稳定选项 ID，不再依赖选项文字首字符判题；
- `correctAnswer` 必须引用有效选项 ID；
- 错误选项应尽量具有独立 `answerAnalysis`；
- `misconceptionByAnswer` 是内容标注，不是运行时 AI 诊断；
- 填空题可通过 `acceptedAnswers` 声明多个明确等价答案；
- `variantGroupId` 只表示训练目标相同，不表示题目可以互相替代为同一道题。

### 7.2 PracticeSession

```ts
type PracticeSession = {
  schemaVersion: 1;
  id: string;
  mode: 'category' | 'mixed' | 'mistake_review';
  category?: string;
  seed: string;
  baseQuestionIds: string[];
  queue: PracticeQueueItem[];
  currentIndex: number;
  responses: PracticeResponse[];
  reinforcementLinks: ReinforcementLink[];
  status: 'active' | 'completed' | 'abandoned';
  startedAt: string;
  updatedAt: string;
  completedAt?: string;
};
```

`baseQuestionIds` 只包含创建会话时的原始题。动态插入的巩固题只能进入 `queue`，不得回写 `baseQuestionIds`。

### 7.3 PracticeQueueItem

```ts
type PracticeQueueItem = {
  questionId: string;
  role: 'base' | 'reinforcement';
  sourceQuestionId?: string;
  status: 'pending' | 'answered';
};
```

### 7.4 PracticeResponse

```ts
type PracticeResponse = {
  id: string;
  sessionId: string;
  questionId: string;
  role: 'base' | 'reinforcement';
  sourceQuestionId?: string;
  submittedAnswer: string;
  normalizedAnswer: string;
  correctAnswer: string;
  isCorrect: boolean;
  knowledgePoint: string;
  misconceptionCode?: string;
  durationMs: number;
  answeredAt: string;
  questionContentVersion: number;
};
```

每个会话中的每个队列项只能生成一条有效 Response。重复点击、浏览器重放或组件重复渲染不得创建重复记录。

### 7.5 ReinforcementLink

```ts
type ReinforcementLink = {
  sourceQuestionId: string;
  reinforcementQuestionId: string;
  triggerResponseId: string;
  result?: 'correct' | 'incorrect';
};
```

### 7.6 PracticeResult

```ts
type PracticeResult = {
  schemaVersion: 1;
  sessionId: string;
  mode: PracticeSession['mode'];
  category?: string;
  baseQuestionCount: number;
  reinforcementQuestionCount: number;
  firstAttemptCorrectCount: number;
  firstAttemptAccuracy: number;
  reinforcementCorrectCount: number;
  durationMs: number;
  knowledgePointSummaries: KnowledgePointSummary[];
  misconceptionSummaries: MisconceptionSummary[];
  completedAt: string;
};
```

结果对象在会话完成时生成，结果页优先读取该不可变摘要，不在每次渲染时用可变题库重新计算历史结果。

## 八、题目数据迁移与质量门禁

### 8.1 迁移策略

现有 27 道题按以下方式迁移：

1. 保留原 `id`；
2. 将中文题型映射为稳定枚举；
3. 把选项拆成稳定 `id + text`；
4. 将现有答案字母映射为选项 ID；
5. 将“基础 / 中等 / 较难”映射为 `1 / 2 / 3`；
6. 补充 `solutionSteps`；
7. 对单选和判断题补充选项级解释；
8. 对可以形成真实巩固关系的题目建立 `variantGroupId`；
9. 人工确认后标记 `approved`；
10. 不满足标准的题目保留为 `draft` 或移出学生可用集合。

### 8.2 自动校验

至少校验：

- ID 唯一；
- 必填字段存在且非空；
- 枚举值合法；
- 单选 / 判断题选项数量合法且选项 ID 唯一；
- 正确答案存在于选项中；
- 所有错误选项至少有解释或明确的通用降级解释；
- 填空题至少有一个可接受答案；
- `variantGroupId` 组内不存在重复 ID；
- 同组题目知识点一致或具有显式兼容声明；
- 已停用题不能被新会话选中；
- 发布内容版本为正整数。

校验失败必须阻断构建或专项数据检查命令，不得仅在控制台警告后继续上线。

### 8.3 人工内容核对

自动校验不能替代内容核对。每道新增或迁移题至少确认：

- 题干无歧义；
- 正确答案唯一或接受答案边界明确；
- 干扰项具有合理迷惑性；
- 选项解析与当前选项一一对应；
- 错因提示不夸大、不贴长期标签；
- 解题步骤对下一道题具有迁移价值；
- 适配声明的年级和难度；
- 变式题不是原题的机械改写。

## 九、练习组生成规则

### 9.1 通用原则

- 选题必须是纯领域逻辑，可独立测试；
- 新会话创建后题目集合和顺序固定；
- 同一会话刷新后不得重新随机；
- 新会话使用新 seed；
- 不以重复题凑满目标数量；
- 不选用 `draft` 或 `retired` 题目。

### 9.2 专项练习

目标为 5 道原题：

1. 仅选择指定分类；
2. 同一 `variantGroupId` 在基础题集合中最多 1 道；
3. 最近两个已完成会话出现过的题目降低优先级；
4. 可用题充足时，难度目标为 `2 基础 + 2 中等 + 1 较难`；
5. 难度不足时按相邻难度补位；
6. 可用题少于 5 道时返回实际可用数量；
7. 可用题为 0 时阻止创建并返回可理解的空状态。

### 9.3 综合练习

目标为 10 道原题：

1. 可用时覆盖至少 3 个分类；
2. 单个分类不应超过基础题集合的 40%；
3. 有历史时优先包含本轮需巩固知识点；
4. 没有历史时尽量均衡覆盖分类；
5. 同一变式组在基础题集合中最多 1 道；
6. 最近题目降权但不永久排除；
7. 全库不足 10 道时使用所有符合条件题目且不重复。

### 9.4 近期降权

第一阶段采用简单、可解释规则：

- 当前未完成会话已出现：严格排除；
- 最近 1 个已完成会话出现：最高降权；
- 最近第 2 个已完成会话出现：中等降权；
- 更早出现：恢复普通候选权重；
- 当候选不足时，允许按“更早 → 最近第 2 个 → 最近第 1 个”顺序逐步放宽。

页面不承诺“绝不重复”，只承诺“优先减少近期重复”。

## 十、判题规则

### 10.1 单选与判断

- 使用稳定选项 ID 精确匹配；
- 不再使用 `option[0]` 截取答案；
- 提交前必须存在有效选择；
- 提交成功后锁定本题；
- 重复提交返回原 Response，不创建第二条记录。

### 10.2 填空题

第一阶段只支持明确答案型填空：

- 去除首尾空白；
- 将连续空白归一化；
- 可配置是否忽略中文、英文标点差异；
- 与 `acceptedAnswers` 中任一规范化答案匹配即为正确；
- 不进行语义相似度、大模型判断或模糊猜测；
- 开放表达题不得伪装成填空题进入本链路。

### 10.3 无效输入

- 空字符串不可提交；
- 只包含空白或标点的填空答案不可提交；
- 无效选项 ID 不可提交；
- 题目已停用但存在于已开始会话时，允许使用会话保存的内容版本继续完成；如无法恢复内容快照，则明确终止并保留已有记录。

## 十一、逐题反馈契约

### 11.1 反馈结构

反馈最多包含四层：

1. **本题结果**：答对或答错；
2. **当前选择解释**：学生所选答案为什么成立或不成立；
3. **关键依据**：正确答案成立的知识或语境依据；
4. **下次方法**：1—3 个可执行解题步骤。

### 11.2 答对反馈

答对时优先简洁，示例结构：

```text
回答正确
关键在于“夸夸其谈”带有贬义，与赞扬回答准确的语境冲突。
本题考查：成语感情色彩。
```

不得因为单题答对显示“你已掌握该知识点”。

### 11.3 答错反馈

答错时必须针对提交选项，示例结构：

```text
这道题需要重点检查成语的感情色彩

你选择了 A：……，这个选项为什么不成立。
正确答案是 C：……，关键依据是什么。

下次按这三步判断：
1. 理解词义；
2. 判断褒贬；
3. 核对语境。
```

如果题目缺少当前错误选项的独立解释，应使用明确的内容降级文案并记录内容缺口，不得由页面临时编造错因。

### 11.4 反馈文案边界

禁止：

- 人格判断；
- 长期能力标签；
- 没有证据的根因断言；
- 仅重复“答案错误”；
- 用内部字段、错误码或数据状态直接面向学生；
- 为了显得智能而输出不稳定的长篇解释。

## 十二、错题即时巩固规则

### 12.1 触发条件

同时满足以下条件才触发：

- 当前为基础题而非巩固题；
- 首次作答错误；
- 题目存在 `variantGroupId`；
- 同组存在另一道 `approved` 题目；
- 候选题未在当前会话中出现；
- 当前原题尚未触发过巩固题。

### 12.2 插入规则

- 默认插入到当前题之后第 1—2 个位置，避免立即机械模仿答案；
- 会话剩余题较少时可插入末尾；
- 每道原题最多 1 道巩固题；
- 每个会话动态巩固题上限为 3 道；
- 巩固题答错不得继续递归插题；
- 找不到合适题目时只保留错因提示，不以无关题替代。

### 12.3 统计规则

- 原题首次正确率只统计 `base` 题；
- 巩固题单独统计；
- 巩固题答对不改写原题为正确；
- 结果页可以表达“完成 2 道巩固题，其中 1 道答对”；
- 不得表达“通过一题巩固已经掌握”。

## 十三、持久化与恢复

### 13.1 第一阶段存储边界

第一阶段使用浏览器本地存储，不接入账户和服务端。建议通过统一 Repository 管理以下逻辑键：

```text
chinese-learning.practice.active-session
chinese-learning.practice.session-history
chinese-learning.practice.question-history
chinese-learning.practice.mistakes
chinese-learning.practice.last-result
```

具体物理键可在实现时统一加版本前缀，但不得由各页面自行定义。

### 13.2 保存时机

以下状态变化后立即保存：

- 会话创建；
- 答案提交成功；
- 巩固题插入；
- 当前题推进；
- 会话完成；
- 会话放弃；
- 错题状态更新。

### 13.3 恢复规则

- 进入知识练习入口时检查未完成会话；
- 存在未完成会话时优先展示“继续上次练习”；
- 用户可以显式放弃并新建；
- 已作答题恢复后保持锁定和反馈可见；
- 当前题未作答时恢复输入草稿属于可选增强，不是第一阶段 PASS 条件；
- 已完成会话不得恢复为 active；
- 结果页刷新后仍能读取最后一次完成结果。

### 13.4 数据版本与损坏降级

- 所有持久化根对象必须包含 `schemaVersion`；
- 读取时进行结构校验；
- 可迁移版本执行显式迁移；
- 无法迁移或损坏的数据隔离为不可用，不得导致应用白屏；
- 清理损坏记录时保留可恢复的其他独立记录；
- 页面使用可理解文案说明“上次练习记录无法恢复，可以开始新练习”。

## 十四、统计与结果页口径

### 14.1 基础指标

```ts
firstAttemptAccuracy = baseQuestionCount === 0
  ? 0
  : Math.round(firstAttemptCorrectCount / baseQuestionCount * 100);
```

结果页不再使用 `correct * 10`。如展示“本次得分”，其值等于首次作答正确率；更推荐直接使用“首次正确率”，避免把轻量练习包装为正式考试。

### 14.2 用时

- 使用会话真实开始、完成和题目作答时间；
- 页面隐藏或长时间离开时，应避免把全部后台停留时间当作有效思考时间；
- 第一阶段可采用单题最大计时上限，例如 10 分钟，超出部分不进入有效作答时长；
- 展示按分钟或“X 分 Y 秒”格式化的真实累计时长。

### 14.3 知识点摘要

按基础题聚合：

| 条件 | 学生表达 |
| --- | --- |
| 0—1 道基础题 | 本轮证据较少 |
| 至少 2 道且全部首次答对 | 本轮表现较稳 |
| 出现 1 次错误 | 本轮建议巩固 |
| 出现至少 2 次错误 | 本轮优先巩固 |

巩固题结果可以作为辅助信息展示，但不得改变基础题首次表现口径。

### 14.4 错因摘要

- 仅聚合内容中预先定义的 `misconceptionCode`；
- 展示学生可理解的短文案，不展示内部 code；
- 按出现次数降序排列；
- 同次数时按首次出现顺序；
- 没有结构化错因时展示具体错题，不生成推测性错因。

### 14.5 下一步推荐

第一阶段使用确定性规则：

1. 存在未完成巩固题：优先继续当前会话；
2. 存在本轮优先巩固知识点：推荐对应专项 5 题；
3. 仅有 1 次零散错误：提供重做错题和该分类专项；
4. 全部基础题答对但证据分散：推荐新的综合练习；
5. 题库不足以生成推荐组：明确提示内容不足并返回分类入口。

推荐文案必须说明依据，例如：

> 本轮“成语感情色彩”3 题中答错 2 题，建议继续完成 5 题专项巩固。

## 十六、状态机与异常处理

### 16.1 会话状态

```text
不存在
→ active
→ completed

active
→ abandoned
```

`completed` 和 `abandoned` 均为终态，不可原地恢复为 `active`。重新练习必须创建新 Session ID。

### 16.2 题目交互状态

```text
unanswered
→ submitting
→ answered_correct | answered_incorrect
→ advancing
```

提交运行态期间禁用重复提交。提交失败时保持当前答案并允许重试。

### 16.3 异常场景

| 场景 | 处理 |
| --- | --- |
| 分类没有可用题 | 阻止创建，展示空状态 |
| 目标题数不足 | 使用实际数量，不重复凑题 |
| 当前题内容缺失 | 尝试会话快照；仍缺失则终止并保留记录 |
| 本地存储写入失败 | 当前页面保留内存状态并明确提示无法保证刷新恢复 |
| 本地数据损坏 | 隔离损坏对象，允许开始新会话 |
| 选项级解释缺失 | 使用题目通用解析并记录内容缺口 |
| 巩固题不足 | 不插题，不影响主会话完成 |
| 结果摘要缺失 | 尝试由已完成 Session 重建；无法重建时返回入口 |

## 十九、浏览器人工验收

### 19.1 主链 A：专项练习

1. 进入知识练习；
2. 选择一个至少有 5 道可用题的分类；
3. 确认只生成 5 道原题；
4. 故意答错一题；
5. 核对反馈明确解释当前错误选项；
6. 核对后续出现一题相关巩固题；
7. 完成会话；
8. 核对原题首次正确率与巩固结果分开；
9. 从结果页进入推荐专项。

### 19.2 主链 B：综合练习与轮换

1. 创建综合练习；
2. 核对最多 10 道且覆盖至少 3 类；
3. 完成后再次创建综合练习；
4. 核对存在足够候选时，最近题目明显减少；
5. 核对题目不足时没有重复题凑数。

### 19.3 主链 C：恢复

1. 开始练习并完成至少两题；
2. 在一题反馈展示状态刷新页面；
3. 核对当前题、反馈、进度和统计恢复；
4. 关闭后重新进入知识练习；
5. 点击继续上次练习；
6. 完成并刷新结果页；
7. 核对结果保持一致。

### 19.4 适配与可访问性

- 手机宽度下题干、选项、反馈和底部按钮无遮挡；
- PC 宽度下内容区不过宽，阅读节奏稳定；
- 键盘可选择选项、提交和进入下一题；
- 结果不能只依赖红绿颜色表达；
- 按钮具有可理解的 disabled 状态；
- 错误、恢复和空状态均可被屏幕阅读器识别。

### WP6：结果摘要与下一步推荐

交付：

- PracticeResult；
- 真实正确率和用时；
- 知识点与错因摘要；
- 确定性下一步推荐；
- Result 页面改造。

依赖：WP3—WP5、WP7A Engineering PASS。

### WP7B：全链回归与产品验收

交付：

- 唯一入口整合后的全链回归；
- 未完成正式任务与知识练习会话的优先级验收；
- 自动化验收矩阵全量通过；
- 手机 / PC 浏览器验收；
- 工程验收报告与已知限制。

依赖：WP1—WP6、WP7A。

## 二十一、阶段门禁

### 21.1 Design PASS

同时满足：

1. 本文范围、术语和非目标得到确认；
2. Question、Session、Response、Result 核心契约得到确认；
3. 首次正确率、巩固题和知识点结论口径得到确认；
4. 与正式 `/learning` 的隔离边界得到确认；
5. `WP1—WP4 → WP7A → WP5 → WP6 → WP7B` 实施顺序得到确认。

### 21.2 Engineering PASS

同时满足：

1. 专项 5 题、综合 10 题规则稳定运行；
2. 同会话无重复题，变式组基础题不重复；
3. 逐题反馈能对应学生当前选择；
4. 巩固题触发、上限与统计口径正确；
5. 刷新、关闭和重新进入均可恢复；
6. 结果页不再使用错误计分或估算用时；
7. 自动化验收矩阵通过；
8. 主链 A—C 浏览器验收通过；
9. 不影响正式 `/learning` 入口和既有 Runtime 回归。

### 21.3 Product Acceptance PASS

工程通过后，由真实目标用户完成至少 5 次受控试用，满足：

1. 用户能独立开始、作答、查看反馈、继续和完成；
2. 用户能复述至少一条反馈指出的具体错误原因；
3. 用户不会把“本轮表现”误解为长期能力结论；
4. 中断恢复没有造成明显困惑或重复作答；
5. 题目重复没有在短期内成为主要负面反馈；
6. 至少一半错题反馈被用户评价为“知道下次怎么判断”；
7. 发现的内容错误和交互阻断均形成可追踪问题。

### 21.4 Live / Natural-day

第一阶段不因工程完成自动标记 Live。至少需要连续 5—7 个自然日真实使用数据，观察完成率、重复率、巩固表现、恢复和反馈理解后再决定。

## 二十二、风险与预案

| 风险 | 影响 | 第一阶段预案 |
| --- | --- | --- |
| 现有题量不足 | 无法稳定去重和生成巩固题 | 按覆盖矩阵及连续 5 / 10 次使用的重复率、枯竭率补题；题少时降级实际数量，不重复凑数 |
| 选项解析补充成本高 | 反馈仍显通用 | 优先补高频分类；缺失时明确降级并记录内容缺口 |
| 变式组标注不可靠 | 巩固题与原错因无关 | 人工核对变式关系；宁可不插题也不使用弱关联题 |
| 本地存储被清理 | 历史丢失 | 明确第一阶段仅本机保存；不承诺云同步 |
| 旧页面状态与新 Repository 冲突 | 重复记录或恢复错位 | 单一写入边界；迁移完成后移除旧写路径 |
| 统计被误读为能力诊断 | 违背产品总纲 | 全部结论带“本轮”；禁止“已掌握 / 能力提升” |
| 轻量入口与正式主链分叉 | 长期维护两套系统 | 执行已确认 WP0A，先完成 WP7A 唯一入口最小整合 |
| 一次改造范围过大 | 难以验证和回退 | 按 `WP1—WP4 → WP7A → WP5 → WP6 → WP7B` 小步交付，每包独立测试 |

## 二十三、已确认决策

以下 D1—D7 于 `2026-08-28` 确认；2026-08-29 产品负责人进一步确认 WP0A D1—D8。发生冲突时，以 WP0A 为更新后的上位决策：

| 编号 | 决策 | 确认结果 | 实施约束 |
| --- | --- | --- | --- |
| D1 | 首批内容范围 | 聚焦七年级上册 | 学生可用集合不得继续混入未明确标注的跨年级题；现有非七上题先迁移为 `draft` 或保留在非首批集合 |
| D2 | 单组题量 | 专项默认 5 道，综合默认 10 道 | 候选不足时使用实际题数，不得重复凑数 |
| D3 | 第一阶段内容建设目标 | 100 道 `approved` 作为估算目标，不是固定产品门禁 | 最终数量由覆盖、连续使用重复率和枯竭率校准；未通过人工核对的题不计入目标 |
| D4 | 填空判定 | 只支持严格答案与明确等价答案 | 使用 `acceptedAnswers` 和确定性规范化，不引入模糊匹配或大模型判定 |
| D5 | 恢复范围 | 仅本机、本浏览器恢复 | 第一阶段不承诺账户、跨浏览器或跨设备同步，入口需明确这一边界 |
| D6 | 结果核心指标 | 取消“得分”，展示首次正确率 | 巩固题单独统计，不回写首次正确率 |
| D7 | 真实学生验收 | 由产品负责人组织，工程协助记录 | Engineering PASS 后执行至少 5 次受控试用；使用统一观察表记录任务完成、反馈理解、恢复体验和问题 |
