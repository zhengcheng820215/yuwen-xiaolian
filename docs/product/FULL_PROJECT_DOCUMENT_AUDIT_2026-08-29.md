## 一、审计结论

当前项目不是“只有 12 道题的刷题产品”。项目已经形成一条较完整的正式语文能力学习主链，并拥有 24 篇正式材料、81 道 Current Frozen Resource。81 道题属于正式题库，其中 63 道是普通新会话可进入的核心阅读题，18 道是满足特定缺口后才调度的针对性短片段微训练题。

用户感受到“题目少”和“反馈不够好”仍可能是真实问题，但主要原因不能再解释为“项目没有题库”：

1. 学生唯一正式入口 `/learning` 采用任务调度，不展示题库全量，也不等同于自由选题目录；库存数量与学生当下可见、可开始的任务数量不是同一指标。
2. 新增知识练习当前只有 12 道 `approved` 轻量知识题，学生若进入 `/practice/knowledge`，确实会感受到内容少。
3. `/learning` 与 `/practice/knowledge` 是两套入口、Session、存储、反馈和结果链；学生感知被割裂，中央产品文档又仍规定 `/learning` 是唯一正式入口。
4. 正式 Learning 已有 Rubric、证据诊断、反馈后一次修订、超时恢复等较完整反馈能力；知识练习 WP3 解决的是客观题的确定性逐题反馈。两者都完成了工程验收，但真实学生是否觉得“有帮助”仍缺统一产品验收与连续使用证据。

因此，WP1—WP4 解决的问题是真实且有价值的，但它们解决的是“轻量知识练习能否稳定使用”，不是“正式阅读题库从无到有”，也尚未解决全产品唯一入口、内容发现、统一推荐与真实反馈效果问题。

审计建议：WP5 不应直接按原方案继续扩展。应先完成一次上位产品决策和文档对齐，明确知识练习在唯一 `/learning` 入口中的角色，再决定复用现有 WP1—WP4 领域能力的方式。

## 三、当前项目的真实产品结构

### 3.1 上位产品目标

[PRODUCT.md](./PRODUCT.md) 明确规定：产品是“AI 语文能力诊断与成长系统”，题目是能力观察、证据生成和训练验证的载体；题量和题库规模不是当前核心目标。

正式主链为：

```text
有效任务
→ 学生独立作答
→ 作答有效性判断
→ 本次能力诊断
→ Ability Evidence
→ 针对反馈与训练
→ 独立复测或迁移验证
→ 多次 Evidence 评估
→ Student Ability Profile 更新
→ 下一步个性化任务
```

这一定义仍然合理，不应因为用户提出“题少”就退回到以题量为核心的普通题库产品。但产品必须让已有内容可感知、可进入、可连续使用，否则“能力优先”会被学生体验成“没有内容”。

### 3.2 正式学生入口

[学生产品界面收口契约](./STUDENT_PRODUCT_INTERFACE_CONSOLIDATION.md) 冻结 `/learning` 为学生唯一正式入口，并规定 `UnifiedLearningEntryState` 是开始、继续、恢复和进入工作区的唯一权威状态。

代码与这一主链基本一致：根路径跳转 `/learning`，正式 Learning 承担阅读、开放作答、单选、诊断、反馈、修订和下一任务调度。

但代码仍保留并可点击进入以下旧辅助表面：

- `/practice`
- `/practice/knowledge`
- `/mistakes`
- `/profile`

导航数据虽然把“练习、错题本、我的”标为 `frozen: true`，实际仍渲染为可点击链接；`/practice` 继续把知识练习宣传为独立入口。这与“学生唯一正式入口”存在产品语义冲突。

## 四、主要文档冲突与风险

### P0：唯一学生入口与知识练习独立入口冲突

中央契约要求 `/learning` 是学生唯一正式入口；知识练习总体方案却把 `/practice/knowledge` 定义为“正式能力成长主链的辅助入口”，并建立独立 Session、localStorage、反馈、结果和错题事实。

该“辅助入口”定位只出现在知识练习自身文档中。对其余产品、教育、运行和阶段报告的全局检索，没有找到中央控制表或系统地图对这条新链路的正式纳入记录。

风险不是技术上有第二个 Repository，而是学生端形成第二个产品壳和第二套学习事实解释：

```text
/learning：正式资源 → 正式 Session → Diagnosis/Evidence → 下一任务
/practice/knowledge：轻量题 → PracticeSession → 本地反馈/错题 → 本地推荐
```

在角色未定义前继续 WP5—WP7，会进一步固化两套入口和两套成长叙事。

### P0：当前 Trial 状态没有单一权威页

文档时间线为：

1. 2026-08-25：旧构建 Trial 已激活，状态为 `real_trial / real_trial`；
2. 2026-08-26：运行身份变化后旧 Trial 必须失效，WP-R4 验收明确记录 Trial 保持 `off`；
3. 2026-08-26：当前 Commit 准入清单仍为 `NOT YET RUN / REAL TRIAL OFF`；
4. 2026-08-27：[WP-R5 最终收口](./PRODUCT_RUNTIME_RELIABILITY_WP_R5_FINAL_CLOSEOUT.md) 又记录“当前已激活 Trial Window”，并记录窗口内 8 轮，其中 5 轮为真实学生自然使用。

这些记录可以解释为不同时间点的真实历史，但缺少一份带 Runtime Identity、Window ID、激活时间、当前终态和关闭条件的最新签署页。读者无法仅靠当前中央文档确定“现在是否仍在 Trial”。

结论：Trial 技术链不是失败，而是当前状态治理不合格。任何对外或产品决策不得仅引用某一份旧报告宣称“已开启”或“未开启”。

### P1：中央控制表和系统地图存在数量漂移

[产品控制表](./PRODUCT_CONTROL_TABLE.md) 更新日期仍为 2026-08-20，当前优先级继续写“10 篇材料、34 道正式题”；而最新正式资源基线是 24 篇、81 道。

该表自身规定发生冲突时必须纠正，因此这不是可忽略的历史文字，而是当前控制面的失真。系统地图和教育 README 也混合保留多个阶段快照，容易把 34、81、Trial 0/5、Trial 已启动等不同时间事实并列当成当前事实。

### P1：知识练习状态文档未同步

- 总体方案首页仍为 `DESIGN PASS / ENGINEERING PENDING`；
- WP1、WP4 实施文档仍保留待实施或待确认措辞；
- 执行清单已经记录 WP1—WP4 `ENGINEERING PASS`；
- WP2、WP3 的部分“已知限制”已被 WP4 消除，但仍以当前限制口吻存在。

历史限制可以保留，但必须标明“当时状态 / 已由 WP4 关闭”，否则文档使用者会重复解决已完成问题。

### P1：工程通过与产品可用被混用

当前多数验收报告证明的是：

- 领域规则和状态机可运行；
- 自动化测试通过；
- 隔离浏览器或受控主链通过；
- Production Build 通过。

这些证据不能自动证明：

- 学生能理解入口关系；
- 学生感到题量足够；
- 反馈真正回应其答案；
- 学生能根据反馈完成独立改进；
- 连续 5—7 天使用时内容不重复、不枯竭。

知识练习执行清单虽然正确保留了 `PRODUCT ACCEPTANCE PENDING`，但总体叙述容易让“WP1—WP4 工程完成”被误读为“产品已解决反馈和题量问题”。

### P2：100 道轻量知识题目标缺少上位授权

知识练习方案把内容目标设为约 60—100 道，执行清单进一步冻结为 100 道 `approved`。该目标未进入 PRODUCT、产品控制表或系统地图，也没有基于用户频率、轮换周期、知识点覆盖和重复容忍度推导。

100 道可以作为内容建设假设，不应作为当前上位产品承诺。应先定义最小覆盖矩阵和连续使用指标，再由数据推导所需题量。

### P2：当前文档体系缺少“当前事实层”

项目已经有丰富的契约和验收证据，但当前状态散落在：

- 中央控制表；
- 系统地图；
- 教育 README 的追加时间线；
- 最新阶段报告；
- 运行健康页；
- 本地正式资源 Store；
- 浏览器 IndexedDB 中的 Trial 和学习事实。

文档没有统一区分：

- `CURRENT`：当前权威事实；
- `CONTRACT`：长期不变量；
- `PLAN`：尚未实施；
- `ACCEPTANCE EVIDENCE`：某个时点的验收证据；
- `HISTORICAL / SUPERSEDED`：历史快照。

这正是多次讨论中出现“到底是 12、34 还是 81 道”“Trial 到底开没开”的根本原因。

## 五、对“之前优化到底解决了什么”的裁决

WP1—WP4 的方向不是完全错误，也不是在重复建设 81 道阅读题。它们处理的是另一类问题：

| 维度 | 正式 81 道阅读题 | 轻量知识练习 WP1—WP4 |
| --- | --- | --- |
| 内容对象 | 阅读材料、开放作答、阅读单选、针对性微训练 | 字词、成语、病句、古诗文等客观知识题 |
| 核心目的 | 观察能力、形成 Evidence、驱动训练与复测 | 低负担巩固、即时纠错和短期轮换 |
| 学习状态 | 正式 Learning Session / Attempt | 独立 PracticeSession |
| 存储 | 正式 Repository / IndexedDB 与资源链 | 浏览器 localStorage |
| 反馈 | Rubric、Diagnosis、修订与证据边界 | 确定性判题、选项错因和步骤 |
| 长期结论 | 可进入 Evidence / Profile 评估 | 明确禁止生成长期能力结论 |

所以，之前优化正确解决了“轻量知识练习不可稳定连续使用”的工程问题；方向偏差发生在它与总产品唯一入口的关系没有先被中央文档确认，而不是 WP1—WP4 的领域能力本身没有价值。

这些已完成能力应尽量复用，不建议推倒重来。

## 六、为什么有 81 道题，用户仍会觉得题少

“题库库存”至少应拆成四个产品指标：

| 指标 | 含义 | 当前可确认事实 |
| --- | --- | --- |
| Inventory | 系统已发布的正式题目总量 | 81 |
| Eligible Pool | 当前任务类型和条件下可进入候选的题 | 核心 63；条件微训练 18 |
| Scheduled Next | 当前学生状态下实际排出的下一任务 | 由 Observation Plan / Strategy 决定 |
| Visible Choice | 学生在页面上能感知或主动选择的内容 | `/learning` 不展示 81 题目录；知识入口仅 12 道 approved |

用户反馈“题少”最可能指后两项，而不是 Inventory。现有文档几乎只证明资源库存和调度正确，没有专门验收“学生是否知道还有多少内容、为什么只看到这一题、做完后还有什么”。

因此正确优化方向不是简单再造一批题，而是先解决：

1. 学生在唯一入口中能否理解当前任务、可选训练类型和后续内容；
2. 无任务、已完成、资源不匹配和 Trial 未准入是否被准确区分；
3. 连续若干次使用时，实际可调度内容是否重复或耗尽；
4. 轻量知识训练是否应作为 `/learning` 中的一个任务家族或受控辅助模式。

## 七、方向调整建议

### 7.1 WP5 前新增“WP0A：产品入口与内容角色对齐”

在继续开发错题巩固前，先输出并确认一份短上位决策文档，至少冻结：

1. `/learning` 是否继续是学生唯一入口；
2. 知识练习是 `/learning` 内的 `knowledge_practice` 任务类型、独立辅助工具，还是继续保留第二入口；
3. 哪些状态和事实复用正式身份、Session、事件采集，哪些保持轻量隔离；
4. 81 道正式阅读题与轻量知识题如何在入口中被解释、推荐和展示；
5. WP5、WP6、WP7 哪些内容保留、前移、合并或取消。

推荐方案：保留 WP1—WP4 的 Question、选题、判题和恢复领域能力，将知识练习作为 `/learning` 唯一入口中的受控轻量任务家族；不把轻量客观题强行升级为正式能力 Evidence，也不继续扩建第二套学生产品壳。

### 7.2 调整 WP5—WP7 顺序

建议顺序为：

```text
WP0A 上位角色与入口决策
→ WP7A 唯一入口最小整合与内容可见性
→ WP5 错题巩固（仅在入口和事实归属清晰后）
→ WP6 结果摘要与下一步推荐
→ WP7B 全链回归与真实学生产品验收
```

原方案把入口整合放在最后，会让 WP5、WP6 继续依赖尚未确认的第二产品壳，返工风险较高。

### 7.3 用覆盖与使用指标替代“100 道”单一目标

内容建设至少应按以下门禁管理：

- 年级、学期、知识类别和知识点覆盖；
- 每个知识点可独立作答的基础题数量；
- 错误选项是否有真实且不同的误区；
- 变式关系是否经人工确认；
- 5 次、10 次连续练习的重复率和枯竭率；
- 反馈是否能让学生说清“为什么错、下次先检查什么”。

题量由覆盖矩阵倒推。若 40 道能满足首阶段连续使用，就不为凑 100 道复制内容；若关键知识点需要 120 道，也不应被 100 道上限限制。

### 7.4 建立真实产品验收

下一阶段必须区分三种 PASS：

| 状态 | 证明内容 |
| --- | --- |
| Engineering PASS | 规则、状态、恢复、构建和回归成立 |
| Product Acceptance PASS | 学生理解入口、反馈和下一步，连续使用无明显阻断 |
| Educational Evidence | 独立复测或迁移证据支持改善结论 |

对“反馈不太行”的最小验收不应只检查页面有反馈，而应记录：

- 反馈是否引用了本次答案的具体选择或表达；
- 学生是否理解错误点；
- 学生是否知道下一步动作；
- 同题修订是否改善；
- 新题或新文本中是否仍能独立完成。
