# 产品颜色语义规范

状态：ACTIVE  
更新日期：2026-07-29

## 一、用途

本文统一素材资源录入平台、题目审核与发布平台及后续产品页面的颜色用途。

颜色用于帮助用户快速识别状态和操作类型，不用于装饰，也不能作为传递信息的唯一方式。状态必须同时通过文字、图标或组件形态表达。

## 二、颜色语义

| 颜色 | 核心含义 | 典型场景 |
| --- | --- | --- |
| 绿色 | 通过、成功、已完成、可用 | 审核通过、检查通过、发布成功、服务可用、成功状态 |
| 红色 | 失败、阻断、严重警告、危险操作 | 校验失败、无法继续、发布阻断、删除、不可恢复操作 |
| 黄色 | 提醒、注意、待确认、非阻断问题 | 质量提醒、设置差异、待人工确认、可继续但需要关注 |
| 蓝色 | 选中、动作、执行、当前焦点 | 当前选中项、可执行操作、链接、输入组件聚焦态 |
| 紫色 | AI、智能生成、智能优化 | AI 生成、AI 重新生成、AI 优化、AI 建议 |

## 三、使用边界

### 1. 绿色

- 只表达正向结果或已达到要求的状态。
- 不用于普通主操作按钮，避免把“可执行动作”误读为“已经成功”。
- “审核通过”“已发布”等状态应同时显示明确文字。

### 2. 红色

- 用于已经失败、明确阻断或具有破坏性的操作。
- 严重警告必须说明阻断原因和解决方法。
- 删除等危险操作使用红色文字或危险按钮，并保留确认机制。
- 不用于普通提醒，避免制造不必要的紧张感。

### 3. 黄色

- 用于尚未失败、但需要用户关注或确认的事项。
- 黄色提醒默认不阻断流程；若实际会阻断，必须在文案中明确说明。
- 提醒内容应包含“哪里有问题”和“下一步怎么处理”。
- 不能用黄色表达已经完成或已经通过。

### 4. 蓝色

- 用于当前选中、常规动作、执行入口和输入焦点。
- 输入框、选择框和文本域聚焦时统一使用蓝色边框或焦点环。
- 蓝色可以表示正在操作，但不能代替成功、失败或 AI 身份。
- 同一操作区只保留一个主要蓝色动作，避免多个同级主操作争夺注意力。

### 5. 紫色

- 只用于 AI 身份明确的操作与内容。
- AI 实色按钮和线框按钮统一使用品牌紫 `#6713EE`。
- 普通人工编辑、保存、提交和返回操作不得使用紫色。
- AI 生成结果仍需结合绿色、黄色或红色表达其质量状态，紫色本身不代表结果通过。

## 四、严重程度规则

```text
绿色：已经通过或完成
蓝色：现在可以操作或正在操作
紫色：该操作由 AI 提供
黄色：可以继续，但需要注意或确认
红色：已经失败、被阻断或存在危险
```

红色与黄色的判断标准：

- 会阻止保存、提交、审核或发布：红色。
- 不阻止流程，但需要人工关注：黄色。
- 删除、停用等高风险操作：红色。
- 尚未完成但可以继续处理的状态：黄色。

## 五、组件规则

- `Status`：按业务结果使用绿、黄、红，不使用蓝色表示完成。
- `Alert`：成功用绿、提醒用黄、失败或阻断用红、一般说明用蓝。
- `Button`：常规主操作用蓝或产品定义的中性主色；AI 操作用紫；危险操作用红。
- `Input / Select / Textarea`：聚焦态统一使用蓝色。
- `Tag`：能力、题型等分类标签使用中性或蓝色；状态标签按状态语义着色。
- `Link`：默认使用蓝色；AI 专属入口可以使用紫色。

## 六、可访问性要求

- 不得只靠颜色区分状态。
- 每个状态必须提供可理解的中文文案。
- 警告和失败应配合图标或明确标题。
- 文本与背景需要保持足够对比度。
- 禁用态使用灰色，不使用低透明度的业务状态色伪装禁用。

## 七、验收标准

1. 同一颜色在两个生产平台表达相同含义。
2. 绿色不会用于尚未完成的动作状态。
3. 黄色提醒与红色阻断可以被用户明确区分。
4. 所有输入组件聚焦态统一为蓝色。
5. 所有 AI 操作入口统一为紫色，并且不与人工操作混淆。
6. 删除、失败和阻断状态均有明确文案，不能只显示红色。
7. 页面在去除颜色后，仍能通过文字和组件结构理解状态。
