# AI 题目生成质量与定向优化契约

英文名称：AI Question Generation Quality and Targeted Optimization Contract

状态：`ACTIVE`

文档版本：`ai_question_generation_quality_and_targeted_optimization_v2.0`

生效日期：`2026-08-20`

## 一、目标与适用范围

本文约束 AI 如何依据材料和训练任务生成完整题目方案，以及如何在不扰动现有正式资源的前提下定向优化少量题目。目标是：

1. 保证题干、作答动作、作答格式、难度、能力、评分标准和答案接受范围属于同一个完整方案；
2. 减少同篇材料中回答对象、证据范围、能力动作和评分目标的重复；
3. 在保持文本价值的前提下改善基础—中等—高阶梯度，不以机械配额改题；
4. 先生成候选，再由用户执行“采用并发布 / 重新生成题目”一次决定；
5. 采用失败或系统中断时继续保护当前正式题和 Learning 消费。

本文不授权 AI 修改材料正文、原位覆盖 Frozen Question Version、批量替换全部题目，也不增加人工改题、审核人、审核意见或第二次确认。

阅读训练单项选择的对象结构、适用边界、干扰项质量、学生投影、Diagnosis、真实数据和分阶段验收统一遵循[阅读训练单项选择作答契约](./READING_SINGLE_CHOICE_RESPONSE_FORMAT_CONTRACT.md)。Schema 中预留 `single_choice` 枚举不等于工程能力已经可执行；在该契约阶段1—4完成前，不得将其标记为正式覆盖能力。

阅读开放文本题的进入难度、单题复合度、推荐作答长度、提示负担、题组坡度和既有题治理统一遵循[阅读开放文本题难度梯度与输入负担优化契约](./READING_OPEN_RESPONSE_DIFFICULTY_AND_INPUT_LOAD_OPTIMIZATION_CONTRACT.md)。该优化降低训练入口与表达负担，但不删除 Observation Plan 必需的高阶文本观察，也不改变 Candidate → Adopt → Revision → Publish 主链。

若需要把题组坡度用于识别学生从哪一层开始失稳，还必须遵循[阅读训练递进负担模型契约](./READING_TRAINING_PROGRESSIVE_LOAD_MODEL_CONTRACT.md)。生成器不得自行把内容层负担标签投射为学生能力结论；阶段 0 仅执行历史正式题的只读兼容投影。

## 二、当前基线与优化边界

2026-08-13 当前本地基线为：

- `10` 篇活动 Material（九篇 v3 与《走一步，再走一步》v1）；
- `34` 道当前正式题；
- `34 / 34` Active Registry；
- `34 / 34` Active Observation Link；
- `34 / 34` Frozen Quality Trace；
- Learning 可以读取当前正式资源；
- 当前能力分布以 `analysis / intermediate` 为主，但不存在要求整批推翻的阻断性问题。

因此，本轮采用“规则先行、少量试点、逐题采用”的策略：

```text
冻结34道正式题基线
→ 优化 AI 生成规则
→ 对4道试点题生成完整候选
→ 用户逐题采用并发布，或重新生成
→ 验证 Registry / Link / Learning
→ 再决定是否扩大范围
```

在任一试点候选被采用前，正式题总数、活动版本和 Learning 行为都不得改变。

## 三、完整题目方案契约

每个 `QuestionCandidate` 必须作为不可拆分的完整方案生成，至少包含：

| 内容 | 要求 |
| --- | --- |
| `questionStem` | 明确材料范围、回答对象和学生需要完成的动作 |
| `responseFormat` | 与实际回答负荷一致，不沿用不匹配的旧格式 |
| `minimumAnswerRequirement` | 与题干动作和评分项共同推导，不使用无依据的固定字数 |
| `abilityMetadata` | 主能力、难度和任务角色与题干真实要求一致 |
| `rubric` | 每个评分项可由题干要求和材料证据支持 |
| `answerAcceptance` | 允许合理的语义等价表达，开放题不收窄为唯一措辞 |
| `sourceAnchorIds` | 引用范围属于当前 Material Version，段落位置可解释 |
| 生成上下文 | 绑定当前 Material、Plan、TrainingTask 和基准正式版本 |

禁止只生成新题干后沿用旧题的格式、难度、Rubric 或答案接受范围。任何一个组成部分变化，都必须重新计算完整方案的内容哈希和质量结果。

## 四、题干动作与作答格式匹配

### 4.1 短文本适用条件

`short_text` 原则上只用于一个主要回答动作，例如：

- 定位并提取一个或两个明确事实；
- 概括一个局部对象的特点；
- 对一句话或一个动作作聚焦解释；
- 评分标准可以用少量关键点稳定判定。

短文本题不得同时要求全文梳理、多角度比较、人物心理链、结构作用和主题意义等多个独立任务。

### 4.2 长文本适用条件

出现下列情况时，AI 应优先评估 `long_text`，或主动缩小题干范围后再使用短文本：

- 要求从两个或更多角度分析；
- 要求比较多个对象、阶段或情节；
- 要求同时提供材料证据、解释关系和形成结论；
- 要求梳理因果链、发展过程或全文结构；
- Rubric 包含三个或更多相互独立的核心观察点时，产生长文本强提示；
- 开放答案需要容纳多种有依据的合理解释。

Rubric 数量本身不是格式阻断规则。有些题虽然评分点较多，但每个评分点都能通过简短、明确且互不冲突的答案表达，此时仍可以使用 `short_text`。系统必须结合题干动作、回答对象、证据范围和预计回答负荷完成一致性检查，不能仅按评分项数量机械切换格式。

### 4.3 单项选择适用条件

`single_choice` 只适用于能够通过一次明确选择观察的训练动作，例如信息定位、基础理解、局部判断、简单因果和语句作用的初步辨认。生成器不得为了题型丰富度或固定配额把概括、多证据整合、推理、人物分析和主题理解改造成单选题。

选择题必须作为独立 `QuestionCandidate` 生成，不嵌入文本题内部。AI 必须一次生成完整题干、稳定选项身份、唯一正确答案、逐项干扰依据、Answer Acceptance 和 Rubric。任一错误选项缺少可解释偏差时，候选不得进入“可以发布”。详细规则以[阅读训练单项选择作答契约](./READING_SINGLE_CHOICE_RESPONSE_FORMAT_CONTRACT.md)为准。

同篇任务推荐由低输入负荷向高输入负荷组织，但选择题不固定排第一。实际顺序由 Observation Plan 的教学意图和任务依赖决定，`taskRole` 只约束任务用途。

第一版只允许 `single_choice`，不实现 `multiple_choice`、选择后追问或反馈后立即改选。

### 4.4 一致性检查

系统必须同时检查：

```text
题干动作数量
↔ 回答对象数量
↔ 证据范围
↔ responseFormat
↔ minimumAnswerRequirement
↔ Rubric 核心项数量
```

任一方向不一致时，候选不得显示为“可以发布”；AI 应重新生成完整方案，而不是要求用户修改字段。

一致性检查必须是双向的：题干提出的动作必须被 Required Rubric 覆盖；每个 Required Rubric 也必须能在题干中找到学生可见、可理解的明确要求。题干未要求的结构关系、比较、原因、情感主题、写法效果、文本依据或解释动作，不得作为基本完成判定或隐藏失分条件。

短段落并不自动等于证据不足，但证据范围较短时必须控制核心任务数量。一个短文本题通常只保留一个主要认知动作和一至两个相互依赖的核心评分项；补充观察只能作为非 Required 的优秀表现，不得借 Rubric 扩张题干没有提出的任务。

定向生成“新版方案”时，生成器必须读取目标题当前的题干、学生动作和 Required Rubric，而不是只读取抽象训练方向。若首轮候选出现题干—Rubric 隐藏要求，系统应在候选进入工作台前执行一次受控修复：保持回答对象和核心训练意图不变，优先删除或降级题干未要求的评分项；只有该维度确属核心训练目标时，才可同步把要求写入题干。修复后仍不一致的候选不得显示为“可以发布”。

## 五、题组去重与观察价值

同篇材料的题目不能只通过替换措辞制造表面差异。系统应使用以下组合判断重复风险：

```text
回答对象 + 材料证据范围 + 学生能力动作 + Rubric 目标
```

生成新候选时必须读取该材料当前任务组和正式题目，并优先增加新的观察价值：

- 相同材料片段可以服务不同能力，但回答动作和评分目标必须不同；
- 相同能力可以重复出现，但必须覆盖不同对象、证据或推理关系；
- 题干不同但标准答案和 Rubric 实际相同，仍按疑似重复处理；
- 已发布题不因候选重复而改变，未采用候选可以被下一轮候选直接替换。

重复风险属于候选生成约束。系统能够确定为同一回答对象、同一证据和同一评分目标时应阻断；仅属于能力分布相近时作为优化提醒，不阻断用户采用。

`training / retest / transfer` 等任务角色不构成重复检查豁免。即使角色不同，系统仍必须比较回答对象、证据范围、学生能力动作和 Rubric 目标：

- Retest 必须能够观察能力在间隔或新条件下是否稳定，不能只是复制 Training；
- Transfer 必须改变材料、情境、证据组织或应用条件，不能只替换任务角色标签；
- 只有任务角色带来了可解释的新增观察价值时，相似题才能放行；
- 不得仅凭 `taskRole` 不同跳过实质重复判断。

## 六、能力与难度梯度

题组应优先形成可解释的认知梯度：

1. 基础层：定位、提取、准确概括；
2. 中等层：局部分析、作用解释、关系说明；
3. 高阶层：全文整合、推理、比较、主题判断。

梯度规则用于发现盲区，不是配额：

- 不要求每篇材料固定包含三种难度；
- 不为补足类别生成缺少文本价值的题目；
- 当同篇任务全部集中在同一能力或难度时，AI 必须先寻找不同的有效观察点；
- 若材料确实只支持相近能力，生成结果必须保留内部理由，但不要求用户填写说明；
- 批次中某一能力占比过高只产生治理提醒，不自动批量改写正式题。

能力和难度必须根据最终题干重新计算，不能仅复制 TrainingTask 或旧 Question Version 的标签。

## 七、质量门禁与用户决策

### 7.1 阻断项

以下问题必须阻止候选进入“可以发布”：

- 题干缺少明确学生动作；
- 题干引用范围超出当前 Material Version；
- 作答格式与题目负荷明显冲突；
- Rubric 无法由题干或材料证据支持；
- Required Rubric 包含题干没有明确要求的必答维度；
- Candidate、Assessment、TrainingTask 和 Material 身份不一致；
- 与同篇当前题在回答对象、证据和评分目标上实质重复；
- 使用过期 Assessment 或旧内容哈希授权新候选。

阻断后的唯一内容动作是“重新生成题目”。技术中断由系统继续重试。

### 7.2 非阻断提醒

以下问题可以作为采用前提醒：

- 批次能力分布仍偏集中；
- 难度标签存在一定解释空间；
- 开放题可能需要真实作答扩展接受范围；
- 来源或版权状态尚未核验。

提醒不得增加人工审核步骤。用户仍只执行：

```text
采用并发布 | 重新生成题目
```

能力集中、难度集中、基础难度缺口等 `advisory` 必须按材料或题组聚合，不得在每道已发布题上重复制造“需要处理”的视觉状态。长文本负荷属于 `strong_hint`，只有作答格式与负荷形成明确冲突时才升级为阻断。来源与版权状态进入素材治理摘要，不计入题目待发布数。

### 7.3 历史正式题的最新质量重新准入（2026-08-19）

Formal Resource 曾经发布成功，只能证明该版本通过了发布当时的契约，不能永久豁免后续已冻结的内容质量门禁。系统在建立新的 Learning Session 前，必须对每个 Active Registry Current Head 使用当前质量策略重新计算准入结果：

```text
Active Registry Current Head
→ 身份、Link 与 Material / Plan 完整性检查
→ 按当前题干、作答格式、选项、Rubric 和同篇题组重新评定
→ ready | ready_with_guidance | blocked
→ 仅前两类进入新会话候选池
```

强制边界：

1. 重新准入以当前内容和当前策略计算，不得只信任历史 `Frozen Quality Trace` 中的旧结论；
2. `blocked` Current Head 继续保留为可审计历史，但不得进入新 Learning Session，也不得计入“当前可学习题目”；
3. `ready_with_guidance` 仍可进入 Learning，题组级建议不得伪装成逐题待处理；
4. 已经开始的 Learning Session 继续使用启动时冻结的确切 `resourceVersionId`，不得因策略升级在题间静默换题；只有资源身份损坏、内容不可执行或安全风险才允许中止，并须给出明确恢复动作；
5. 最新质量状态、策略版本、阻断原因码与评定时间必须可审计；策略升级后的重新评定不得原位修改 Frozen Version；
6. 新会话的入口探测、任务队列创建和工作区加载必须消费同一份最新质量准入结果，不能入口可开始而工作区再次阻断。

历史阻断题的处理不是删除，也不是在题组末尾持续追加：

```text
生成修复 Candidate
→ 用户采用
→ 创建同一 Question Lineage 的后继版本
→ 通过最新质量门禁
→ 原子切换 Registry Current Head
→ 旧版本保留历史且不再进入新会话
```

当题组已达到规划上限时，新增单项选择必须优先替换同一题组中已阻断或低观察价值的 Current Head，不得通过不断追加造成题目无限增长。只有题组仍低于容量上限、Observation Plan 存在独立观察缺口且新题不与现有任务重复时，才允许作为新的 Candidate 补充。

## 八、正式版本保护与原子替换

候选生成不修改当前正式资源。只有用户点击“采用并发布”后，系统才按顺序执行：

```text
创建后继 Question Revision
→ 结构与语义质量检查
→ 记录同一次采用决定
→ Freeze 新版本
→ 写入新 Formal Version
→ 原子切换 Registry 与 Observation Link
→ 旧版本进入历史
```

前台只呈现一次“采用并发布”，但后台必须持久化可恢复的阶段结果。推荐的内部投影至少包括：

```text
adoption_completed
→ validation_completed | validation_failed
→ assessment_completed | assessment_failed
→ publication_completed | publication_failed
```

这些状态只用于幂等重试、断点恢复、错误定位和审计，不得投射成新的人工步骤：

- `adoption_completed` 只表示候选采用结果已保存，不等于已经正式发布；
- `validation_failed` 且属于内容问题时，前台只提供“重新生成题目”；
- `assessment_failed` 属于技术中断时，前台只提供“继续发布”，系统从断点重试；
- `publication_failed` 时旧正式版本继续 Active，前台只提供“继续发布”；
- `publication_completed` 后才显示“已发布”。

强制要求：

1. 不原位改写 Frozen Version；
2. 切换成功前，旧 Registry 和 Link 继续保持可消费；
3. 任一步失败时不出现半发布状态，Learning 继续使用旧版本；
4. 重试复用稳定幂等键，不重复创建 Revision、Trace、Registry 或 Link；
5. 单题替换前后当前正式题总数保持不变；
6. 已开始的 Learning Session 继续绑定原 Frozen Version，新 Session 读取切换后的活动版本；
7. 题目优化不得创建新的 Material Version，也不得修改素材正文或来源状态。

- 每道题生成时读取其当前正式版本作为基准；

- 用户可以逐题采用，也可以持续重新生成；
- 不提供字段级人工编辑、删除题目、审核意见或独立保存按钮；
- 四道试点未全部采用不视为失败，保留当前正式版本属于合法结果。

## 十、验收与回滚

### 10.1 生成规则验收

- 完整候选字段齐全，身份和内容哈希一致；
- 作答格式与题目负荷检查覆盖短文本和长文本两类；
- 同篇重复判断同时使用回答对象、证据范围、能力动作和 Rubric；
- 能力分布只产生建议，不机械改变正式题；
- 内容阻断只导向重新生成，技术中断只导向系统重试。

### 10.2 单题采用验收

- 采用期间只显示一个“正在发布”状态，不允许重复提交或同时重新生成；
- 采用成功后当前卡片原位变为“已发布”；
- 采用失败时旧正式版本仍为 Active；
- 重试不产生重复正式版本或活动关系；
- 当前正式题、Registry、Link 和 Frozen Quality Trace 均保持 `34 / 34`；
- Learning 启动、刷新和新任务匹配继续成功。

### 10.3 回滚口径

候选未采用时无需回滚。发布事务失败时系统保持旧活动链；新建但未接通的对象保留为非活动、可恢复记录。已经成功原子切换的新版本如需撤回，必须创建新的正式决策和后继版本，不允许直接改回旧 Registry 字段或删除历史证据。

## 十一、真实作答校准

试点题发布后，题目质量结论仍需真实 Learning 作答验证：

- 样本严格绑定 `resourceVersionId`；
- `0` 份有效样本返回 `awaiting_data`；
- 按当前试运行策略，`1–29` 份返回 `insufficient_sample`；
- 按当前试运行策略，达到 `30` 份后才计算试运行难度、区分度和评分接受范围风险；
- `30` 份是当前单学生、本地试运行阶段启动初步校准的产品治理阈值，不代表统计学意义上的稳定区分度，也不是永久标准；
- 样本阈值必须作为可版本化策略配置，后续可以根据学生数量、题型、作答独立性和统计方法调整；
- 达到当前阈值后只输出“初步指标”或“试运行指标”，不得表述为题目质量已经稳定；
- 不同版本样本不合并；
- 样本不足不触发自动回滚或批量重生成；
- 后台发现稳定问题后，仍回到“生成完整候选 → 采用并发布 / 重新生成题目”的标准路径。

## 十二、P0—P2 收口后的生成机制稳定期（2026-08-14）

P0—P2 完成后，当前正式基线为12篇活动材料、46道 Learning 可消费题。四道基础能力补充题已经通过完整内容方案、质量检查、正式发布、幂等回归和浏览器验收。现阶段没有需要立即重写生成主链或 Prompt 的 P0 缺陷。

后续生成机制进入“保持主链稳定、由真实数据触发小步校准”的观察期：

1. 继续使用“读取材料与现行题组 → 识别新增观察价值 → 生成完整候选 → 隔离质量检查 → 用户采用并发布”的标准路径；
2. 记录生成、重新生成、采用和放弃事件，并保留 Prompt / Policy Version、候选身份与放弃原因；
3. 真实 Learning 侧重点观察有效作答率、空答率、明显跑题率、修改次数、完成时长、诊断分布和答案接受边界命中情况；
4. 大量跑题优先检查题干与作答要求，答案高度趋同优先检查区分潜力，普遍无法作答优先检查难度与证据负荷，诊断频繁失配优先检查 Rubric 与 Answer Acceptance；
5. 单题未达到当前版本化样本阈值时只记录现象，不自动改题、不自动回滚、不批量重生成；
6. 达到阈值后仍先形成可解释的治理建议，再按后继 Candidate / Version 路径调整，不允许系统直接学习并覆盖 Frozen Version；
7. 材料级能力或难度集中继续属于非阻断组合提示，不据此机械补题或追求比例平均；
8. 《女娲造人》《天上的街市》是否补充基础题，等待首批真实作答反馈后再判断，不预先转成工程待办。

允许进入下一轮机制调整的证据至少包括：跨多次真实作答重复出现的同类问题、可定位到具体 `resourceVersionId`、能够区分题干/Rubric/难度/证据范围问题，并且调整目标可以通过版本化验收验证。单次异常、少量样本或材料级 advisory 不构成机制重写依据。

## 十三、禁止做法

- 一次性重新生成并替换全部34道题；
- 为改善分布机械规定每篇必须包含固定能力或难度数量；
- 只修改题干而沿用旧 Rubric、格式或 Assessment；
- 把未采用 Candidate 计入发布数或 Learning；
- 采用前停用旧正式版本；
- 用人工逐字段改题代替 AI 重新生成；
- 要求填写审核人、审核意见、保留理由或第二次确认；
- 让来源核验状态阻断当前内部试运行题目优化；
- 制造学生样本，或在未达到当前版本化治理阈值时宣称题目质量稳定。

## 十四、2026-08-19 当前正式题重新准入审计

本轮按照第 7.3 节对权威共享正式资源执行了最新策略重新评定。校准前的首轮扫描曾把 Rubric 中的正确答案细节误识别为题干遗漏动作，产生 `22` 道假性阻断；门禁现已明确区分“学生必须执行的新动作”与“对正确答案的评分说明”，并保留真正的隐藏必答维度阻断测试。

校准后的只读审计结果：

- Active Current Head：`46` 道；
- 最新策略 `blocked`：`0` 道；
- `ready_with_guidance`：`16` 道，均为三个或更多核心观察点的长文本强提示，不阻断 Learning；
- `ready`：`30` 道；
- 作答格式：`long_text 34`、`short_text 12`、`single_choice 0`。

因此，当前文本题不存在需要批量重写或删除的质量阻断。剩余差距属于题组梯度而不是现有题目错误：历史 Current Head 尚未包含单项选择。系统必须继续通过“生成完整 Candidate → 用户采用并发布”补充高质量基础单选，不得为了让统计立即达标而后台静默发布、原位改写或自动停用现有题。题组达到 `6` 道后，如仍需新增单选，只能通过同一 Lineage 的后继版本替换低观察价值任务，不能继续追加。

## 十六、2026-08-25 全量正式题复审与 successor 治理边界

本轮使用当前冻结的生成质量策略、正式资源身份规则与递进负担语义，对 `24` 篇活动材料、`81` 道 Current Head 执行只读复审。复审范围包含 `12` 篇核心阅读材料与 `12` 篇 targeted excerpt；正式题身份、Active Registry、Active Observation Link、Frozen Quality Trace 与 Learning 可消费投影均保持 `81 / 81`，一致性问题为 `0`。

治理前最新质量分布为：

- `ready`：`63` 道；
- `ready_with_guidance`：`16` 道；
- `blocked`：`2` 道；
- 作答形式：`long_text 31`、`short_text 32`、`single_choice 18`。

两项阻断必须通过不可变后继版本治理：

1. 《春》一题声明为 `single_choice`，但发布投影遗漏 `choiceInteraction`，导致正式版本缺少选项、正确答案身份与干扰项依据；
2. 《女娲造人》一题的 Rubric 要求解释“小人的表现—女娲喜悦”的关系，但旧题干没有把该必答关系说清楚。

本轮治理冻结以下边界：

1. 不原位修改、删除或覆盖 Frozen Resource；两题均沿原 `resourceId` 创建 successor Candidate / Draft / Frozen Version；
2. 旧版本转为 `superseded` 并继续保留审计链；已开始 Session 继续绑定旧版本，新建 Session 只消费新 Current Head；
3. Current Head 总数保持 `81`，不得把版本治理误计为新增题量；Registry、Link、Quality Trace 与 Plan 必须在同一次受控提交中切换；
4. 《春》后继版本必须完整保留 `choiceInteraction`，且 `acceptedOptionIds` 必须与 `correctOptionIds` 一致；补充生成发布器必须将该字段同时投影到 Draft 与 Frozen Version，避免同类缺陷复发；
5. 《女娲造人》后继版本只显式化原 Rubric 已要求的因果关系，不扩充新的观察动作，不改变题型、任务角色或能力结论；
6. 治理完成后，当前质量重新准入必须达到 `0 blocked`，正式身份与 Learning 消费继续保持 `81 / 81`。

递进负担审计中的 `unexplained_responsibility_jump` 属于题组级治理提示，不等于单题内容错误或学生能力不足。系统不得为了消除提示机械补齐全部负担等级，也不得批量改写既有正式题。只有在能够证明缺少过渡理由、真实 Learning 出现同层级失稳，且 successor 能增加独立观察价值时，才进入后继候选治理；否则保留为 advisory 并记录处置理由。

所有审计与迁移脚本不得继续把 `61` 道题、`15` 道单选等历史快照写死为永久断言。历史报告保留当时事实；当前验收必须从执行前权威共享存储动态读取基线，并验证治理前后题量、身份链和题型数量守恒。
