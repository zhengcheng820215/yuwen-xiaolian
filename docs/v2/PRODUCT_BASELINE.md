# 轻舟 V2.0 产品基线

版本：V0.1（转型设计基线，待产品决策项关闭后冻结）

适用范围：`轻舟V2.0` 转型副本

依据：用户提供的《轻舟 V2.0｜错题诊断、训练与评估标准》V0.1 与《移动端优先设计规范》V0.2
配套执行清单：[轻舟 V2.0 分阶段开发清单](./PHASED_DEVELOPMENT_CHECKLIST.md)

## 1. 产品目标与版本边界

轻舟 V2.0 是基于学生**真实错题**的 AI 学习诊断与针对性训练工具。首版要让一道人为确认的错题形成可追溯的学习闭环：

**拍照或上传 → 识别并确认 → 证据诊断 → 方法指导 → 2 道针对训练 → 1 道独立复测 → 效果评估。**

第一阶段学科为初中语文。系统可识别并分类基础知识、古诗文、现代文阅读、语言运用和写作题，但首版完整诊断、训练和复测能力**仅面向现代文阅读主观题**。其他题型可以分类、存档，并清楚告知尚未开放完整闭环；不得因能够识别题型就宣称能够诊断该题型。

转型副本中的既有 `/learning`、正式题库、知识练习与长期能力画像是旧方向的实现和历史资产，不自动构成 V2.0 的需求、完成证据或上线状态。可复用能力必须经过适配与验收。冻结版分支不受本基线影响。

## 2. 首版用户旅程

| 步骤 | 用户必须能完成的事 | 系统必须给出的结果或边界 |
| --- | --- | --- |
| 输入 | 拍照或从相册选择图片；阅读材料可按顺序上传多图 | 显示上传与处理状态；权限被拒仍可用相册 |
| 确认 | 查看、修正题干、材料、学生答案和批改信息；多题图片选择当前错题 | 关键字段不清晰时要求补充或手动修正，不猜测缺失文章 |
| 诊断 | 对照原题、学生答案与具体错误 | 区分观察事实、原因假设和证据；必要时追加一次简短验证 |
| 指导 | 理解正确思路和下一题可复用的方法 | 方法与当前训练目标一一对应，避免泛泛评价 |
| 训练 | 完成 2 道同能力点、难度相近、内容不同的题 | 第 1 题可分步提示；第 2 题默认独立，求助须记录 |
| 复测 | 对新材料或新问法独立作答 | 不显示提示、参考答案或训练题反馈中可泄漏的答案 |
| 结果 | 查看目标评分点与掌握状态 | 只给出有证据支持的“初步掌握 / 尚未掌握 / 证据不足” |

没有学生答案时，可以解释题目，但不能给出个人错误根因诊断。题目、答案或阅读材料等关键证据不足时，不能绕过确认直接进入诊断。

## 3. 诊断与训练规则

首版错误标签为知识缺失、审题偏差、信息提取、理解分析、方法策略、表达规范；“偶发性失误”是非能力性标签，不能凭一次错误断定为粗心。允许多个标签并存，但每轮优先选择一个最值得干预的核心问题。

诊断输出至少包含：具体错误表现及其原题/作答证据、最可能的原因及确定程度、正确思路、下一题可重复使用的改进方法。无法区分两种可能原因时，追加一个围绕这两种原因的简短任务；仍无法判断则标记“原因暂不明确”，不强行归因。任何能力结论都不能只由题型名称或一次错误推出。

训练题必须针对**诊断目标**而非仅与原题同类型。每题生成时同时形成合理答案范围、关键评分点、可接受的同义表达、常见错误和纠正方法。质量检查须覆盖目标能力一致性、材料和答案一致性、与原题难度可比性（材料长度、信息密度、推理步骤、知识要求、答案复杂度）及内容差异性；不合格题不得展示给学生。

每次训练反馈应指出已满足的要点、未满足的要点、相对上次的变化以及下一次注意点。主观题按评分点和语义评价，不按参考答案的字面一致性评价。第 2 题的提示使用必须记录，不能算作独立完成；诊断目标发生有证据支持的变化时，允许调整训练目标。

## 4. 复测与结果判定

复测使用同一目标能力点、难度相近但内容不同的新材料或新问法。预设评分规则评价结果正确性、方法运用、独立程度与迁移表现；不得在复测前展示提示或参考答案。

| 状态 | 首版判定条件 |
| --- | --- |
| 初步掌握 | 独立有效作答，达到该题预设通过标准，且目标能力的关键评分点全部满足 |
| 尚未掌握 | 有效复测未达通过标准，目标关键错误仍可观察到 |
| 证据不足 | 作答无效、题目质量或难度不可比、答案含义不清，或评分争议无法可靠消除 |

只有评分规则、目标能力和难度具有可比性时，才能陈述本轮表现改善。单次复测不能宣称“稳定掌握”，不能给出虚假的精确提升百分比。跨时间的同能力点复测及长期画像属于后续阶段；无效复测也不能算能力下降。

## 5. 移动端体验与数据边界

以 375–393 CSS px 为主要设计基准，核心流程单列、无横向滚动；每屏突出当前任务与主要操作。关键按钮尽量位于底部安全区域，兼顾刘海屏和虚拟键盘；触控目标建议至少 44×44 CSS px。

输入优先提供拍照，并支持相册、裁剪、旋转、放大和重拍。OCR 结果必须可修正；长篇材料支持多图上传及顺序确认。诊断先展示错误表现、原因和方法，细节分段展开；原题、学生答案和诊断结果易于对照。训练一次重点展示一道题，阅读材料与题目可快速定位；首版主观题以文字输入为主，手写图片作答作为后续增强。

训练中途退出应能恢复未完成内容。上传和 AI 处理要有明确状态；网络失败保留已输入内容并可重试，输入框聚焦后不遮挡题干与提交操作。上传图片须合理压缩、受控存储，避免错题及学生信息不必要的长期暴露。

最小学习记录包含 WrongQuestion、Diagnosis、Training、Retest 和 Evaluation，串联原图/确认文本、证据、训练目标、题目与版本、学生原始答案、评分点、提示使用、反馈和最终状态。图片、OCR 文本及学生答案的保留期限和删除方式须在上线前明确。

## 6. MVP 完成定义

以下条件必须同时满足，且在主流手机浏览器上完成端到端验收：

1. 从真实图片中识别并由用户确认一道人为选择的现代文阅读主观错题。
2. 根据题目和学生答案指出可追溯的具体错误；证据不足时追加验证或保留不确定性。
3. 输出正确思路和可在下一题使用的具体方法，并映射到一个训练目标。
4. 生成并完成两道目标一致、难度可比且内容不同的训练题，反馈按预设评分点给出。
5. 生成并完成一道无提示、无答案泄漏的独立复测题。
6. 根据预设评分规则给出三级掌握状态，完整保存并可查询本轮学习记录。
7. 摄像头拒权、上传/AI 失败、网络重试、中途退出与键盘遮挡场景均有可用恢复路径。
8. 图片与学生信息的存储、访问和删除边界经过确认与验证。

## 7. 开发前待确认的产品决策

这些事项不改变上述目标，但其取值会影响实现、测试和上线边界；在对应阶段开工前需形成明确规则。

| 决策 | 需要确定的内容 | 最迟关闭阶段 |
| --- | --- | --- |
| 输入准入 | 哪些字段必须由用户确认；多题/多图如何选择与排序；无学生答案的讲解路径 | 阶段 1 |
| AI 服务与质量门 | OCR、诊断、出题及评分的服务方案；失败重试、人工修正和不合格内容拦截 | 阶段 1–3 |
| 评分阈值 | 首版支持的阅读主观题子类、评分点模板、通过标准及有争议答案处理 | 阶段 3 |
| 会话与隐私 | 账号是否必需、跨设备是否支持、图片/文本保留期限、删除和访问权限 | 阶段 1 |
| 验收样本 | 真实错题样本、难度可比样本、错误归因分歧样本和移动端测试设备 | 阶段 0 |

待确认事项不得被实现中的默认值悄悄替代；可用受控样本验证后再作产品裁决。
