# 最小闭环模块开发原则

## 1. 核心原则

本项目采用“最小闭环模块 -> 阶段功能 -> 产品能力”的递进开发方式。

产品不是一次性完成的，而是通过一个个可独立运行、可独立验收、可互相协同的最小功能模块逐步生长出来。

本项目不是页面驱动型开发，而是能力驱动型开发。页面只是产品能力的承载方式，真正的开发目标是让系统逐步具备可运行、可验证、可复用的学习 Runtime 能力。

## 2. 递进关系

### 最小闭环模块

最小闭环模块是产品能力的最小组成单位。

每个模块必须具备：

- 明确输入
- 明确处理逻辑
- 明确输出结果
- 可独立运行
- 可独立验收
- 可被其他模块调用或协同
- 不依赖大范围重构才能生效

最小闭环模块不是代码文件，也不是页面组件，而是一个能够完成独立产品动作的运行单元。

### 阶段功能

若干个最小闭环模块组合后，形成一个阶段功能。

阶段功能不是页面集合，而是一个真实可运行的产品能力。

例如：

```text
题目输入模块
-> AI 诊断模块
-> 结构化结果展示模块
-> 诊断记录保存模块
-> 训练建议生成模块
```

这些模块组合后，形成“AI 诊断与训练建议闭环”。

### 产品能力

若干个阶段功能持续累积后，形成完整产品能力。

完整产品能力不是一次性设计完成，而是通过多个阶段逐步叠加形成。

例如：

```text
题目理解能力
-> 能力诊断能力
-> 训练建议能力
-> 能力证据能力
-> 学生画像能力
-> 复测验证能力
-> 长期成长追踪能力
```

这些能力持续组合，最终形成可长期运行的 AI 学习 Runtime。

## 3. Phase 开发规则

每个 Phase 只解决一个核心产品目标。

每个 Phase 建议拆分为 2 到 4 个小闭环，具体数量应根据阶段复杂度决定。

每个小闭环都必须能独立开发、独立运行、独立验收。

每个小闭环完成后，产品必须获得一个可感知、可保存或可复用的能力变化。

Phase 开发应遵循以下顺序：

```text
定义阶段目标
-> 拆分最小闭环
-> 明确输入输出
-> 建立调试样例
-> 实现运行模块
-> 输出结构化结果
-> 验收并沉淀为可复用能力
```

如果某个 Phase 无法拆出可验收的小闭环，说明该 Phase 目标仍然过大或不够清晰。

## 4. 禁止事项

开发过程中禁止以下行为：

- 只做页面展示，但没有真实数据流
- 只完成代码结构，但用户无法感知结果
- 一个小闭环混入多个阶段目标
- 为当前小闭环大范围重构无关模块
- 破坏上一阶段已经验收通过的功能
- 把 AI 单次问答包装成产品能力
- 在没有保存、复用、协同机制的情况下宣称闭环完成
- 在输入、处理、输出不清晰的情况下进入开发
- 在没有可验证样例的情况下宣称模块稳定

## 5. 验收标准

一个最小闭环模块完成时，必须满足：

1. 用户或系统有明确触发动作。
2. 系统有明确处理流程。
3. 页面或数据层有明确结果输出。
4. 结果可以保存、复用或驱动下一步动作。
5. 不破坏已有功能。
6. 可以被单独验证。

如果一个模块只能在人工解释后才算完成，说明它尚未形成产品能力。

如果一个模块只能展示结果，但不能被下一步模块消费，说明它尚未形成闭环。

## 6. 本项目的阶段能力方向

本项目后续能力按阶段逐步形成。

当前建议方向包括：

- 真实 AI 诊断能力
- 训练任务生成能力
- 复测验证能力
- 学生模型能力
- 长期成长追踪能力

这些阶段方向不是固定不变的排期，而是当前产品能力演进的建议路径。

每个阶段都必须围绕一个核心产品能力展开，不能偏离阶段目标。

当真实使用反馈表明阶段顺序需要调整时，应优先保持“最小闭环模块 -> 阶段功能 -> 产品能力”的开发原则，而不是机械执行原有阶段编号。

## 7. 与当前系统的关系

当前系统已经形成多个最小闭环模块：

```text
Question Metadata Generator
-> Metadata Validator
-> Diagnosis Agent
-> Training Agent
```

这些模块组合形成了第一条可运行的学习诊断链路：

```text
Question
-> Question Metadata
-> Validator
-> Diagnosis
-> Training
```

后续新增能力也应遵循同样原则。

例如，学生能力画像不应直接做成一个展示页，而应拆成：

```text
能力证据抽取
-> 能力状态更新
-> 弱点排序
-> 下一步建议
-> 画像展示
```

只有当数据能够被保存、复用并驱动下一步训练时，学生画像才算形成产品能力。

## 8. 开发结论

本项目不是页面驱动型开发，而是能力驱动型开发。

页面只是产品能力的承载方式。

真正的开发目标是让系统逐步具备：

- 输入能力
- 题目理解能力
- 诊断能力
- 记录能力
- 训练能力
- 复测能力
- 成长追踪能力

通过最小闭环模块持续积累，最终形成一个可长期运行的 AI 学习 Runtime。

本原则的目标不是增加开发复杂度，而是保证项目在长期演进中始终保持清晰、稳定、可验证、可扩展。
